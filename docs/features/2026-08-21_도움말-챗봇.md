# 도움말 — 사용 설명서 + 앱 사용법 챗봇

> 작성일 2026-08-21 · 분류: **기능 문서** (매매 판단과 무관한 조회 기능 — 도메인 아님)
> 코드: `features/help/appManual.ts`(설명서 본문), `features/help/helpChat.ts`(프롬프트·프록시), `features/help/ui/HelpChat.tsx`, `app/help.tsx`
> 진입: 홈 상단바 **말풍선**(검색 돋보기 옆)

## 1. 무엇
앱 사용법을 물어보면 답하는 챗봇. 기업 탭(AI 요약)과 **같은 프록시**를 쓰되, 재료가 뉴스가 아니라 **앱 설명서와 사용자의 현재 설정·상태**다.
답변 화면 외에 "설명서 전체 읽기"로 원문을 그대로 볼 수 있다 — AI가 실패해도 도움말은 산다.

## 2. 구조
```
APP_MANUAL (설명서 본문, 코드 상수)
  + describeUserSettings(AppSettings)   ← 지금 걸린 진입금액·수량·속도·순위 원천
  + describeRuntimeState(오토파일럿)     ← 돌고 있을 때만: 상태·리스트 수·보유 티커·사이클
  = systemInstruction
대화 히스토리(최근 8턴) = contents  →  /api/simple/gemini (스트리밍, 자유 텍스트)
```
- 프록시는 `contents`를 그대로 전달하므로 **멀티턴은 프록시 수정 없이** 된다.
- 기업 탭과 다른 점 둘: JSON 모드 안 씀(자유 텍스트), 히스토리 상한 있음(`HISTORY_MAX_TURNS`).
- 스트리밍은 기업 탭과 같은 방식(expo/fetch + `body.getReader()`), 조각마다 말풍선에 그린다.

## 3. 결정
- **설명서는 `docs/`가 아니라 코드에 둔다.** RN은 런타임에 `docs/*.md`를 못 읽고, `docs/`는 개발자용(도메인 규칙·ADR·분석 일지)이라 사용자 질문과 재료가 다르다. 사용자용 설명서의 정본은 `features/help/appManual.ts` 하나다.
- **바뀌는 숫자는 설명서에 쓰지 않는다.** 봉 주기·손절 %·추격 상한·기본 설정값은 전부 코드 상수(`TREND_BAR_MINUTES`·`TREND_CONFIG`·`TREND_ENTRY_CHASE_MAX_PCT`·`DEFAULT_APP_SETTINGS`·`MAX_GRIDS_LIMIT`·`RANKING_TOTAL_MAX`)에서 보간한다. 문서에 숫자를 굳히면 규칙이 바뀐 날 챗봇이 **확신에 차서 틀린 값**을 말한다 — 정적 문서보다 나쁘다.
- **설정 키 커버리지 테스트**(`appManual.test.ts`) — `USER_FACING_SETTING_KEYS ∪ HIDDEN_SETTING_KEYS = AppSettings`를 강제한다. 설정을 추가하면 둘 중 하나에 넣어야 하고, 사용자용이면 §7에 설명이 있어야 통과한다.
- **개인정보는 안 보낸다.** 프록시는 외부(Vercel)다 — 계좌번호·앱키·시크릿은 프롬프트에 넣지 않는다. 넣는 것은 설명서, 매매 파라미터, 오토파일럿 상태·보유 티커까지.
- **도움말이 매니저를 만들지 않는다.** `peekManagerBootstrap()`(신규)으로 **이미 돌고 있을 때만** 상태를 곁들인다. `useScalperManager`를 쓰면 도움말을 여는 것만으로 KIS 세션·WS가 생긴다.
- 답변 규칙: 설명서에 없으면 "확실하지 않아요", **종목 추천·주가 예측·매매 조언 금지**, "~해요"체. 상태 블록이 없으면 systemInstruction이 그 블록을 언급조차 하지 않는다(없는 자료를 가리키면 값을 지어낸다).

## 4. 아직 안 한 것
- 할당량·비용 모니터링(챗봇은 기업 탭보다 호출이 잦다). 문제가 보이면 턴 상한(8)부터 줄인다.
- 대화 저장 — 화면을 나가면 대화는 사라진다. 필요해지면 AsyncStorage에 종목 요약처럼 붙인다.
