## 원인 규명 — 토스 c-chart의 dt는 봉의 **끝** 시각이었다 (실측)

2026-08-26 07:43 KST(= 18:43 ET) 실호출:

- 진행 중 봉의 dt가 **"18:45"** — 지금(18:43)보다 미래. dt가 봉 시작이라면 불가능.
- min:5의 sessionType 실측: `main` 라벨 = **09:35~16:00**(= 실제 09:30~16:00), `pre` 04:05~09:30, `after` 16:05~20:00, `day`(주간거래) 20:05~04:00.

앱 전체는 dt를 봉 **시작**으로 해석하고 있었다. 그 결과:

1. **판정이 상시 한 봉(5분) 늦었다** ← 핵심. 진행 중 봉 컷오프(`키 ≥ 지금 봉 키`)가 "방금 닫힌 봉"(끝 라벨 = 지금 버킷)을 미완성으로 오인해 버렸다. 예: AMIX 진입 09:35:26 — 스캐너가 그 직전에 판정한 마지막 봉은 09:30~35 봉이 아니라 **09:25~30 봉**. 백테스트 가정(신호 봉 마감 → 다음 봉 시가 진입) 대비 실제는 신호 봉 마감 +5.5분 진입. 급등 5분봉에서 5분 늦은 진입은 꼭대기 매수와 같다 — "사자마자 −2~4% 찍고 그 뒤 급등"의 구조적 원인.
2. **점선(미확정) 봉이 2개 그려졌다** — 방금 닫힌 봉(끝 라벨 = 지금 버킷)까지 `inProgress` 판정. 사용자 관찰 그대로.
3. **세션 경계 오판** — 마지막 정규장 봉(15:55~16:00, 끝 라벨 16:00)을 애프터로 버리고(하루의 마지막 신호 기회 상실), 프리장 마지막 봉(09:25~30, 끝 라벨 09:30)을 정규장으로 오판(개장 +5초에 프리장 봉으로 매수 가능했던 상태).

추가 확인: 학습 파이프라인(financial-analyze `build-dataset.aggregateBars`)은 1분봉 **끝 라벨**을 그대로 버킷·세션 판정에 썼다(합성봉 session = 마지막 구성 분봉의 session 필드). 즉 정본 규약은 "끝 라벨 09:31~16:00 = main"이고, 앱의 `isMainSessionBar(시작+주기−1)`가 정본에서 4분 어긋나 있었다.

한계(정직하게): 학습 합성 5분봉은 끝 라벨 `floor(분/5)` 버킷이라 토스 네이티브 min:5와 **1분 위상차**가 있다(학습 봉 = 실제 :x9~:x4, 앱 봉 = :x0~:x5). 판정 주기가 같은 5분이라 수용하고, 위상까지 맞추려면 앱이 1분봉을 받아 자체 합성해야 한다(미룸).

## 바꾼 것

1. `lib/tossMinuteChart.ts` — `parseTossMinuteCandles`가 **minuteKey = dt의 epoch 분 − intervalMin**(봉 시작)으로 정규화. 차트·추세 시드·모델 조회 전 경로 적용. 컷오프가 이제 진행 중 봉만 빼고 방금 닫힌 봉은 살린다 → **판정 지연 −5분**.
2. `core/model/session.ts` — `isMainSessionBar` = etMinuteOfDay(**시작+주기**) ∈ [09:31, 16:00] (마지막 구성 1분봉의 끝 라벨 = 학습 필터 그대로). 15:55 봉 회복, 09:25 프리장 봉 차단.
3. 차트 점선 봉은 정확히 1개(진행 중 봉만)가 된다 — 별도 수정 없이 키 정규화의 결과.
4. 테스트: 토스 파서·컷오프 픽스처를 실측 규약(dt=끝)으로 재작성, 889건 통과.

## 안 바꾼 것과 이유

- **청산 규칙(고점 −5% / 하드 −2%)** — JEM −3.98%·AMIX −4.05%는 규칙 위반이 아니라 급락 중 시장가 추격의 슬리피지(−2% 선을 뚫는 갭). 지연 진입이 고쳐지면 "꼭대기 진입 → 즉시 손절" 빈도 자체가 줄어야 하므로, 청산은 고치지 않고 지연 수정 후 데이터로 재평가.
- **"팔고 나서 급등" 대응(재진입 등)** — 모델은 봉마다 다시 판정하므로 급등이 이어지면 다음 봉에서 재신호가 날 수 있는 구조가 이미 있다. 별도 재진입 규칙은 만들지 않는다.
