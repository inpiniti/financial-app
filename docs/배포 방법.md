# 배포 방법

이 앱을 배포하는 방법은 두 가지다. 평소에는 OTA만 쓰고, 네이티브 쪽이 바뀔 때만 재빌드한다.

## 1. OTA 업데이트 (`eas update`) — 평소에 쓰는 방법

이미 설치된 앱 안의 JS 번들만 원격으로 교체한다. 네이티브 코드는 그대로다. 앱을 껐다 켜면 최신 코드를 받는다.

```bash
npx eas-cli update --branch production --message "변경 내용 요약"
```

- 프로젝트 루트(`financial-app/`)에서 실행한다.
- `--message`는 EAS 대시보드에 남는 커밋 메시지 역할 — 무엇이 바뀌었는지 한 줄로 적는다.
- `@latest`를 붙이거나 `cd ... && npx eas-cli ...`처럼 다른 명령과 묶지 않는다. 배포 전에는 `npx tsc --noEmit`, `npm test`로 검증한 뒤 실행한다.

### 언제 이걸로 충분한가

화면·로직·훅 등 JS/TS 코드만 바뀐 경우. 이 프로젝트 대부분의 변경(오토파일럿 로직, 화면 UI, 설정값 등)이 여기 해당한다.

## 2. 네이티브 빌드 (`eas build`) — 앱 자체가 바뀔 때만

다음 중 하나라도 해당하면 OTA로는 반영되지 않고 새로 빌드해서 재설치해야 한다.

- 새 네이티브 모듈 추가(`npx expo install`로 새 패키지를 넣은 경우)
- `app.json`의 permissions·plugins 변경
- 앱 아이콘·스플래시 이미지 변경
- `expo-updates`의 runtime version 정책이 바뀌는 경우

### 개인 설치용 (Android)

`eas.json`의 `preview` 프로필이 `distribution: "internal"`로 이미 설정돼 있어 별도 설정 없이 바로 쓸 수 있다.

```bash
npx eas-cli build --platform android --profile preview
```

- 산출물은 스토어용 AAB가 아니라 폰에 바로 설치 가능한 **APK**다(`internal` distribution의 기본값).
- 첫 빌드 때 Android 서명 키(keystore)를 물어보면 **EAS가 자동 생성·관리**하도록 둔다 — 이후 빌드도 같은 키로 서명돼야 업데이트 설치가 이어진다.
- 클라우드 빌드라 보통 10~20분 걸린다.
- 빌드가 끝나면 터미널에 QR코드/다운로드 링크가 뜬다. 폰에서 QR을 찍거나 링크를 열어 APK를 받고, "출처를 알 수 없는 앱 설치 허용"을 한 번 켜면 홈 화면에 일반 앱처럼 설치된다.

### iOS 개인 설치용

Apple Developer Program 가입(연 $99)과 기기 UDID 등록이 필요하다. 필요해지면 별도로 정리한다.

### 스토어 정식 출시 (참고용, 미착수)

Google Play / App Store에 올려 일반 사용자가 받게 하려면 스토어 심사, 개인정보처리방침, 앱 아이콘·스크린샷 등 준비물이 많고 시간이 걸린다. 계좌 연동형 자동매매 앱은 스토어 정책상 심사 통과가 까다로울 수 있어, 이 프로젝트는 현재 개인 설치(OTA + 개인 빌드) 방식만 쓴다.

## 요약

| 상황 | 명령 |
|---|---|
| JS/화면/로직만 변경 | `npx eas-cli update --branch production --message "..."` |
| 네이티브 모듈·설정·아이콘 변경 (Android 개인 설치) | `npx eas-cli build --platform android --profile preview` |
