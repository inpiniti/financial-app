# 다중 그리드 — 변곡점 감시를 멈추지 않고 그리드를 여러 개 연다 (2026-08-05)

## 배경

기존 오토파일럿은 `AutoPilot.active`가 **단일 사이클**이었다. 한 종목에 진입하는 순간

- `reselect()`가 `state !== 'SCANNING'`이라 즉시 return → **변곡점 감시가 멈추고**
- `watchedTickers = [진입종목]`으로 접혀 다른 종목을 아예 보지 않았다.

즉 그리드는 항상 1개였다.

또 진입 수량이 **세션 금액**(마틴게일로 손실마다 2배가 되는 `session.amountUsd`) 기준이라,
그리드의 −w 물타기(수량 배증)와 겹쳐 노출이 두 겹으로 폭주했다.
(실제 사고: 진입금액 $2 설정 → 마틴 연패로 세션 금액 $32~64 → 그리드 물타기 2~3회 → 27주 × $4 ≈ $108)

## 결정

| # | 결정 | 이유 |
|---|---|---|
| D1 | `active: ActiveCycle \| null` → `actives: Map<ticker, ActiveCycle>` | 종목당 사이클 1벌. `buyingSince`·`abandonRequested`·`pendingSettle`을 전역에 두면 A의 미체결 시계가 B의 자동 포기를 오발동시킨다 |
| D2 | `reselect()`는 사이클 중에도 계속 돈다. 대신 `actives`·`pendingBuys` 티커를 **후보에서 제외** | "감시는 늘 새로 살 종목만 본다" — 사용자 요구 그대로 |
| D3 | 동시 그리드 상한 `maxConcurrentGrids`(기본 3, 최대 6) | WS 호가(R) 구독 예산과 현금 분할이 감당하는 선 |
| D4 | 슬롯 점유는 `pendingBuys` 등록(**동기**)으로 확정 | 프리플라이트가 async라, 그 창 안에 들어온 신호가 같은 슬롯을 중복 점유하면 상한을 넘겨 진입한다 |
| D5 | 진입금액 = **`config.startAmountUsd` 고정**. 세션 금액은 진입에 관여하지 않는다 | 세션과 그리드를 분리. 마틴 배증 × 그리드 배증 = 이중 폭주를 끊는다 |
| D6 | 설정 UI에서 마틴게일 토글·최대금액 제거 (`martingale:false`로 정규화 저장) | 다중 그리드에서는 "동시에 끝난 여러 사이클 중 어느 금액을 2배 할지"가 정의되지 않는다. 세션은 성과 집계 단위로만 남는다 |
| D7 | 그리드 물타기 예산 = `매수가능금액 ÷ maxConcurrentGrids` | 그리드 N개가 같은 현금을 각자 "전부 내 것"으로 보고 −w 매수를 걸면 전부 체결될 때 계좌가 즉시 잠긴다 |
| D8 | 현금 부족: **보유 그리드가 0개일 때만 PAUSED**, 있으면 신규 진입만 60초 쉰다 | PAUSED는 폴 타이머를 끈다 — 관리 중인 포지션이 있는데 들어가면 그리드가 방치된다 |
| D9 | FAULT는 **전역 유지**(한 종목이라도 주문 신뢰가 깨지면 전체 동결) | 부분 동결은 계좌 상태를 사람이 추론할 수 없게 만든다 |
| D10 | 보유 종목의 detector는 떼지 않는다(감시 목록에서만 뺀다) | 그리드 미사용 경로(`gridConfig` 미주입)에서 SELL 청산 신호가 거기서 온다 |
| D11 | `AutoPilot.gridConfig`를 필드로 빼고 `setGridConfig()`로 교체 가능하게. `managerProvider`가 단타 탭 포커스마다 최신 `appSettings`를 흘려 넣는다 | **사고 수정**: 매니저가 모듈 스코프 싱글턴이라 `buildManager()`가 앱 부팅에 한 번만 돌았다. 설정 탭에서 그리드 폭을 바꿔 저장해도 앱을 완전히 껐다 켜기 전에는 반영되지 않아 "항상 ±10%·배율 1"로 보였다. 이미 걸린 `Grid`는 생성자에서 폭을 캡처하므로 **다음에 새로 여는 그리드부터** 적용된다 |
| D12 | 그리드 폭 ≤ 50%, 매수 배율 ≤ 5로 저장 시 상한 검증 | 오타 하나(10 → 100)가 그대로 발주가에 들어가면 되돌릴 수 없다 |

## 전역 상태

`AutoPilotState`는 이제 **파생값**이다(우선순위 순):

```
IDLE(정지) > FAULT > PAUSED > ENTERING(하나라도 진입 중) > EXITING > HOLDING > SCANNING
```

⚠ 배지가 `HOLDING`이어도 **감시는 계속 돈다**. 배지는 요약일 뿐 감시 여부의 근거가 아니다.

## 남은 위험 (미해결)

- **Stop + 그리드 armed 동시 매도**: `stop()`이 `RunCycle.stop()`을 부르면 HOLDING 사이클이 청산 매도를
  낸다. 그런데 그리드의 +w 매도 지정가(같은 수량)도 계좌에 살아 있다. 둘 다 체결되면 초과 매도가 된다.
  그리드 도입(커밋 `0b74a7e`) 시점부터 있던 문제이고 이번 작업으로 바뀌지 않았다 —
  Stop 시 그리드 주문을 취소할지, 그리드에 청산을 맡길지 결정이 필요하다.
- **그리드 물타기 횟수 상한 없음**: `core/grid`는 −w 체결마다 수량을 배증하며, 브레이크는 가용현금뿐이다
  (D7로 1/N 분할은 했지만 상한은 아니다).
