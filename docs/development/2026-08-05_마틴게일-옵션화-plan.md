# 마틴게일 옵션화 — 켜면 시작/최대금액, 끄면 고정 금액 (2026-08-05)

## 배경

마틴게일(손실 2배·수익 절반)이 강제였다. 자동관리는 금액이, 수동 카드 오토런은 수량이 무조건 배증하고 상한이 없어, 연속 손실 구간에서 노출이 기하급수로 커지는데 끌 방법이 없었다.

**확정 사항**
1. 마틴 ON — 기존대로 시작금액·최대금액.
2. 마틴 OFF — 고정 금액 하나. 금액이 절대 안 변한다.
3. 마틴 OFF면 **세션 완주 판정을 하지 않는다**. 정지할 때까지 반복하고, 세션 손익·사이클 수·오늘 성과는 그대로 누적.
4. 자동관리(금액)와 수동 카드(수량) 둘 다 옵션화.

세션 완주 조건이 `수익 사이클 && 투입금액 ≥ 최대금액 && 세션성과 ≥ 0`이라 **마틴게일에 완전히 의존**했다. 금액이 고정이면 "최대금액 도달"이 상수가 되어 조건이 의미를 잃으므로 OFF에서는 판정 자체를 건너뛴다.

## 이번 작업의 핵심 함정 — `setConfig` 동기화

`setConfig`는 "진행 중 세션은 안 건드리고 다음 세션부터 적용"인데, **OFF에는 다음 세션이 없다**(세션 완주 판정을 안 하므로). 동기화하지 않으면 사용자가 금액을 바꿔도 영원히 예전 금액으로 진입한다.

→ `setConfig` 성공 직후, 새 설정이 OFF이고 세션이 있으면 `session.amountUsd`를 설정 금액으로 동기화한다. `setConfig`는 IDLE에서만 통과하므로 진행 중 사이클·미체결 주문과 충돌하지 않는다. ON→OFF 전환 시 불어나 있던 금액도 이때 내려온다. (OFF→ON은 동기화하지 않는다 — 마틴 진행 중 성과를 임의로 리셋하지 않기 위해.)

## 그 외 함정

- **`settle()`에서 OFF 검사가 `shouldEndSession`보다 먼저** 와야 한다. 뒤로 가면 `start=max` 설정에서 OFF 세션이 완주해버린다.
- 세션 손익·사이클 수와 일일 통계 누적은 분기 **바깥**이라 요구 3번이 자동 충족된다.
- `maybeAutoRerun`에서 **수량이 같아도 `setQty`를 호출**한다. `setQty`는 `RunCycle`을 재생성하는 부수효과가 있어, 스킵하면 ON/OFF의 객체 수명이 달라진다.
- `AmountSheet`에서 OFF→ON 토글 시 `max <= start`면 최대금액 칸을 비운다. 안 그러면 "첫 수익에 즉시 세션 완주"라는 의도치 않은 설정이 된다.
- `validateConfig`가 OFF에서 **더 관대**해진다(최대금액 검사 스킵) → `restore()`의 필터에서 설정이 소실될 위험이 오히려 줄어든다. `restore()` 본문은 무변경.

## 사문화되는 것들 — 전부 무해하게 남겼다

`AMOUNT_FLOOR_USD`(public API)·`shouldEndSession`·`nextAmountUsd`는 OFF에서 미사용이지만 제거·개명하지 않고 JSDoc만 갱신했다.

PAUSED의 `resume`/`resetSession`은 **중복이 아니다** — `resume`은 세션 손익·사이클 수를 유지하고 `resetSession`은 0으로 리셋하므로, 금액이 같아도 통계 관점에서 결과가 다르다. 둘 다 유지.
