  지금 동그라미+이니셜(TickerAvatar) 자리에 실제 로고를 표시한다.

## 1. 요구사항 (사용자 구술)

- **로고 관리 도메인**: 티커 → 로고 아이디 리스트를 관리한다 (예: `[["NVDA","nvidia"], …]`).
- **갱신**: 앱 시작 시 트레이딩뷰 스크리너 API(`scanner.tradingview.com/america/scan`)를 조회해 리스트 갱신.
  - 범위는 `[0, 9000]` (전체 약 8,000종목), 필요 없는 컬럼은 뺀다.
  - 응답 형태: `{ data: [{ s: "NASDAQ:NVDA", d: [ { name, logo: { logoid } }, … ] }], totalCount }`.
- **로고 URL**: `https://s3-symbol-logo.tradingview.com/{logoid}.svg`.
- **표시**: 리스트/카드의 이니셜 아바타 대신 로고. (로고가 없으면 기존 이니셜 유지 — §4-3)

## 2. 설계

### 2-1. 모듈 배치 — 로고는 KIS와 무관한 앱 공용 도메인이므로 `lib/`에 둔다
```
lib/tradingviewLogos.ts   # 스크리너 1콜 → [ticker, logoid][] 파싱 (순수 fetch 로직)
lib/logoStore.ts          # AsyncStorage 영속 + 인메모리 Map + 신선도 갱신 + logoUriFor(ticker)
components/TickerAvatar.tsx  # (개편) 로고 있으면 SVG, 없거나 로드 실패면 기존 이니셜 폴백
```

### 2-2. 조회 요청 — 사용자 예시를 **최소화**해서 쓴다
- **쿠키·sec-ch-ua 등 브라우저 지문 헤더는 전부 뺀다.** 특히 예시의 `cookie`에는 트레이딩뷰
  **로그인 세션ID가 들어 있다 — 코드에 절대 넣지 않는다**(§4-1). 스크리너는 공개 API라 쿠키 없이 동작한다.
- 헤더는 `accept: application/json`, `content-type: text/plain;charset=UTF-8` 정도만.
- 컬럼 최소화: 티커는 `s`("NASDAQ:NVDA")에서, 로고는 첫 컬럼 `ticker-view`의 `logo.logoid`에서 얻는다.
  (구현 스모크에서 `logoid` 단일 컬럼이 동작하면 그걸로 더 줄인다 — 응답이 수백 KB → 수십 KB로.)
- `range: [0, 9000]` 1콜(사용자 확정). 필터는 예시의 primary·주식/DR/펀드 조건 유지.
- 파싱: `data[].s`의 콜론 뒤 = 티커(대문자 그대로 — BRK.A 같은 특수 표기도 그대로 저장),
  `logo.logoid` 없으면 그 종목은 건너뛴다(로고 없는 종목).

### 2-3. 저장·갱신(logoStore)
```
storage key 'logos:v1' → { fetchedAt: epochMs, pairs: [ticker, logoid][] }
```
- 앱 시작(부트스트랩): ① 저장값을 즉시 메모리에 로드(오프라인에서도 마지막 로고 사용) →
  ② `fetchedAt`이 **24시간**보다 오래됐으면 백그라운드로 재조회·저장(§4-2 — 콜드 스타트마다 8천 행을
  다시 받지 않게 스로틀). 조회 실패는 조용히 무시(기존 캐시 유지).
- 조회 API: `logoUriFor(ticker): string | null` — 동기(인메모리 Map). null이면 폴백.

### 2-4. 표시(TickerAvatar 개편) — 호출부 무수정
- `TickerAvatar`가 내부에서 `logoUriFor(ticker)`를 조회:
  - 로고 있음 → 원형 클리핑된 SVG 렌더 (`react-native-svg`의 `SvgUri` — §4-4).
  - 로고 없음 / 로드 실패(onError) → **기존 이니셜 원형 그대로 폴백**.
- 사용처(순위·보유·오늘거래·단타 카드·자동 단타 리스트)는 전부 `TickerAvatar` 경유라 화면 수정 없음.

## 4. 구술에서 빠져 있던 부분 (제안 — 확인 요망)

| # | 이슈 | 제안 |
|---|---|---|
| 1 | **예시 요청의 쿠키에 트레이딩뷰 세션ID가 들어 있음** | 코드에 넣지 않는다(공개 API라 불필요). 이미 대화에 노출된 세션이니 걱정되면 트레이딩뷰에서 로그아웃/재로그인으로 무효화 권장 |
| 2 | "앱 시작 시 갱신"의 빈도 — 콜드 스타트마다 8천 행 조회는 낭비 | 캐시 즉시 사용 + **24시간 지났을 때만** 백그라운드 재조회. 실패 시 기존 캐시 유지 |
| 3 | 로고 없는 종목·신규 티커 | 기존 이니셜 아바타로 폴백(빈 원 없음) |
| 4 | **SVG 렌더 의존성** — RN 기본 Image는 SVG를 못 그림 | `react-native-svg`(Expo Go 내장 — 새 네이티브 빌드 불필요, OTA 호환) `SvgUri` 사용 |

| 6 | 응답 크기 — 예시 컬럼 23개 × 9000행 | 컬럼 최소화(§2-2)로 축소. `[ticker,logoid][]` 압축 형태로 저장(사용자 제안 채택) |
| 7 | 비상장/이전 티커가 캐시에 남는 문제 | 갱신 시 통째로 교체(머지 아님) — 24h 내 자연 정리 |
