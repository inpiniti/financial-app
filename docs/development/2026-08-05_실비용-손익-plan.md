# 실비용 반영 손익 — 발주가 기준 체결가 + 수수료 차감 (2026-08-05)

## 배경

앱이 보여주는 손익이 실제보다 낙관적이라, 파라미터를 바꿔도 개선인지 판단할 수 없었다.

`pnl = (exitPrice − entryPrice) × qty` 인데 `entryPrice/exitPrice`가 `fill.price ?? 신호 시점 틱 가격`이었다. 그런데 `createKisBroker.fetchFills`는 **전량 체결 시 `filledPrice`를 항상 null**로 준다 — 미체결 목록에서 사라진 걸로 체결을 추론하므로 가격을 모른다. 부분체결로 목록에 남아 있을 때만 `ft_ccld_unpr3`를 준다.

결과적으로 대부분의 거래가 신호 시점 틱 가격으로 계산됐다. 매수는 매도1호가, 매도는 매수1호가 지정가로 내므로 **왕복 스프레드가 손익에서 통째로 빠졌다.** 수수료는 코드 어디에도 없었다.

### 함께 고친 버그 2개

1. **STOP 청산 손익이 0으로 기록됐다.** `stop()`이 `placeSell(null, 'STOP')`이라 `pendingSnapshot`이 null이고, 체결가도 없으면 3단 폴백이 `?? pos.entryPrice`까지 내려가 `exitPrice = entryPrice` → pnl 정확히 0. 수동 정지 청산의 손익이 통째로 누락돼 왔다.
2. **정정 후 옛 체결가가 새 주문 체결가로 둔갑했다.** `fireAmend`가 `filledBase`는 갱신하면서 `lastFillPrice`는 리셋하지 않았다(2026-08-04 매도 실행기 작업에서 유입).

## 설계

**발주가를 체결가 폴백으로 쓴다.** 매수는 ask1 `ceil`, 매도는 bid1 `floor` 지정가라 실체결이 발주가보다 유리하거나 같다 → **오차가 항상 보수적**이고 스프레드가 손익에 들어온다. `PendingOrder.orderPrice`가 이미 있어 새 의존성이 필요 없다.

실시간체결통보(H0GSCNI0)는 채택하지 않았다 — **암호화 스펙이 문서에 없고**(응답 Header 절이 원문에서 비어 있음) HTSID 저장소도 없어 리스크가 크다. 별도 작업으로 남긴다.

| 항목 | 결정 |
|---|---|
| 폴백 위치 | 어댑터 `settlePrice()`. core 무수정 |
| STOP 버그 | 위 변경으로 자동 해소(fill.price가 항상 존재). core의 `?? pos.entryPrice`는 `FillResult.price`가 계약상 optional이라 남기고 회귀 테스트로 고정 |
| 부분체결 | `filledValueBase`(누적 체결대금) 1개로 수량 가중평균. 정정이 없으면 단순 폴백과 결과가 완전히 동일 |
| 수수료 | core `emitTrade`에서 차감 — pnl 산출이 한 줄뿐인 단일 병목. `pnl`이 순손익이 되어 마틴게일·세션이 자동으로 순손익 기준 |
| 수수료 식 | `fees = feeRate × (entryPrice×qty + exitPrice×qty)` — 편도 요율을 매수·매도 대금 각각에 |
| 기본값 | `commissionRatePct = 0`(끔) — 기존 테스트가 하나도 안 깨진다 |

## `place()` 예외 가드가 필요했던 이유

`roundOverseasOrderPrice`는 가격 0 이하면 throw하는데 `place()`는 core의 **동기** OrderPort 계약이다. 여기서 예외가 새면 `stop()` → `placeSell` 경로에서 **사용자 Stop이 통째로 실패하고 포지션이 HOLDING으로 남는다**(정지했다고 믿는데 안 됨). 이제 삼켜서 FAULT 채널로 넘기고, 발주는 하지 않는다. 이 유령 주문은 `odno: null`이라 `needsPoll`·`findRepriceablSell`에서 자동 제외된다.

## ⚠ 수수료를 켤 때의 행동 변화

마틴게일은 `pnl > 0`이 아니면 금액·수량을 **2배**로 올린다. 수수료를 켜면 "본전(pnl = 0)" 케이스가 사실상 사라져 **훨씬 자주 2배가 된다 = 실질 리스크 증가.** 세션 완주(`shouldEndSession`)도 어려워지는데 이건 의도한 방향이다. 테스트로 이 동작을 명시 고정했다.

그래서 수수료 기본값을 0으로 두고 사용자가 관찰 후 켜도록 했다.
