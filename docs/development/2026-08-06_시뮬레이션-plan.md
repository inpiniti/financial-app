# 시뮬레이션 모드 + 가상 전략 매트릭스 plan (2026-08-06)

> 상태: **구현 완료** (tsc + vitest 458개 통과). 사용 전 사전 준비는 §7.

## 1. 배경 / 목적

실거래 중인 오토파일럿(변곡점 진입 + ±폭 OCO 그리드)을 **실제 들어오는 시세 그대로, 주문만 가상**으로
하루 이상 돌려본다. 동시에 **폭×배율 ~20조합의 가상 전략**이 같은 진입을 각자 관리하며 결과를 Supabase에
쌓는다 — 어떤 설정이 몇 분 만에, 몇 번의 물타기로, 얼마까지 물렸다가 탈출했는가. 단순 모의투자가 아니라
**전략 연구 데이터 수집 도구**다.

가상 전략 매트릭스(SimLab)는 시뮬 모드뿐 아니라 **실거래 중에도** 돈다(mode='live'로 구분 기록) —
실제 주문은 하나만 나가고 뒤에서 20개 전략이 같은 시세를 평가하는 구조(사용자 원안).

### 2-1. 체결 판정 (확정 — 원 메시지의 매수/매도 방향은 착각이었음을 사용자 확인)

**전 주문 단일 규칙, 즉시 체결 특례 없음. 진입도 동일하다.**

- **매수 지정가 P**: 현재가가 **P보다 낮은** 틱이 찍혀야 체결. 매수 10 → 9.9999 틱 관찰 시 체결, 체결가 = 10.
- **매도 지정가 P**: 현재가가 **P보다 높은** 틱이 찍혀야 체결. 매도 10 → 10.01 틱 관찰 시 체결, 체결가 = 10.
- 지정가에 정확히 닿기만 한 틱(= P)은 미체결 — "한 틱 뚫어야 인정".
- 체결가는 항상 지정가(더 유리한 체결을 가정하지 않음) → 시뮬은 실전 대비 **보수적**.
- 부분체결은 시뮬하지 않음(전량만) — 실물 브로커도 "미체결 목록 부재→전량" 추론이 주 경로라 정합.

## 3. 구현 결과

### Phase A — 시뮬레이션 모드

| 파일 | 내용 |
|---|---|
| `lib/appSettings.ts` | `simulationMode: boolean` (기본 false) |
| `features/scalper/simBroker.ts` | `SimExchange` — 티커별 가상 브로커(ScalperBroker 구현). §2-1 체결 규칙, 기체결 취소는 throw(KIS 거절 재현 — OCO/FAULT 경로가 시뮬에서도 정직), 정정은 새 odno, 가상 포지션(가중평균) 유지 |
| `features/scalper/ui/managerProvider.tsx` | `simMode`(mutable ref) — makeBroker가 매 진입마다 읽어 KIS/SimExchange 선택. 시뮬이면 fetchBuyableUsd→null(무한), fetchHoldings→가상 잔고. WS 틱 탭: SimExchange·SimLab이 오토파일럿보다 먼저 같은 틱을 받는다 |
| 기록 분리 | 시뮬 거래는 `trades.*`(실거래 손익 화면)에 쓰지 않는다 — `AutoPilotManagerDeps.isSimulation` |
| UI | 설정 탭 "시뮬레이션" 패널(ToggleRow) + AutoPilotScreen 주황 "시뮬레이션" 배지(실제 적용 모드를 읽음) + 이벤트 `[시뮬]` 접두 |

**모드 전환 안전장치**: 브로커를 재빌드 없이 갈아끼우기 위해 mutable ref를 쓰되, 전환은
`refreshLiveSettings`가 **오토파일럿 IDLE일 때만** 수행(단타 탭 재진입 시). 실행 중이면 타임라인에 안내만.
전환 시 SimExchange.reset() + 열린 에피소드 stopped 마감. 실거래/가상 브로커가 한 세션에 섞이는 일은 불가.

### Phase B — 가상 전략 매트릭스 + Supabase

| 파일 | 내용 |
|---|---|
| `features/scalper/simLab.ts` | `buildSimMatrix`(폭 [2,3,5,7,10]% × 배율 [0.5,1,2,3] = 20조합, 사용자 설정 조합 `is_primary` — 축 밖이면 21번째 추가) + `SimLab`(에피소드 관리). 다리 가격은 core/grid의 `roundGridPrice` 재사용(KIS 자릿수·부동소수 잔재 제거) |
| `features/scalper/autopilot.ts` | `onEntryFilled` 훅 — HOLDING 첫 확정 시 1회(입양 제외). 도메인에 시뮬 로직 미침투 |
| `lib/simEpisodeStore.ts` | Supabase insert + 실패 시 AsyncStorage 큐(상한 500) + 앱 시작 시 flush — 네트워크가 시뮬을 막지 않는다 |
| `supabase/migrations/0002_sim_episodes.sql` | 스키마 + anon insert-only RLS + 분석 인덱스 |

**에피소드 종료 4경로**: ① 매도 다리 체결(`escaped`) ② 틱 공백 마감(`data_lost`) ③ Stop·모드 전환(`stopped`)
④ 동시 에피소드 상한(8개, 종목 기준) 초과 축출(`evicted`). ②~④도 그 시점 상태(MAE·최대투입·수량)로 기록 —
**미탈출 데이터가 더 귀중하다**.

**재진입 규칙 (2026-08-06 개정, 사용자 확정)**: 전략은 각자 **독립된 가상 계좌**다. 같은 종목에
재진입이 와도 보유 중인 전략은 자기 에피소드를 그대로 이어가고, **놀고 있는(이미 탈출한) 전략만**
새 진입가로 새 에피소드를 시작한다. 초기 구현은 재진입이 이전 에피소드를 통째로 `stopped` 마감했는데,
활발한 종목일수록 넓은 폭(7~10%) 전략의 측정이 계속 잘려 탈출률 통계가 조직적으로 불리해졌다
(첫날 ONFO 데이터에서 10% 폭 0/8 전부가 이 아티팩트였음). 그래서 행 수는 "진입당 20행"이 아니라
**전략이 각자 끝나는 시점에 1행씩** 쌓인다 — 어느 시점에 세어도 20의 배수가 아닐 수 있는 게 정상.

### §5-4 실전 수정 — 트레이딩 종목의 WS 구독 유지 (사용자 지시: 필수)

`AutoPilotManager`에 **체결가(D) 구독 홀드**(티커별 참조 카운트)를 추가했다:
- 보유·진입 중 사이클 전 종목 + SimLab 에피소드 종목은 **단타 리스트에서 탈락해도 슬롯·WS 구독 유지**
- 홀드가 있는 동안 `dropSlot`을 건너뛰고, 마지막 해제 때 리스트에 없으면 그때 정리
- 부수 효과: 리스트 밖 종목을 입양(adopt)해도 이제 구독이 붙는다

참고: 실거래의 그리드 **체결 감지**는 원래 KIS REST 폴링(fetchFills)이라 WS와 무관하게 안전했다.
이 수정으로 좋아지는 것: 게이지 현재가 표시 연속성 + **시뮬 체결 판정**(WS 틱 의존)의 공백 제거.

### sim_episodes 스키마

| 컬럼 | 내용 |
|---|---|
| mode | 'sim'(주문 가상) / 'live'(실거래 병행 관찰) |
| ticker, trade_date | 종목 · 진입일(KST) |
| entered_at, exited_at, duration_s | KST 'YYYY-MM-DD HH:mm:ss' · 소요 초 |
| entry_price, exit_price, min_price, mae_pct | 진입가·종료가·최저가·최대역행률(양수 %) |
| max_qty, max_invested_usd | 최고 보유수량 · 최대 투입금액(무한 기준 = 최소 필요 자금) |
| rebuy_count | 물타기 횟수 |
| width_pct, buy_multiplier, is_primary | 전략 설정 (primary = 사용자 실제 설정) |
| escaped, exit_reason | 탈출 여부 · escaped/data_lost/stopped/evicted |
| tick_rate_at_entry, entry_session | 진입 당시 틱/초 · 세션(pre/regular/after/off — 판정은 미국장 기준, 시각 기록은 KST) |

## 4. 분석 쿼리 예시 (Supabase SQL Editor)

```sql
-- 전략별 성적표: 탈출률·평균 소요·최대 필요 자금
select width_pct, buy_multiplier,
       count(*) as episodes,
       round(avg(case when escaped then 1.0 else 0 end) * 100, 1) as escape_rate_pct,
       round(avg(duration_s) filter (where escaped) / 60.0, 1) as avg_escape_min,
       max(max_invested_usd) as worst_capital_usd
from sim_episodes
group by 1, 2 order by escape_rate_pct desc;

-- 세션(시간대)별 평균 탈출 시간
select entry_session, round(avg(duration_s) filter (where escaped) / 60.0, 1) as avg_min
from sim_episodes group by 1;
```

## 5. 한계 / 다음 단계 후보

1. **영속화 없음** — 앱 재시작 시 가상 포지션·진행 중 에피소드 소실(기록도 안 남음). 하루 실험 전제.
   밤새 돌리려면 SimExchange/SimLab 상태 영속화 필요. → 보완 후보
2. **포그라운드 필수** — 앱을 백그라운드로 보내면 Expo JS·WS가 멈춰 시뮬도 멈춘다. 전용 기기에 화면
   켠 채(keep-awake가 실행 중 유지) 운용 권장.
3. **진입 전략은 비교하지 않는다** — 20전략 모두 오토파일럿의 진입(사용자 감시·게이트 설정)에 종속.
   이 실험은 **청산(그리드) 전략만** 비교한다(사용자 확인).
4. **동시 에피소드 상한 8개** — WS 구독 예산 보호. 초과 시 가장 오래된 에피소드를 evicted로 마감.
5. **anon insert-only의 보안 한계** — anon 키가 앱에 있으므로 이론상 제3자 insert 가능(select는 차단).
   개인 앱이라 수용.
6. **수동 카드 상호 배타 유지** — 수동 카드 실행 중엔 시뮬 오토파일럿도 시작 불가(기존 `isManualBusy`
   가드 그대로). 시뮬/실거래 모드가 갈려도 규칙이 하나라 혼동 사고 여지가 없다.
7. 데이터가 충분히 쌓이면(수백 건~) 전략 자동 추천은 별도 프로젝트로 — 이번 스키마가 그 학습 데이터
   포맷을 겸한다(진입 컨텍스트 컬럼 포함).
