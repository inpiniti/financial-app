## 1. 요구사항 (사용자 확정)

### A. 금액 설정: 투입금액 1개 → 시작금액·최대금액
- 기존 `baseAmountUsd` 단일 값 → **`startAmountUsd`(시작금액) / `maxAmountUsd`(최대금액)** 두 값으로 대체.
  ("최소금액"이라는 이름은 오해 소지가 있어 **시작금액**으로 확정 — 반감 하한과는 무관하다.)

### B. 최소 속도(minTickRate, 틱/초)
- 감시 대상 = **"최소 속도 이상인 것 중 틱/초 상위 최대 3개"**. 1개면 1개만, **0개면 감시하지 않는다**(진입 없음).
- **0으로 설정 불가**(> 0 강제), **기본값 1틱/초**.
- 매수까지 진행된 사이클은 이후 유동성이 죽어도 **반드시 매도까지 완료**한다(중도 포기 없음 — 사용자 확정).

### C. 세션(Session)
- 세션은 **투입금액**과 **성과(세션 누적 손익)**를 가진다. 새 세션은 **시작금액**·성과 0으로 개시.
- **종료 조건 — 셋 다 만족(AND)**, 판정은 **금액 조정 전**(사용자 확정):
  1. 마지막 사이클이 수익(pnl > 0)
  2. 세션 투입금액이 최대금액에 도달/초과(≥ max)
  3. 세션 성과가 음수가 아니다(**0 포함**, ≥ 0)
- 달성 → 현 세션 종료, 새 세션 자동 개시(시작금액·성과 0).

### D. 현금 부족 → 일시정지(PAUSED) — 사용자 확정(§4-3)
- 배증에 상한은 없다. 단, **매수에 필요한 현금이 부족하면 자동매매를 일시정지**한다.
- 일시정지 중엔 새 세션을 자동으로 열지 않는다. **사람이 선택**한다:
  - **이어서 재개** — 입금 후 같은 세션·같은 금액으로 계속.
  - **세션 초기화** — 현 세션을 버리고 시작금액으로 새 세션.

### E. 표시
- "오늘 성과"는 **오늘 전체 누적**(세션과 무관) + **오늘 세션 수**.
- "오늘"의 기준일은 **미국 장 기준**(America/New_York 날짜 — 사용자 확정, 한국시간 아님).

## 2. 설계

### 2-1. 설정·상태 모델 (영속 v2)
```
AUTOPILOT_STORAGE_KEY = 'scalper:autopilot'
{
  version: 2,
  startAmountUsd: number,    // 세션 시작 금액
  maxAmountUsd: number,      // 세션 종료 조건 2의 기준
  minTickRate: number,       // 틱/초, > 0 강제, 기본 1
  session: { amountUsd, pnl, cycles, paused: boolean },  // 진행 중 세션(재시작 복원)
  daily: { date: 'YYYY-MM-DD'(ET), sessionCount: number },
}
```
- 검증: `0 < start ≤ max`, `minTickRate > 0`. AmountSheet → 3필드(시작·최대·최소속도) 시트로 개편.
- **마이그레이션(v1→v2)**: `{baseAmountUsd}` 존재 시 `start = base`, `max = base × 4`, `minTickRate = 1`.
- 기준일 유틸: `etDateOf(epochMs)` — America/New_York 날짜 문자열(Intl 사용, DST 자동).

### 2-2. 감시 선정(reselect) 확장
- 후보 = `tickRate ≥ minTickRate`인 슬롯만. 그중 상위 최대 3. 자격 미달 빈 자리는 비워 둔다.
- 히스테리시스(1.2배)는 자격자끼리의 교체에만 적용. 감시 중 종목이 기준 미달이 되면 **즉시 해제**.
- **진입 직전 재검사**: commitBuy 확정 직전 해당 종목 틱/초가 기준 미달이면 진입 포기(이벤트 기록).
- 보유 중 포지션은 속도와 무관하게 매도 변곡점 감시를 계속한다(사이클은 반드시 완주).

### 2-3. 세션 수명주기 (정산 훅)
```
정산(자연 완료 SELL_SIGNAL만):
  session.pnl += record.pnl; session.cycles += 1
  if (record.pnl > 0 && 이번 사이클 투입금액 >= maxAmountUsd && session.pnl >= 0):
      세션 종료 → 새 세션 { amountUsd: startAmountUsd, pnl: 0 }, daily.sessionCount += 1
  else:
      수익 → amountUsd = max(amountUsd / 2, 1)   # 하한 $1 — 시작금액 아님(사용자 확정 §4-1)
      손실 → amountUsd = amountUsd × 2           # 상한 없음
      본전 → 유지
  persist
```
- 수동 Stop 청산(STOP)은 금액 조정·세션 종료 판정 없음(성과에는 pnl 반영). Stop·FAULT·재시작에도 세션 유지.
- 최초 start: session 없으면 시작금액으로 개시 + sessionCount=1. ET 날짜가 바뀌었으면 sessionCount 리셋.

### 2-4. 현금 부족 일시정지(PAUSED)
- **감지**: commitBuy에서 주문 확정 직전 **해외 매수가능금액 조회**(`docs/koreainvestment/매수가능금액조회.txt` TR)로
  `필요금액(qty × price) > 주문가능금액`이면 발주하지 않고 PAUSED 진입.
  (사전 조회가 실패하면 조회 없이 진행 — 주문 거절 시엔 기존 FAULT 인터록이 받는다.)
- **PAUSED 상태**: 감시 전부 해제·신규 진입 없음·리스트 폴링은 유지(재개 대비). keep-awake 해제.
- **해제(사람 판단)**: UI 두 버튼 —
  - "이어서 재개": 같은 세션·같은 금액으로 SCANNING 복귀.
  - "세션 초기화하고 재개": 새 세션(시작금액·성과 0, sessionCount+1) 후 SCANNING.
- Stop은 언제나 가능(PAUSED → IDLE, 세션은 유지).

### 2-5. UI
- 상태 패널: "투입 금액" 행 → `시작 $A ~ 최대 $B · 최소 {r}틱/초` 표시, 탭 → 3필드 시트(IDLE에서만).
- **세션 행** 추가: `세션 #N · 투입 {session.amountUsd} · 세션 성과 {session.pnl}`.
- "오늘 성과" = 전체 누적 + `사이클 n회 · 세션 m개`(ET 기준일).
- PAUSED 배지(주황) + 안내 문구("현금이 부족해서 쉬고 있어요…") + 재개/초기화 버튼 2개.
- 감시 0개(자격 미달) 상태: "모든 종목이 {r}틱/초 미만이라 기다리고 있어요" 안내.
- 기록 이벤트: 세션 종료/개시, 속도 미달 진입 포기, 현금 부족 일시정지.
