# 주간거래 Plan

> 상태: **설계 확정, 착수 가능** — 코드 미착수. v1(2026-08-06 초저녁)에서 §6 결정 사항 다수를 "미확인"으로
> 잘못 표기했던 것을 사용자 피드백 + `docs/koreainvestment/*` 원문 재확인 + KIS 공식 GitHub
> (`koreainvestment/open-trading-api`) example 대조로 정정(v2, 2026-08-06). 실측이 필요한 항목은 §6에 남은
> 2개뿐이고 나머지는 문서·공식 예제로 이미 확정됐다.

## 1. 배경 / 무엇을 여는가

"주간거래"는 미국 정규장(한국시간 22:30~05:00, `entry_session`의 pre/regular/after/off)과는
**완전히 별개의 체결 경로**다. 뉴스 확인 결과 KIS는 **Blue Ocean·Bruce·Moon 3개 대체거래소(ATS)**로
주문을 분산 체결하며(v1에서 "Blue Ocean ATS로 추정"이라 썼던 건 부정확 — 단일 거래소가 아니다),
평일 한국시간 **10:00~18:00**에 미국주식·ETF 매매를 지원한다. 프리마켓(18:00~23:30)·정규장(23:30~06:00)·
애프터마켓(06:00~09:00)까지 합치면 하루 최대 23시간 논스톱 거래가 된다는 것이 KIS의 공식 포지셔닝이다.

- 이미 존재하는 것: `kis/priceDetail.ts`의 `PriceDetailExchangeCode`에 `BAY/BAQ/BAA` 정의됨(현재가상세 조회만).
  `kis/realtimePrice.ts`의 `looksLikeRsym` 정규식도 `BAQ|BAY|BAA`를 이미 인식(그러나 `RealtimeMarketCode`
  타입에는 아직 없어 `buildFreeQuoteTrKey`로 구독 키를 못 만든다 — 구멍).
- 아직 없는 것: 주문(`kis/order.ts`) · 정정취소(`kis/orderCancel.ts`) · TR ID 표(`kis/trId.ts`) 전부
  정규장 전용이라 주간거래 주문은 아예 못 나간다. `features/scalper/*`(오토파일럿·그리드·시뮬)는
  session 개념이 없다 — `sessionOf()`(simLab.ts)도 정규장 ET 시계열만 판정한다.

목표: 기존 변곡점 감지(`core/detector`) + 그리드(`core/grid`) + 오토파일럿 상태기계를 **그대로 재사용**하면서,
10:00~18:00 KST 창에서 (a) 실거래 또는 (b) 실비용 없는 시뮬레이션으로 굴릴 수 있게 만든다.

## 2. 문서 재확인 결과 (v1의 "미확인" 정정)

v1 작성 시 반입된 두 파일(`주간주문.txt`, `주간정정취소.txt`)은 실제로 정독했고, 그 안에
`OVRS_EXCG_CD` 스펙("NASD:나스닥 / NYSE:뉴욕 / AMEX:아멕스")이 명시돼 있었는데도 §6-1에서 "미확인"으로
잘못 적었다 — 읽은 내용을 반영하지 못한 실수. 이번에 `docs/koreainvestment/` 전체를 grep하고
KIS 공식 GitHub(`koreainvestment/open-trading-api`)의 `examples_llm/overseas_stock/daytime_order`,
`daytime_order_rvsecncl` 예제 코드까지 대조해 아래처럼 정정한다.

| API | Method/URL | TR ID(실전) | 비고 |
|---|---|---|---|
| 주간주문 | POST `/uapi/overseas-stock/v1/trading/daytime-order` | 매수 `TTTS6036U` / 매도 `TTTS6037U` | **모의투자 미지원**(TrPair 불가 — live 전용). `ORD_DVSN`은 지정가("00") 고정. Body에 `SLL_TYPE` 필드 자체가 없음(정규장 매도 전용 필드와 다름). |
| 주간정정취소 | POST `/uapi/overseas-stock/v1/trading/daytime-order-rvsecncl` | `TTTS6038U`(정정·취소 공통 1개) | 정규장은 국가별 TR이 갈리지만 주간은 미국 전용 단일 TR. `CTAC_TLNO`·`MGCO_APTM_ODNO`가 Required(Y) — 정규장 취소 경로는 옵셔널 처리했던 필드라 주간은 빈 문자열이라도 반드시 채워야 한다. |

**OVRS_EXCG_CD = `NASD`/`NYSE`/`AMEX` — 확정.** 두 문서 원문에 명시돼 있고, KIS 공식 GitHub의
`daytime_order.py`/`daytime_order_rvsecncl.py` docstring도 동일하게 세 코드만 나열한다.
`BAY`/`BAQ`/`BAA`는 **시세 조회 전용**(현재가상세 EXCD, 실시간 WS tr_key) 코드이고 주문 Body에는 쓰지 않는다.

공통 주의사항(두 문서 동일): "미국주간거래의 경우, 모든 미국 종목 매매가 지원되지 않습니다 — 일부 종목만 매매
가능", "미국주간거래시간 외 API 호출 시 에러 발생". 즉 **화이트리스트가 없다** — 거부는 주문 시점에 KIS가
판단하므로, 우리 쪽은 "거부되면 그 종목만 감시 해제"로 대응해야 한다(사전 검증 API 없음).

### 2-1. 운영시간 표기 불일치 — 두 갈래 문서가 다른 숫자를 준다

- `주간주문.txt`/`주간정정취소.txt`(주문 계열): "주간거래(장전거래) : **10:00 ~ 18:00**"
- `실시간지연체결가.txt`/`실시간호가.txt`(시세 계열): "미국주간거래(**10:00~16:00**) 시세 조회도 가능"
- 뉴스(2025-11-04, 재개 시점 보도)도 "오전 10시~오후 6시"로 **10:00~18:00**을 확인해준다.

**판단**: 주문 가능 창은 **10:00~18:00**을 정본으로 삼는다(주문 문서 + 뉴스 일치, 시세 문서 쪽 16:00은
과거 버전 잔존으로 추정). 다만 시세(WS) 수신이 16:00 이후에도 끊기지 않는지는 실측 확인 대상으로 남긴다(§6-1).

## 3. 설계

### 3-1. 세션 판정 유틸 — `core/session`(신설) 또는 `features/scalper/daySession.ts`
```ts
// KST 고정 10:00~18:00, DST 영향 없음(문서 명시) — Intl로 KST 시각 뽑아 비교.
export function isDaytimeSessionOpen(epochMs: number): boolean
```
`sessionOf()`(ET 기준, simLab.ts)와는 **독립된 판정**이다. **세 세션(주간거래·정규장군[프리/정규/애프터]·완전
휴장)은 시간대가 겹치지 않는다** — 사용자 확인: 동시 운용 자체가 성립하지 않고, "지금이 어느 창이냐"만
판정하면 된다(§5-5 결정 완료, 아래 3-5 참고).

### 3-2. `kis/` 레이어 확장
- `trId.ts`: `DAYTIME_ORDER_TR = { buy: 'TTTS6036U', sell: 'TTTS6037U' }`, `DAYTIME_CANCEL_TR = 'TTTS6038U'`.
  `TrPair`(live/paper) 구조를 강제로 맞추지 않는다 — 모의 없음을 타입으로 드러내야 kis-openapi 철칙 2
  ("TR ID 미해석 시 주문 차단")를 자연스럽게 지킨다. `environment==='paper'`로 호출되면 즉시 throw.
- `order.ts`: `placeOverseasDaytimeOrder()` 신설(기존 `placeOverseasOrder`를 고치지 않는다 — 정규장 경로
  회귀 방지). 엔드포인트 `daytime-order`, body는 `SLL_TYPE` 제외, `ORD_DVSN` 고정 `'00'`,
  `OVRS_EXCG_CD`는 `NASD`/`NYSE`/`AMEX`(§2 확정).
  가격 절사(`roundOverseasOrderPrice`/`formatOverseasOrderPrice`/`roundingForSide`)는 **정규장과 동일 규칙
  그대로 재사용**(사용자 확정 — 문서에 별도 규칙 언급 없음, 다른 요구 전까지 동일 취급).
- `orderCancel.ts`: `cancelOrAmendOverseasDaytimeOrder()` 신설. `CTAC_TLNO`/`MGCO_APTM_ODNO`를 빈 문자열
  고정으로 채워 필수값 누락 거절을 막는다.

### 3-3. 실시간 시세 확장 — `kis/realtimePrice.ts`
**tr_key 접두 = `R` — 확정.** `실시간지연체결가.txt`/`실시간호가.txt` 원문에 "미국 주간거래: R+시장구분(3자리)+
종목코드, 예) RBAQAAPL"로 명시돼 있고, KIS 공식 GitHub 예제(`overseas_stock_examples_ws.py`)의
`kws.subscribe(request=asking_price, data=["RBAQAAPL"])` 호출도 동일하다. `D`(무료시세) 접두는 정규장 전용이고
**주간거래에는 애초에 D 옵션이 없다**(문서에 무료/유료 구분 자체가 없음 — 유료시세 신청 여부와 무관하게
주간거래는 R 고정).
- `RealtimeMarketCode`에 `'BAY' | 'BAQ' | 'BAA'` 추가.
- `buildQuoteTrKey`/신규 `buildDaytimeQuoteTrKey`류로 `R${market}${symbol}` 조립 함수를 분리한다
  (기존 `buildFreeQuoteTrKey`/`buildQuoteTrKey`는 D 고정이라 그대로 두고 별도 함수로 R을 강제 — 실수로
  D를 보내 주간거래 구독이 조용히 실패하는 걸 막는다).
- `looksLikeRsym`은 이미 `BAQ|BAY|BAA`를 인식하므로 파싱 쪽은 추가 작업 불필요.
- 분봉조회(`kis/minuteChart.ts` 있다면)도 참고: `분봉조회.md`에 "미국주식 주간거래(EXCD: BAY/BAQ/BAA)는
  최대 1일치 분봉만 조회 가능" — 변곡점 감지가 다일봉 히스토리에 의존한다면 이 제약을 감안해야 한다.

### 3-4. 브로커 계층 — `createKisBroker` 분기
`ScalperBroker` 인터페이스(placeOrder/cancelOrder/amendOrder/fetchFills/fetchPosition)는 그대로 두고,
`createKisBroker(config)`에 `tradingWindow: 'regular' | 'daytime'`을 추가해 내부에서
`placeOverseasOrder` vs `placeOverseasDaytimeOrder`(주문), `cancelOrAmendOverseasOrder` vs
`cancelOrAmendOverseasDaytimeOrder`(취소)만 갈아끼운다.

`fetchFills`(미체결내역 TTTS3018R)/`fetchPosition`(잔고)은 정규장과 **동일 TR을 우선 재사용**한다 —
`미체결내역.txt`의 `OVRS_EXCG_CD` 허용값 목록(NASD/NYSE/AMEX 등)에 BAY/BAQ/BAA 같은 주간 전용 코드가
없다는 것은, 주간거래 주문도 `NASD`/`NYSE`/`AMEX` 코드로 같은 조회 TR에 잡힌다는 정황 증거다(주문 자체가
그 코드로 나가므로). 다만 문서에 명시적 언급은 없어 **실계좌 1회 검증은 필요**(§6-1, 리스크는 낮음).

새 오더 오브젝트를 매 사이클 새로 만드는 기존 구조(`AutoPilotManager`가 슬롯별 브로커를 진입 시점에
구성)를 그대로 따르되, **진입 시점의 `isDaytimeSessionOpen()` 판정으로 tradingWindow를 고정**한다
(사이클 도중 창이 닫혀도 진행 중인 사이클은 완주 — 기존 "매도까지 반드시 완주" 원칙과 동일선상).

### 3-5. 감시/진입 게이트 — `autopilot.ts`
- 오토파일럿 상태기계는 그대로. reselect(감시 대상 선정) 앞단에 게이트 하나만 추가:
  `isDaytimeSessionOpen() || sessionOf(now) !== 'off'`가 아니면(즉 모든 창이 닫혀 있으면) 신규 진입 금지.
- **동시 운용 없음 — 확정**(사용자 확인): 주간거래·프리마켓·정규장·애프터마켓은 시간대가 겹치지 않으므로
  "지금 열려 있는 창이 정확히 하나"가 항상 성립한다. 게이트는 배타적 우선순위가 아니라 **단순 판정**이면
  된다 — 어느 창인지 하나 고르고 그 창의 브로커·거래소코드·워치리스트를 쓴다.
- 워치리스트/자금 세션 공유 여부는 여전히 결정 필요(§6-2) — 겹치지 않는다는 것과 "같은 워치리스트를 쓸지"는
  별개 질문이다.
- 진입 거부(종목 미지원) 대응: `placeOrder` throw 시 기존 FAULT 인터록이 받되, 주간거래 전용 사유
  ("이 종목은 주간거래 미지원")를 이벤트에 남겨 같은 종목 재시도 루프에 빠지지 않게 즉시 그 슬롯만 해제.

### 3-6. 시뮬레이션 — 실거래와 같은 착수 라운드, 안전 체크포인트로 유지
사용자 확정: **이번 라운드에 시뮬레이션·실거래를 함께 만든다**(범위를 시뮬만으로 좁히지 않는다). 다만
`SimExchange`(simBroker.ts)는 세션 개념이 전혀 없어 WS 틱만 들어오면 수정 없이 그대로 동작하므로,
**구현 순서상** 3-3(WS 구독)이 뚫리는 즉시 시뮬로 먼저 관찰하고, 그 관찰 결과를 실거래 오픈 전 안전
게이트로 쓰는 것을 권장한다(스코프 축소가 아니라 릴리스 순서 문제):
1. 시뮬레이션 모드 ON + daytime 게이트 → 10:00~18:00 KST에 가상 진입/청산 관찰
2. `sim_episodes.entry_session`에 `'daytime'` 라벨 추가(현재 pre/regular/after/off 4종 + 1종)
3. 같은 날 실거래 TR(3-2)도 배선 완료해두고, 소액 리허설 전까지는 시뮬 지표로 그리드 폭·배율을 튜닝

### 3-7. UI
- AutoPilotScreen 상태 패널에 "정규장" 배지 옆 "주간거래" 배지 추가(현재 어느 창이 열려 있는지).
- 워치리스트 공유 여부(§6-2)에 따라 설정 화면 구조가 갈린다.

## 5. 리스크

- **종목 화이트리스트 부재** — 사전 조회 API가 없어 "일부 종목만 지원"을 주문 거절로만 알 수 있다.
  거절 → 즉시 슬롯 해제가 유일한 방어선.
- **모의투자 완전 미지원** — 주간거래는 페이퍼 계좌로 리허설이 안 된다. 3-6(시뮬레이션 관찰)이 사실상
  유일한 안전한 사전 검증 경로 — 실거래(5단계)를 열기 전 반드시 거친다.
- **운영시간 표기 불일치(§2-1)** — 시세 문서의 16:00과 주문 문서의 18:00 차이를 확인 없이 한쪽으로만
  구현하면, 16:00~18:00 구간에서 "주문은 가능한데 시세가 끊겨" 그리드가 눈먼 채 도는 상황이 생길 수 있다.
  단계 3에서 실계좌로 반드시 확인.
- **분봉 히스토리 1일 제한** — 변곡점 감지가 여러 날치 분봉을 참조한다면 주간거래 구간에서는 그 로직이
  무력화될 수 있다(§3-3 하단).

## 6. 남은 결정/확인 사항

| # | 이슈 | 상태 |
|---|---|---|
| 1 | WS 16:00 이후(18:00까지) 시세 수신 지속 여부, `fetchFills`/`fetchPosition`이 주간거래 체결도 잡는지 | **실측 필요**(§2-1, §3-4) — 유일하게 남은 미확인 항목 |
| 2 | 정규장·주간거래 워치리스트/자금(세션) 공유 vs 완전 분리 | **결정 필요** — 동시 운용은 없음이 확정됐지만(§3-5) 자원 공유 여부는 별개 |

착수 순서: **1~4단계는 §6과 무관하게 바로 시작**(실거래를 내보내지 않음). 5단계(실거래) 전에 §6-1을
실계좌로 확인하고, §6-2는 늦어도 6단계(UI) 전에 정하면 된다.
