# 주간거래(Blue Ocean ATS) Plan

> 상태: **설계 단계** — 코드 미착수. 사용자 지시(2026-08-06)로 `docs/koreainvestment/주간주문.txt`,
> `주간정정취소.txt` 반입 확인 후 작성. 구현 전 §6 결정 필요 사항에 대한 사용자 확정이 선행돼야 한다.

## 1. 배경 / 무엇을 여는가

"주간거래"는 미국 정규장(한국시간 22:30~05:00, `entry_session`의 pre/regular/after/off)과는
**완전히 별개의 체결소**다. KIS 문서 표기: EXCD `BAY`(뉴욕-주간) / `BAQ`(나스닥-주간) / `BAA`(아멕스-주간) —
Blue Ocean ATS로 추정되는 대체거래소를 한국시간 **10:00~18:00 고정**(서머타임 무관, 문서에 "Summer Time 동일"
명시)으로 중계하는 채널이다.

- 이미 존재하는 것: `kis/priceDetail.ts`의 `PriceDetailExchangeCode`에 `BAY/BAQ/BAA` 정의됨(현재가상세 조회만).
  `kis/realtimePrice.ts`의 `looksLikeRsym` 정규식도 `BAQ|BAY|BAA`를 이미 인식(그러나 `RealtimeMarketCode`
  타입에는 아직 없어 `buildFreeQuoteTrKey`로 구독 키를 못 만든다 — 구멍).
- 아직 없는 것: 주문(`kis/order.ts`) · 정정취소(`kis/orderCancel.ts`) · TR ID 표(`kis/trId.ts`) 전부
  정규장 전용이라 주간거래 주문은 아예 못 나간다. `features/scalper/*`(오토파일럿·그리드·시뮬)는
  session 개념이 없다 — `sessionOf()`(simLab.ts)도 정규장 ET 시계열만 판정한다.

목표: 기존 변곡점 감지(`core/detector`) + 그리드(`core/grid`) + 오토파일럿 상태기계를 **그대로 재사용**하면서,
10:00~18:00 KST 창에서 (a) 실거래 또는 (b) 실비용 없는 시뮬레이션으로 굴릴 수 있게 만든다.

## 2. 문서 요약 (반입된 두 파일)

| API | Method/URL | TR ID(실전) | 비고 |
|---|---|---|---|
| 주간주문 | POST `/uapi/overseas-stock/v1/trading/daytime-order` | 매수 `TTTS6036U` / 매도 `TTTS6037U` | **모의투자 미지원**(TrPair 불가 — live 전용). `ORD_DVSN`은 지정가("00") 고정 — 주간거래는 지정가만 허용. Body에 `SLL_TYPE` 필드 자체가 없음(정규장 매도 전용 필드와 다름). |
| 주간정정취소 | POST `/uapi/overseas-stock/v1/trading/daytime-order-rvsecncl` | `TTTS6038U`(정정·취소 공통 1개) | 정규장은 국가별 TR이 갈리지만 주간은 미국 전용 단일 TR. `CTAC_TLNO`·`MGCO_APTM_ODNO`가 Required(Y) — 정규장 취소 경로는 옵셔널 처리했던 필드라 주간은 빈 문자열이라도 반드시 채워야 한다. |

공통 주의사항(두 문서 동일): "미국주간거래의 경우, 모든 미국 종목 매매가 지원되지 않습니다 — 일부 종목만 매매
가능", "미국주간거래시간 외 API 호출 시 에러 발생". 즉 **화이트리스트가 없다** — 거부는 주문 시점에 KIS가
판단하므로, 우리 쪽은 "거부되면 그 종목만 감시 해제"로 대응해야 한다(사전 검증 API 없음).

## 3. 설계

### 3-1. 세션 판정 유틸 — `core/session`(신설) 또는 `features/scalper/daySession.ts`
```ts
// KST 고정 10:00~18:00, DST 영향 없음(문서 명시) — Intl로 KST 시각 뽑아 비교.
export function isDaytimeSessionOpen(epochMs: number): boolean
```
`sessionOf()`(ET 기준, simLab.ts)와는 **독립된 판정**이다. 두 세션은 시간대가 겹치지 않으므로
(주간 10~18 KST ≈ 전일 20:00~04:00 ET 부근 = after 세션 후반~off 전체) 오토파일럿이 "지금 정규장이냐
주간거래냐 둘 다 아니냐"를 명확히 셋 중 하나로 고를 수 있다.

### 3-2. `kis/` 레이어 확장
- `trId.ts`: `DAYTIME_ORDER_TR = { buy: 'TTTS6036U', sell: 'TTTS6037U' }`, `DAYTIME_CANCEL_TR = 'TTTS6038U'`.
  `TrPair`(live/paper) 구조를 강제로 맞추지 않는다 — 모의 없음을 타입으로 드러내야 kis-openapi 철칙 2
  ("TR ID 미해석 시 주문 차단")를 자연스럽게 지킨다. `environment==='paper'`로 호출되면 즉시 throw.
- `order.ts`: `placeOverseasDaytimeOrder()` 신설(기존 `placeOverseasOrder`를 고치지 않는다 — 정규장 경로
  회귀 방지). 엔드포인트 `daytime-order`, body는 `SLL_TYPE` 제외, `ORD_DVSN` 고정 `'00'`.
  가격 절사(`roundOverseasOrderPrice`/`formatOverseasOrderPrice`/`roundingForSide`)는 그대로 재사용 —
  주간거래도 "$1 이상 2자리·미만 4자리" 동일 규칙일 가능성이 높지만 **미확인**(§6-3).
- `orderCancel.ts`: `cancelOrAmendOverseasDaytimeOrder()` 신설. `CTAC_TLNO`/`MGCO_APTM_ODNO`를 빈 문자열
  고정으로 채워 필수값 누락 거절을 막는다.
- 거래소 코드: 주문 Body의 `OVRS_EXCG_CD`는 문서 예시상 `NASD/NYSE/AMEX`(정규장과 동일 코드)로 보인다 —
  `PriceDetailExchangeCode`의 `BAY/BAQ/BAA`는 시세 조회 전용이고 주문 Body 필드에는 없음. **이 매핑도
  실계좌 실측 전엔 가정**(§6-1).

### 3-3. 실시간 시세 확장 — `kis/realtimePrice.ts`
- `RealtimeMarketCode`에 `'BAY' | 'BAQ' | 'BAA'` 추가.
- tr_key 접두가 기존 무료시세 `D`인지, 주간거래 전용 `R`인지 **미확인**(realtimePrice.ts 상단 주석이 이미
  "R은 유료·주간거래 계열로 추정"이라고 남겨둔 대로) — §6-2에서 실측 필요. 확정 전까지는 D/R 둘 다 시도하는
  진단 모드(`rawFieldDebug`)로 1회 실측 후 고정.
- `looksLikeRsym`은 이미 `BAQ|BAY|BAA`를 인식하므로 파싱 쪽은 추가 작업 불필요.

### 3-4. 브로커 계층 — `createKisBroker` 분기
`ScalperBroker` 인터페이스(placeOrder/cancelOrder/amendOrder/fetchFills/fetchPosition)는 그대로 두고,
`createKisBroker(config)`에 `tradingWindow: 'regular' | 'daytime'`을 추가해 내부에서
`placeOverseasOrder` vs `placeOverseasDaytimeOrder`(주문), `cancelOrAmendOverseasOrder` vs
`cancelOrAmendOverseasDaytimeOrder`(취소)만 갈아끼운다. `fetchFills`/`fetchPosition`은 정규장과 동일
TR(잔고·미체결내역)을 그대로 쓴다 — 주간거래도 같은 계좌 잔고에 반영된다고 가정(§6-4, 미확인).

새 오더 오브젝트를 매 사이클 새로 만드는 기존 구조(`AutoPilotManager`가 슬롯별 브로커를 진입 시점에
구성)를 그대로 따르되, **진입 시점의 `isDaytimeSessionOpen()` 판정으로 tradingWindow를 고정**한다
(사이클 도중 창이 닫혀도 진행 중인 사이클은 완주 — 기존 "매도까지 반드시 완주" 원칙과 동일선상).

### 3-5. 감시/진입 게이트 — `autopilot.ts`
- 오토파일럿 상태기계는 그대로. reselect(감시 대상 선정) 앞단에 게이트 하나만 추가:
  `isDaytimeSessionOpen() || sessionOf(now) === 'regular'`가 아니면(즉 두 창 다 닫혀 있으면) 신규 진입 금지.
- 정규장/주간거래 **동시 운용은 이번 범위 밖**(사용자 확인 필요, §6-5) — 창이 겹치지 않으므로 자연스럽게
  "지금이 어느 창이냐"로 브로커·거래소코드가 갈린다. 다만 같은 계좌·같은 워치리스트를 쓸지, 종목군을
  분리할지는 결정 필요.
- 진입 거부(종목 미지원) 대응: `placeOrder` throw 시 기존 FAULT 인터록이 받되, 주간거래 전용 사유
  ("이 종목은 주간거래 미지원")를 이벤트에 남겨 같은 종목 재시도 루프에 빠지지 않게 즉시 그 슬롯만 해제.

### 3-6. 시뮬레이션 우선 적용 (권장 착수 순서)
`SimExchange`(simBroker.ts)는 세션 개념이 전혀 없어 **수정 없이 재사용 가능** — WS 틱만 들어오면
트레이드스루 체결 판정이 그대로 동작한다. 즉 3-3(WS 구독)만 먼저 뚫으면:
1. 시뮬레이션 모드 ON 상태에서 daytime 게이트만 열어 10:00~18:00 KST에 가상 진입/청산을 관찰
2. `sim_episodes.entry_session`에 `'daytime'` 라벨 추가(현재 pre/regular/after/off 4종 + 1종)
3. 실거래 TR(3-2)은 시뮬로 지표(탈출률·소요시간)를 먼저 확인한 뒤에 배선 — 정규장 시뮬 릴리스와 동일한 순서(§3-6이 곧 안전장치)

### 3-7. UI
- AutoPilotScreen 상태 패널에 "정규장" 배지 옆 "주간거래" 배지 추가(현재 어느 창이 열려 있는지).
- 설정에 정규장/주간거래 워치리스트를 분리할지, 하나로 공유할지는 §6-5 결정에 따름.

## 5. 리스크

- **종목 화이트리스트 부재** — 사전 조회 API가 없어 "일부 종목만 지원"을 주문 거절로만 알 수 있다.
  거절 → 즉시 슬롯 해제가 유일한 방어선.
- **모의투자 완전 미지원** — 주간거래는 페이퍼 계좌로 리허설이 안 된다. 3-6(시뮬레이션 우선)이 사실상
  유일한 안전한 사전 검증 경로.
- **WS tr_key 접두 불확실** — 확정 전 실거래를 열면 시세 공백 상태로 그리드가 돌아 위험. 반드시 §4 단계 3
  실측을 실거래(단계 5)보다 먼저 끝낸다.
- **정규장과의 동시 운용 충돌** — 같은 슬롯/자금 관리(세션 손익·PAUSED)를 공유할지 분리할지에 따라
  `autopilotManager.ts`의 세션(자금) 개념과 이름이 겹쳐 혼동 소지(§6-5).

## 6. 결정 필요 사항 (사용자 확인 대기)

| # | 이슈 | 비고 |
|---|---|---|
| 1 | 주문 Body `OVRS_EXCG_CD`가 정규장과 동일하게 `NASD/NYSE/AMEX`인지, 별도 코드가 있는지 | 문서 예시 미제공 — 실측 또는 KIS 포럼 확인 필요 |
| 2 | WS 구독 tr_key 접두 `D` vs `R` | realtimePrice.ts 기존 주석의 미해결 추정을 이번에 실측으로 확정 |
| 3 | 가격 절사 규칙(1$ 기준 2/4자리)이 주간거래도 동일한지 | 미검증 |
| 4 | 주간거래 체결이 정규장과 같은 잔고/미체결내역 TR에 잡히는지 | `fetchFills`/`fetchPosition` 재사용 가능 여부 결정 |
| 5 | 정규장·주간거래 **동시 운용** 범위 — 같은 워치리스트/자금 세션 공유 vs 완전 분리 | UI·`autopilotManager` 세션 모델에 영향 |
| 6 | 착수 범위 — 이번 라운드는 **시뮬레이션까지만**(3-6) vs 실거래(3-4/3-5)까지 한 번에 | 시뮬 우선 권장(§5 리스크 참고) |

작업은 §6 확정 없이도 **1~4단계(세션 판정·kis 레이어 뼈대·WS 확장·시뮬 배선)** 까지는 안전하게 착수 가능하다
(실거래를 실제로 내보내지 않으므로). 5단계(실거래)는 §6-1·6-3·6-4가 실측으로 확정된 뒤 진행한다.
