### 구현 (2026-08-10)

1. `kis/trId.ts` — `resolveDaytimeOrderTrId`/`resolveDaytimeCancelTrId`(미국·실전만, 아니면 undefined→호출부 throw).
2. `kis/order.ts`·`kis/orderCancel.ts` — `daytime?: boolean` 파라미터로 URL·TR·Body 분기.
3. `createKisBroker` — **발주 시각**이 주간거래 창이면 daytime 계열로 발주하고 odno별로 플래그를 고정,
   이후 정정·취소는 세션이 바뀌어도 원주문 계열을 따른다. paper 환경은 판정 자체를 끔(모의 미지원).
4. `autopilotManager` — 주간거래 trKey 분기(R+BAQ/BAY/BAA) 복원(00f5c50과 동일 구조) + **세션 전환 감시

   구현에는 없어서 경계에서 틱이 끊겼다).
5. AutoPilotScreen — "주간거래" 배지(파랑, 정보성).

## 1. 이번 전환으로 없어지는 것 / 남는 것

**없어진다** (v3까지 설계했던 것 중 전부 폐기):
- `kis/order.ts`의 `placeOverseasDaytimeOrder()`, `kis/orderCancel.ts`의
  `cancelOrAmendOverseasDaytimeOrder()`, `kis/trId.ts`의 `TTTS6036U/6037U/6038U` TR 등록 — **만들지 않는다.**
  실주문이 나갈 코드 경로 자체가 없으면 "미체결내역이 주간거래를 반영하는지" 질문이 성립하지 않는다.
- `createKisBroker`의 `tradingWindow: 'regular' | 'daytime'` 분기 — 불필요(실거래 브로커가 daytime을 아예 모른다).
- 종목 화이트리스트 부재로 인한 주문 거절 대응 로직 — 실주문을 안 내니 거절도 없다.
- §6-1(미체결내역 실측), 5단계(실거래 배선), 실거래 관련 리스크 항목 전부.

**남는다** (실제로 필요한 건 이 세 가지뿐):
1. 세션 판정(`isDaytimeSessionOpen`, 10:00~16:00 KST) — 지금이 주간거래 창인지만 안다.
2. WS 실시간시세 확장 — `SimExchange`가 체결 판정을 하려면 진짜 틱이 필요하다(`kis/realtimePrice.ts`에
   `BAY/BAQ/BAA` + `R` 접두 추가). 시뮬레이션이라도 "실시세로 주문만 가상"이라는 기존 원칙(2026-08-06
   시뮬레이션 모드 plan)은 그대로 지킨다.
3. **강제 가드** — 주간거래 세션에서는 전역 "시뮬레이션 모드" 설정값과 무관하게 항상 `SimExchange`만
   연결한다(§3-3). 사용자가 설정 화면에서 시뮬레이션을 꺼놨어도 주간거래 창에서는 실거래 브로커가
   물리적으로 생성되지 않는다 — "절대 네버" 요구를 코드 레벨 불변식으로 만든다.

## 2. 문서 재확인 요약 (v2/v3에서 이미 확정한 것, 그대로 유효)

- **TR ID 참고용**(주문 기능은 안 쓰지만 문서 배경 이해용으로 남김): 주간주문 매수 `TTTS6036U` / 매도
  `TTTS6037U`, 주간정정취소 `TTTS6038U` — 모의투자 미지원, 지정가 전용.
- **운영 창 = 10:00~16:00 KST**(§2-1, v3 확정 유지) — 시세(WS) 문서 기준. 시뮬레이션도 실시세가 없으면
  돌아가지 않으므로 이 결정은 실거래를 접어도 그대로 적용된다.
- **WS tr_key = `R` + `BAY`/`BAQ`/`BAA` + 종목코드** — `실시간지연체결가.txt`/`실시간호가.txt` 원문 +
  KIS 공식 GitHub 예제(`RBAQAAPL`)로 확정.
- 종목별 지원 여부(화이트리스트 없음) — 이제 무관하다. 시뮬레이션은 시세만 받으면 아무 종목이나 그리드를
  돌릴 수 있고, "이 종목은 주간거래 미지원"이라는 실주문 거절 자체가 없다.

## 3. 설계

### 3-1. 세션 판정 유틸 — `core/session`(신설) 또는 `features/scalper/daySession.ts`
```ts
// KST 고정 10:00~16:00, DST 영향 없음(문서 명시) — Intl로 KST 시각 뽑아 비교.
export function isDaytimeSessionOpen(epochMs: number): boolean
```
`sessionOf()`(ET 기준, simLab.ts)와는 독립된 판정. 정규장군(프리/정규/애프터)과 시간대가 겹치지 않는다.

### 3-2. 실시간 시세 확장 — `kis/realtimePrice.ts`
- `RealtimeMarketCode`에 `'BAY' | 'BAQ' | 'BAA'` 추가.
- `R${market}${symbol}` 조립 전용 함수를 신설(예: `buildDaytimeQuoteTrKey`) — 기존 `buildFreeQuoteTrKey`/
  `buildQuoteTrKey`(D 고정)는 그대로 두고 섞이지 않게 분리한다.
- `looksLikeRsym`은 이미 `BAQ|BAY|BAA`를 인식하므로 파싱 쪽은 추가 작업 불필요.
- 분봉조회 제약 참고: `분봉조회.md`에 "미국주식 주간거래(EXCD: BAY/BAQ/BAA)는 최대 1일치 분봉만 조회 가능"
  — 변곡점 감지가 다일봉 히스토리를 쓴다면 이 구간만 그 로직이 좁아질 수 있다.

### 3-3. 강제 시뮬레이션 가드 — 이번 설계의 핵심
`AutoPilotManager`(managerProvider.tsx)가 브로커를 고르는 지점(기존 `simMode` mutable ref로 KIS/SimExchange를
가르는 바로 그 자리)에 다음 규칙을 얹는다:

```
if (isDaytimeSessionOpen(now)) {
  broker = SimExchange   // 전역 simMode 설정과 무관 — 항상 강제
} else {
  broker = simMode ? SimExchange : createKisBroker(...)   // 기존 로직 그대로
}
```

- **실거래 브로커(`createKisBroker`)는 주간거래 세션에서 아예 인스턴스화되지 않는다** — "실수로 켜짐"이
  구조적으로 불가능하다(런타임 토글이 아니라 진입 경로 자체가 없음).
- 시뮬 기록은 기존 원칙 그대로: `trades.*`(실거래 손익 화면)에 안 쓰고, `sim_episodes`에만 쌓인다.
- UI에는 "주간거래는 시뮬레이션 전용입니다"를 명확히 표시해 사용자가 실거래로 착각하지 않게 한다(3-5).

### 3-4. 감시/진입 게이트 — `autopilot.ts`
- reselect 앞단 게이트: `isDaytimeSessionOpen() || sessionOf(now) !== 'off'`가 아니면 신규 진입 금지
  (v3와 동일 — 세 창이 안 겹치므로 판정은 단순).
- 진입 거부 대응 로직(v3의 "종목 미지원 시 슬롯 해제") **불필요** — 시뮬레이션은 KIS에 실주문을 넣지
  않으므로 거절이라는 게 없다. `SimExchange`는 어떤 티커든 받아준다.
- `sim_episodes.entry_session`에 `'daytime'` 라벨 추가(현재 pre/regular/after/off 4종 + 1종).

### 3-5. UI
- AutoPilotScreen 상태 패널에 "주간거래(시뮬)" 배지 — 기존 시뮬레이션 모드 배지(주황)와 같은 톤으로
  통일하되, 문구는 "이 시간대는 항상 시뮬레이션입니다"로 실거래 배지와 혼동되지 않게 한다.
- 실거래 관련 설정(거래소코드 선택 등)은 주간거래 워치리스트에 노출하지 않는다 — 애초에 안 쓰인다.

확인받을 수 있으면(포럼 문의 등) 별도 plan으로 재검토한다.

## 5. 리스크

- **WS tr_key `R` 접두 미검증** — 문서·공식 예제 근거는 확실하지만 이 앱의 WS 클라이언트로 실제 구독
  성공(ACK) 확인은 아직 안 했다. 단계 2에서 실계좌로 확인.
- **강제 가드 우회 방지** — `managerProvider.tsx`의 브로커 선택 지점이 앞으로 리팩터링될 때 이 규칙이
  실수로 빠지면 daytime에 실거래가 열릴 수 있다. 반드시 **유닛 테스트로 고정**(단계 3 완료 기준에 명시)
  해서 회귀를 막는다 — 이 테스트가 사실상 "절대 네버"의 유일한 보증선이다.
- **분봉 히스토리 1일 제한** — 변곡점 감지가 여러 날치 분봉을 참조한다면 주간거래 구간에서는 좁아질 수
  있다(§3-2 하단). 시뮬레이션 지표 해석 시 감안.

## 7. 남은 일 (실계좌/실기기 전용)

코드·유닛테스트는 전부 끝났다(vitest 474개 green, `tsc --noEmit` 통과). 아래 둘은 CI/유닛테스트로 확인할 수
없는 항목이라 사용자가 실계좌·실기기로 직접 확인해야 한다:

1. `R${BAY|BAQ|BAA}${symbol}` 형태의 tr_key로 WS 구독 시 실제 ACK(`rt_cd='0'`)를 받는지, 틱이 오는지.
2. 평일 10:00~16:00 KST에 앱을 켜 두고 자동 단타를 실행해 "주간거래 · 항상 시뮬레이션" 배지가 뜨는지,
   가상 사이클이 관찰되는지, `sim_episodes`에 `entry_session='daytime'` 행이 쌓이는지.
