## 1. 목표

현재 리스트 원천은 **거래량순위 · 거래증가율순위 · 거래회전율순위** 3종(NAS·당일)이고 각 상위 3개 → **9종목**이다.
여기에 **상승율/하락율 순위의 상승율(GUBN=1)** 을 4번째 원천으로 추가하고 **상위 3개**를 더 채용한다.

| 항목 | 현재 | 변경 후 |
|---|---|---|
| 리스트 원천 | 3종 | **4종**(+ 상승률) |
| 상시 리스트 | 9종목 | **12종목** |
| 핀 유예(사이클 중 탈락) 포함 최대 | 10 | **13** |
| 순위 폴링 API 콜/주기 | 3콜 / 3분 | **4콜 / 3분**(직렬 유지) |
| WS 구독 | 체결가 9~10 + 호가 3 = 최대 13 | **체결가 12~13 + 호가 3 = 최대 16** |

변경하지 않는 것(기존 결정 유지):
- 거래소 **NAS**, 기간 **당일(NDAY=0)** — 사용자 재확정.
- 필터 규칙: `rate > 0` + `e_ordyn` 주문가능. 랭킹 간 중복 티커는 1개만(우선권 순 차순위 충원).
- **RUN(매매 사이클)은 동시에 1종목만.** 금액 규칙·손절 없음·장 마감 처리 없음.
- 폴링 주기 3분.

### 1-1. 판단이 필요했던 지점 — 기본값으로 진행(다르면 말씀 주세요)

| # | 항목 | 채택 기본값 | 근거 |
|---|---|---|---|
| A | 중복 우선권에서 상승률의 위치 | **맨 뒤** (거래량→증가율→회전율→**상승률**) | 기존 9종목 구성이 그대로 보존되고 상승률은 남은 티커로만 채운다. 변화량 최소 — 확장 전후 비교가 쉽다. |
| B | 감시(detector 부착) 종목 수 `WATCH_COUNT` | **3 유지** | 리스트만 넓히고 감시 폭은 그대로. 호가(R) 구독 3건·detector 3개 유지라 WS 예산과 CPU 영향이 리스트 확장분(체결가 3건)에 그친다. 후보 풀이 12로 넓어져 top3의 질 자체가 올라간다. |
| C | 상승률 조회의 `VOL_RANG` | **'3'(1만주 이상)** — 이 원천만 | 상승률 순위는 등락률 내림차순이라 **거래량이 거의 없는 초저유동성 잡주**가 상단을 점거하기 쉽다. 단타는 체결이 붙어야 성립하므로 최소 거래량 필터를 건다. 기존 3종은 이미 거래량 기반이라 `'0'` 유지. |
| D | 하락율(GUBN=0) | **쓰지 않음** | 현 전략은 롱 전용(+등락 필터). 하락율은 API만 만들어 두고 조회 탭에서만 노출. |

## 4. 리스크와 대응

| # | 리스크 | 대응 |
|---|---|---|
| 1 | **WS 등록 상한** — 체결가 13 + 호가 3 = 16건. KIS는 세션당 등록 건수 상한이 있고 실측이 필요하다(원 plan §5-5도 "실측 포함"으로 남겨둔 항목). | 자동 모드와 수동 모드는 상호 배타라 동시 점유는 없다. 리허설에서 구독 ACK 실패가 기록 패널에 뜨는지 관찰하고, 걸리면 ① 상승률 슬롯 3→2 축소 ② 호가 구독을 사이클 중 1건으로 제한 순으로 줄인다. |
| 2 | **저유동성 잡주 유입** — 상승률 상위는 등락률만 보므로 체결이 거의 없는 종목이 올라온다. 슬롯을 차지한 채 틱/초 0으로 놀 수 있다. | §1-1 C의 `VOL_RANG='3'`로 1차 방어. 그래도 뜨면 상승률 원천에만 최소 틱/초 조건을 추가 검토(리허설 결과 보고 결정 — 지금은 넣지 않는다). |
| 3 | **API 콜 증가** — 3분마다 4콜(직렬). | 직렬 호출 유지로 유량 제한(초당 거래건수)에 여유. 실패 시 기존 동작대로 그 주기 리스트는 직전 상태 유지(`ScalperWatchlist.refresh`의 catch) — 단, 현재 구현은 **한 콜이라도 실패하면 스냅샷 전체가 실패**한다. 원천이 4개로 늘어난 만큼 실패 확률도 늘므로, 4단계에서 `fetchSnapshot`을 **원천별 부분 실패 허용**(실패한 원천은 빈 배열, 나머지로 리스트 구성)으로 바꿀지 함께 판단한다. → **권장: 부분 실패 허용으로 변경.** |
| 4 | `RankingKind` 확장이 `Ranking.tsx`의 exhaustive switch를 깨뜨림 | 2단계에서 같이 처리(컴파일러가 강제하므로 누락 불가). |
| 5 | 리스트 12개 렌더 부하 | 이미 FlatList 기반, 슬롯당 연산은 리샘플 push 1건 — 영향 미미. |

## 5. 리허설 체크리스트(정규장 소액)

1. 리스트가 **12종목**으로 채워지는지, 배지에 '상승률' 출처가 3건 보이는지.
2. 상승률 출처 종목의 틱/초가 실제로 붙는지(0에 머무는 잡주가 아닌지) — 머물면 §4-2 대응.
3. 3분마다 교체가 도는지, 중복 티커가 리스트에 두 번 뜨지 않는지.
4. 구독 ACK 실패가 기록 패널에 뜨는지(16건 예산 실측).
5. 진입 1회 — 체결가·수량·금액 조정(절반/2배) 기록 확인.
6. 순위 4콜 중 1콜 실패 시 리스트가 어떻게 되는지(§4-3 반영 후: 나머지 원천으로 9종 유지).
