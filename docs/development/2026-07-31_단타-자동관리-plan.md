## 1. 목표 요약 (사용자 확정)

### A. 리스트 관리
- 원천: 조회 > 순위의 **거래량순위 · 거래증가율순위 · 거래회전율순위** 3종 (거래소 **NAS**, 기간 **당일**(NDAY=0)).
- 각 순위에서 **등락률이 +인 종목 중 상위 3개**씩 → 합계 **9종목**을 단타 리스트로 상시 유지.
- 순위에서 밀려나거나 등락률이 음전되면 제거하고 다음 후보로 교체.
- 단, 제거 대상이 **매매 사이클 진행 중(RUN)** 이면 제거를 미루고, 사이클 종료(STOP/DONE) 즉시 제거.
  → 일시적으로 최대 **10종목**, 평시 9종목 유지가 목표.
- 폴링 주기: **3분** (정규장 시간에만).
- 랭킹 간 중복 티커는 **1개만** 리스트에 올린다(중복 없이 9티커).

### B. 단타 관리
- 단타 도메인이 **상태 · 금액 · 종목**을 중앙 관리 (기존: 카드별 개별 수량·개별 RUN → 폐지 방향).
- **RUN(매매 사이클)은 동시에 1종목만.**
- 시세(WS 체결가) 수신은 리스트 전 종목이 한다. 종목별 **틱/초**를 실시간 산출.
  - 틱/초는 **평균이 아니라 현재 시점 기준**(순간 활발도) — 짧은 슬라이딩 윈도우(제안 10초)로 계산.
- 틱/초 상위 **3종목만 변곡점(매수 신호) 계산**. 나머지 6종목은 시세 수신·틱/초 계산만.
- 매수 신호 발생 → 그 종목 매수 → 그 종목만 매도 변곡점 감시 → 매도 → 사이클 종료 → 다시 상위 3종목 감시로 복귀.
- 동시 매수신호 발생 시 **틱/초 높은 쪽** 채택.
- **금액 기반 수량 산정**: 목표 금액 ÷ 현재가 → 수량 환산. `qty < 1`(1주 가격이 금액보다 큼)이면 **진입 포기**.
- **금액 조정 규칙**: 사이클이 수익이면 금액 **절반**, 손실이면 금액 **2배**. **상·하한 없음**(사용자 확정 — 서킷브레이커 두지 않는다).
- **손절 라인 없음** — 변곡점(매도 신호)이 곧 손절 라인이다. detector 기본 동작(매도 확인 대기·급락 임계 포함) 외 별도 손절 로직을 추가하지 않는다.
- **장 마감 처리 없음**(사용자 확정 — 사용자가 깨어 있는 시간에만 구동, 마감 임박 진입 금지·강제 청산 로직 두지 않는다).

### C. 부수 결정
- 수동 카드 상한 `MAX_INSTANCES` 3 → **10** 상향 (자동관리 모드와 별개인 기존 수동 모드의 상한).

## 2. 아키텍처 결정

### 2-1. 인스턴스 개념과의 관계 — "구독은 얇게, 사이클은 하나만"
자동관리 모드에서 리스트 종목 9~10개를 기존 `ScalperInstance`(RunCycle 포함)로 만들지 **않는다**.
인스턴스는 "사이클 실행기"라 무겁다. 대신:

- **FeedSlot**(신규, 경량): 종목당 1개. WS 체결가 구독 + 틱/초 계산 + **리샘플러 상시 가동**. RunCycle 없음.
- **detector는 틱/초 상위 3개 슬롯에만 부착/탈착.**
  ⚠ 핵심: 리샘플 버퍼는 리스트 전 종목이 항상 채운다(연산이 미미함 — 3초 청크에 값 1개 push).
  detector 워밍업 조건은 "버퍼 가득참(31청크 ≈ 93초)"이므로, 버퍼를 상시 채워두면
  감시 대상이 교체돼도 **워밍업 재대기 없이 즉시 판정 가능**하다. 버퍼를 안 채우면 교체마다 93초 공백이 생긴다.
- **RunCycle은 오토파일럿이 1개만 소유** — 매수 신호가 뜬 종목으로 그때그때 생성(티커·수량 주입), DONE 후 폐기.
- WS 등록 예산(사용자 확정): **체결가(D)는 전 종목**(9~10건), **호가(R)는 틱/초 상위 3종목만**(사이클 중엔 보유 종목이 감시 대상이므로 자연히 포함) = **최대 13건**.

### 2-2. 모듈 배치
```
features/scalper/
  tickRate.ts          # 틱/초 계산기 (10초 슬라이딩 윈도우 — 순간 활발도, 순수 로직)
  watchlist.ts         # 리스트 관리자 — 순위 3종 폴링→필터→diff→교체, RUN 종목 핀 고정
  feedSlot.ts          # 경량 구독 슬롯 — 틱 수신·틱/초·리샘플 상시, detector 탈부착
  autopilot.ts         # 단타 관리자 — 상태머신·금액 관리·감시 3종 선정·사이클 소유
  ui/AutoPilotScreen…  # 자동관리 UI (모드 전환, 리스트 카드, 마스터 Run/Stop)
```
`core/`(resample·detector·cycle)와 `kis/`(ranking·realtimePrice·주문)는 **무수정 재사용**이 원칙.
수정이 필요해지면 해당 단계에서 명시.

### 2-3. 리스트 관리 상세 규칙
- 폴링: 3개 순위 API를 **3분 간격** 직렬 호출. 정규장 시간에만.
- 필터: `rate > 0`(응답에 이미 있음 — 추가 시세 조회 불필요) + `e_ordyn` 주문가능 종목만.
- **랭킹 간 중복 티커**: 우선권은 거래량 → 증가율 → 회전율 순. 앞 랭킹이 가져간 티커는 뒤 랭킹에서 건너뛰고 차순위로 채운다. (9슬롯에 항상 서로 다른 9티커)
- diff 적용: 제거 대상이 오토파일럿 보유/사이클 진행 종목이면 **핀 고정**(제거 유예) → 사이클 종료 콜백에서 즉시 제거. 감시만 하던(미보유) 종목은 즉시 제거·교체.
- 교체 시 FeedSlot 생성/폐기 + WS 구독 등록/해제는 매니저의 기존 멀티플렉스 경로 재사용.

### 2-4. 오토파일럿 상태머신
```
IDLE ─Run─▶ SCANNING(틱/초 상위3 선정·detector 부착)
        ─매수신호─▶ ENTERING(주문·체결폴링) ─▶ HOLDING(해당 종목만 매도 감시)
        ─매도신호/급락─▶ EXITING ─체결─▶ SETTLE(손익 판정·금액 조정·기록) ─▶ SCANNING
Stop: 어느 상태든 → 보유 있으면 전량 매도 후 IDLE (기존 RunCycle.stop 의미 그대로)
FAULT: 브로커 오류 인터록 — 기존 인스턴스와 동일하게 사용자 Stop으로만 해제
```
- 감시 3종 선정: 틱/초 내림차순. **히스테리시스** — 교체는 30초마다 재평가하되, 신규 진입 종목이 기존 감시 종목의 틱/초를 **20% 이상** 상회할 때만 교체(빈번한 탈부착 방지). ENTERING~SETTLE 동안은 재평가 중단.
- 동시 매수신호(같은 폴 주기에 2개 이상): **틱/초 높은 쪽** 채택, 나머지는 무시(신호 소멸).

### 2-5. 금액 관리
- 저장 항목: `baseAmountUsd`(사용자 입력 기준액), `currentAmountUsd`(조정 반영액). AsyncStorage 영속.
- 수량 환산: `qty = floor(currentAmountUsd / 매수가격)`, `qty < 1`이면 **진입 포기**(신호 무시하고 SCANNING 유지 — 사용자에게 배지로 알림).
- 조정: SETTLE에서 실현손익 기준 수익 → `current /= 2`, 손실 → `current ×= 2`, 본전(±0) → 유지. **상·하한 없음**(사용자 확정).
- 매수가능금액 부족으로 주문이 거절되면 기존 FAULT 인터록 경로를 그대로 탄다(별도 사전 상한 없음).

### 2-6. 재시작 복원 (사용자 확정)
- 앱 재시작 시 상태는 IDLE부터. **잔고조회로 보유 감지** → 감지되면 FAULT 배지로 알리고 **사용자 수동 정리** 유도. 자동 재개는 v2.
- `currentAmountUsd`는 영속값 그대로 복원.

## 5. 리허설 체크리스트 (정규장 실계좌 소액 — 남은 유일한 단계)

1. 설정 탭에서 투입 금액을 소액(예: $30)으로 설정하고 자동 단타 시작.
2. 리스트가 9종목으로 채워지는지, 3분마다 교체가 일어나는지(기록 패널) 확인.
3. 감시 3종 하이라이트가 틱/초 순으로 붙는지, 잦은 교체(깜빡임)가 없는지 확인 — 있으면 히스테리시스 배율 상향 검토.
