# 계좌 없이 둘러보기(데모 모드) — 앱스토어 심사 대비 plan (2026-08-12)

> 상태: **보류 — 구현하지 않음. 앱스토어 심사를 받게 될 때 이 문서로 착수한다** (2026-08-12 사용자 결정).
>
> 앱스토어 심사 예정이 없어 "계좌 없는 사람에게 보여줄 일"이 지금은 없다. 반면 §4 Phase 2의
> 픽스처 350줄은 KIS 응답 스키마·화면이 바뀔 때마다 같이 손봐야 하는데, 쓰는 사람이 없으면
> 조용히 썩는 순수한 짐이 된다. 그래서 **가치가 생기는 시점까지 만들지 않는다.**
>
> **재검토 시점**: 앱스토어 심사를 받게 될 때. 그때는 **심사 기간에만 넣었다가 통과 후 제거**하는
> 형태를 검토한다(사용자 구상). 이 문서는 그때 그대로 착수할 수 있게 남긴다.
>
> 그때 먼저 확인할 것 — Apple은 로그인이 필요한 앱에 **심사용 데모 계정 제공**을 요구하는 것이지
> 데모 모드 자체를 요구하지는 않는다. `approved_users`에 심사용 계좌를 하나 승인해 주는 것으로
> 끝날 수도 있다(다만 KIS 키가 없으면 심사자가 빈 화면만 보게 되므로, 그 지점을 실제 심사 요건과
> 대조한 뒤에 이 문서를 꺼낼지 정한다).
>
> 아래 본문은 결정 시점의 조사 결과 그대로다. 특히 §3-3(격리)과 §5-2(실계좌 무영향)는
> 코드베이스를 실제로 훑어 확인한 내용이라 재착수 때 다시 조사할 필요가 없다.

## 1. 배경 / 목적

지금은 게이트(`app/index.tsx`)에서 **승인된 KIS 계좌번호**가 있어야만 앱 안으로 들어갈 수 있다.
그래서 처음 보는 사람에게 앱을 보여줄 방법이 없다 — 계좌를 등록하고 승인을 기다려야 화면이 열린다.

**계좌 없이도 앱 전체를 체험**할 수 있게 한다. 화면만 그린 목업이 아니라, **실제 매매 엔진(감지 →
사다리 진입 → 그리드 → 청산)이 가짜 시세를 먹고 진짜로 도는** 형태다. 사용자가 보는 건 진짜 로직이고,
바깥(시세·주문·잔고)만 가짜다.

### 2-1. 사용자 확정 (2026-08-12)

| 항목 | 확정 |
|---|---|
| 데모 종목 | **임의 구성** — NVDA·TSLA·PLTR·SOFI·AMD·MARA 등 6~8개를 코드에 선언 |
| 시작 상태 | **빈 계좌** — 보유 0, 미체결 0. 감지→진입→청산을 처음부터 지켜보게 한다 |

**빈 계좌 + 과거 손익은 모순이 아니다.** 보유·미체결은 비우되 **기간손익(지난 며칠 실현손익)은
픽스처로 채운다** — 이미 청산이 끝난 과거 거래라 빈 계좌와 자연스럽게 공존하고, 손익 탭이 처음부터
텅 비는 걸 막는다. 오늘 몫은 데모 엔진이 매매하면서 실시간으로 쌓인다.

| 화면 | 데모 원천 |
|---|---|
| 트레이딩 | 데모 시세 시뮬레이터 + 데모 브로커 (엔진 실제 구동) |
| 보유종목 / 미체결 | 데모 fetch → `inquire-present-balance` / `inquire-nccs` 픽스처 |
| 손익 | 데모 fetch → `inquire-period-profit` 픽스처 + 데모 거래기록("오늘예상") |
| 오늘 거래 기록 | 데모 엔진이 실제로 쌓는 `StoredTrade` |
| 순위 | **손 안 댐** — 토스 공개 API (이미 동작) |
| 검색 / 종목 댓글 | **손 안 댐** — 토스 공개 API (이미 동작) |
| 종목상세 차트·현재가·호가 | 데모 fetch(차트·현재가) + 데모 피드(실시간) |

### 비범위

- 데모 상태의 영속(앱 재시작 시 유지) — 매번 게이트에서 명시적으로 선택한다. 실계좌 오인 방지가 우선.
- 데모 계좌에서 KIS 키 저장 / 실주문 — 경로 자체를 막는다(§6).
- Supabase 기록 — 데모는 아무것도 서버에 쓰지 않는다.

## 3. 핵심 설계

### 3-1. 단일 진실 원천 — `demoMarket`

여러 화면이 각자 랜덤 픽스처를 만들면 **같은 종목의 현재가가 화면마다 다르다**(보유종목 $182,
종목상세 $174, 트레이딩 게이지 $190). 그래서 **가격은 한 곳에서만 만든다.**

```
features/demo/demoMarket.ts  (모듈 싱글턴)
  ├─ 종목별 현재가를 랜덤워크로 굴린다 (250ms 틱)
  ├─ subscribe(symb, cb)  ← 데모 피드가 구독 → 트레이딩·종목상세 실시간
  └─ snapshot(symb)       ← 픽스처들이 조회 → 잔고 평가금액·차트 마지막 봉·현재가
```

- **결정론적 시드 PRNG**(mulberry32) — `Math.random()` 금지. 같은 세션에서 같은 흐름이 재현되고
  테스트가 가능하다. 시드는 데모 시작 시각으로 1회 고정.
- **감지가 보이게 만드는 게 데모의 핵심.** 실장 변동성으로는 사다리 진입이 몇십 분 안 뜰 수도 있다.
  종목마다 30~90초 주기로 **드리프트 방향을 뒤집는다**(하락 구간 → 반등). 사다리 조건
  (`appSettings.entryLadderIntervalPct` × `entryLadderCount`)을 넉넉히 넘기는 폭으로 잡아
  **체험 1~2분 안에 진입이 한 번은 뜨도록** 한다. 이 파라미터는 코드 상수로 두고 손으로 튜닝한다.

#### (b) 네트워크 — 데모에서 실제 요청이 나갈 수 없게

`setKisFetchOverride`가 걸린 동안 **KIS 도메인으로 가는 모든 요청은 데모 픽스처가 응답**하고,
**픽스처에 없는 엔드포인트는 throw**한다. "빠뜨린 API가 조용히 실서버로 나가는" 경로를 코드로 없앤다.
OAuth(`/oauth2/tokenP`, `/oauth2/Approval`)도 같은 오버라이드가 받는다(§4 Phase 2).

#### (c) 잔존 상태 — 종료는 "정리"가 아니라 "재시작"

모듈 싱글턴이 여럿이다(`managerProvider.cached`, 데모 시세 타이머, `kisFlowConfig.minIntervalMs`,
fetch 오버라이드, 데모 브로커들). 이걸 종료 시 **손으로 원복하는 목록**으로 관리하면 언젠가 하나가
빠지고, 그게 곧 "실계좌에 데모가 남는" 사고다.

→ **체험 종료 = `Updates.reloadAsync()`로 앱 재시작**한다. `expo-updates ~29.0.19`가 이미 설치돼 있다.
   원복 코드가 아예 필요 없어지고, 재시작 후엔 데모 플래그가 영속되지 않으므로(§4 Phase 1)
   무조건 깨끗한 실계좌 상태에서 게이트가 뜬다.
   - 데모 **진입**은 재시작이 필요 없다 — 깨끗한 상태에서 시작하기 때문.
   - 종료 전에 `demo.` 접두 키를 지운다(재시작이 상태를 날려도 AsyncStorage는 남으므로).
   - dev 클라이언트에서 `reloadAsync`가 동작하지 않는 경우를 대비해, 실패 시 게이트로 복귀 + 수동 원복을
     폴백으로 둔다(폴백 경로도 §6 검증 대상).

### 3-4. 데모 브로커의 체결 규칙

옛 SimExchange 규칙(`2026-08-06_시뮬레이션-plan.md` §2-1)을 그대로 쓴다 — **즉시 체결 특례 없음**:

- 매수 지정가 P: 현재가가 **P보다 낮은** 틱이 찍혀야 체결, 체결가 = P
- 매도 지정가 P: 현재가가 **P보다 높은** 틱이 찍혀야 체결, 체결가 = P
- 지정가에 정확히 닿기만 한 틱은 미체결 / 부분체결 없음
- 기체결 취소는 throw(KIS 거절 재현) → OCO·FAULT 경로가 데모에서도 정직하게 돈다

즉시 체결(`FakeBroker(autoFill)`)로 하면 미체결 패널이 항상 비고 그리드가 순식간에 도는 가짜 티가
난다. 이 규칙을 쓰면 **미체결 → 체결 → 재정정**이 실제 리듬으로 보인다.

## 5. 안전성 논거

### 5-1. 데모에서 실주문이 나갈 수 없는 이유

1. 데모 세션의 `credentials`는 더미 문자열이고, 모든 REST·OAuth는 `setKisFetchOverride`가 가로채
   **네트워크로 나가지 않는다**. 픽스처에 없는 엔드포인트는 throw라서 "빠뜨린 API가 조용히 실서버로"도 없다.
2. 주문 경로(`kis/order.ts`)는 `makeBroker`를 통해서만 도달하는데, 데모에선 `createKisBroker`가 아예
   호출되지 않는다 — 옛 주간거래 안전장치와 같은 성질(`2026-08-08_시뮬레이션-제거-plan.md` §4):
   **런타임 토글이 아니라 진입 경로 자체가 없다.**
3. WS 승인키를 받지 않으므로 실 WS 연결도 열리지 않는다.
4. 데모 중에는 KIS 키 저장 자체가 막힌다(Phase 4).

### 5-2. 실계좌 모드가 **한 줄도 달라지지 않는** 이유

실계좌에서 실제로 실행 경로가 바뀌는 수정은 **`getKisFetch()` 하나뿐**이다. 나머지는 전부
`if (isDemoMode())` 가드 안에 있고, 데모로 들어가지 않으면 `features/demo/*`는 **import만 되고
아무 부작용도 만들지 않는다**(모듈 최상위에서 타이머·구독을 시작하지 않는다 — §6-4).

`getKisFetch()`는 오버라이드가 `null`일 때 전역 `fetch`를 그대로 돌려주는 3줄짜리 함수다.
데모 플래그가 꺼진 상태에서 이 함수가 기존 동작과 **동일함을 테스트로 고정**한다(§6-2).

## 6. 검증

1. `npx tsc --noEmit`
2. `npx vitest run` — 신규 테스트
   - **`fetchOverride`(최우선)**: 오버라이드 `null`일 때 전역 `fetch`가 그대로 호출된다(실계좌 무영향 고정)
   - `demoMarket`: 같은 시드 → 같은 가격 시퀀스(결정론)
   - `demoBroker`: 복원한 `simBroker.test.ts`의 체결 규칙 케이스 재사용(지정가 미달 미체결 / 관통 체결 / 기체결 취소 throw)
   - `demoFetch`: 엔드포인트 8종(REST 6 + OAuth 2) 각각 `rt_cd === '0'` + 화면이 읽는 필드 존재 + `tr_cont` 헤더 + **미등록 URL은 throw**
   - `demoStorage`: 접두 격리 + `clearDemoStorage` 후 실계좌 키 무사
   - `syncTradingConfig`: 데모에서 `saveAppSettings`가 **호출되지 않는다**(§3-3a의 구멍 고정)
   - 기존 497개+ 전부 통과 — 데모 코드가 기존 테스트를 하나도 건드리지 않아야 한다
3. 수동 — 데모 진입 후
   - 보유종목·미체결은 비어 있고(빈 계좌), 손익에는 과거 실현손익이 뜨고, 종목상세 차트가 그려진다
   - 트레이딩 탭에서 **2분 안에 감지→진입이 최소 1회** 뜨고, 그리드 게이지가 움직이고, "오늘 거래 기록"에 청산이 쌓인다
   - 기내 모드(네트워크 차단)로도 데모가 정상 동작한다 → 실제 통신이 없다는 실증
4. **핵심 회귀 검사 — 실계좌 무영향** (이 절차를 그대로 수행)
   1. 실계좌로 진입 → 손익 화면 오늘/이번달 값, 설정 탭 매매 파라미터 값을 **적어 둔다**
   2. 앱 재시작 → 데모로 진입 → 자동매매를 5분 이상 돌려 청산이 여러 건 쌓이게 한다
   3. 설정 탭 값이 데모 안에서 바뀌어 보이는지 확인(바뀌어도 무방 — 저장만 안 되면 된다)
   4. "체험 종료"(앱 재시작) → 실계좌로 진입
   5. **손익 오늘/이번달 = 1번과 동일**, **설정 매매 파라미터 = 1번과 동일**, 오늘 거래 기록에 데모 거래 0건
   6. AsyncStorage 덤프에 `demo.` 접두 키 0건
5. 잔재 확인: 실계좌 모드에서 `features/demo/*`가 어떤 부작용도 일으키지 않는지 —
   모듈 최상위에서 타이머·구독을 시작하지 않는다(시뮬레이터는 `enableDemoMode()`에서만 시작)

## 8. 열린 질문 (구현 중 확인 필요)

- **`Updates.reloadAsync()`가 dev 클라이언트에서 동작하는지** — 안 되면 §3-3(c)의 폴백 경로가 주 경로가
  되고, 그 경우 원복 목록(오버라이드·`kisFlowConfig`·매니저 싱글턴·데모 타이머)을 한 함수에 모아
  테스트로 고정한다. 릴리스 빌드에서는 재시작이 정상 동작하므로 최종 안전성에는 영향 없음.
- 데모 감지 빈도 튜닝 — 드리프트 반전 주기(30~90초)와 틱 변동폭은 실기기에서 눈으로 보며 조정한다.
