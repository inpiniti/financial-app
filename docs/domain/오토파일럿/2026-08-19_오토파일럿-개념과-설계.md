# 오토파일럿 (AutoPilot) — 개념과 설계

## 1. 오토파일럿이란
**단타의 중앙 관리자.** 트레이딩 리스트 전 종목에 신호 감지기를 상시 부착하고, 신호가 오면 진입 → 포지션 규칙(그리드) → 실행(매매)으로 넘기며, 상태·자금·동시 종목·오류를 한 곳에서 관리한다. 도메인 규칙 자체는 갖지 않고 **어느 도메인을 언제 부르는가**만 결정한다.

## 2. 상태
### 2-1. AutoPilot 상태(전체)
`IDLE → SCANNING → ENTERING → HOLDING → EXITING → SCANNING …`, 언제든 `PAUSED`(현금 부족·수동) / `FAULT`.
상태는 저장하지 않고 **활성 종목들의 사이클 상태에서 파생**한다: 하나라도 매수 대기·주문 중이면 ENTERING, 매도 중이면 EXITING, 보유면 HOLDING, 아니면 SCANNING.

### 2-2. RunCycle 상태(종목 1개, 1사이클 = 매수→청산→종료)
`IDLE → WATCH_BUY → BUYING → HOLDING → SELLING → DONE`, 오류 시 `FAULT`(스스로 전이하지 않음 — 러너가 브로커 오류를 감지해 fault()).

### 2-3. 청산 사유 (`ExitReason`)
| 사유 | 뜻 |
|---|---|
| `SELL_SIGNAL` | 신호 청산(추세 ma5 꺾임 / 변곡점 SELL) |
| `STOP` | 사용자 Stop |
| `STOP_LOSS` | 추세 손절선(틱 판정, 08-18) |
| `CIRCUIT` | 서킷 하킷 2연속, 정지 중 지정가(08-19, `CIRCUIT_MODE`) |
| `MANUAL` | 앱 밖(한투앱 등) 매도를 잔고 재확인으로 인지(08-19) |

## 2-4. 포지션 관리자 (진입 후 관리, 08-19 구조 개선)
종목 1개의 **보유 → 신호/손절/서킷 판정 → 매매 → 부분체결 반영 → 수동청산 인지 → 정산**을 `PositionManager` 하나가 든다. 오토파일럿은 진입 체결 후 이것을 만들고, 신호(`onSignal`)·매초 틱(`tick`)·주기 폴(`poll`)·해제(`release`)만 넘긴다. 폴의 결과값 `holding | sold(TradeRecord) | isolated(사유)`로 정산·격리만 한다 — 진행 중 매매·청산 사유 같은 내부 상태는 오토파일럿이 보지 않는다. 규칙(추세 청산 `TrendExitRule`+서킷 `CircuitExitRule` / 변곡점 `ConditionalGrid`)은 `PositionRule` 계약으로 주입한다. 정산 기록은 `core/cycle`의 `makeTradeRecord` 하나로 합성한다(사이클·OCO 그리드 정산도 같은 함수).

## 3. 규칙
- **감지기 상시 부착**(08-10): 감시 교체 때 떼면 앵커가 리셋돼 신호가 안 쌓인다. "감시(watched)" 목록은 자격자 중 틱/초 상위 3개로, 예열·UI 우선순위일 뿐.
- **진입 게이트 2회**: 신호 시점·발주 직전에 속도(minTickRate) 게이트. 이미 보유·진입 중 종목은 후보 제외.
- **진입 규모**: 고정 금액(startAmountUsd) 또는 고정 수량(entryQty, 08-18). 그리드가 물타기로 수량을 늘리므로 진입금액을 가변으로 두지 않는다.
- **동시 종목**: `maxConcurrentGrids`(기본 1). 종목마다 RunCycle + OrderPort + Grid를 따로 만든다.
- **현금 부족**: 보유 그리드가 없으면 PAUSED(사람이 재개), 있으면 그 진입만 포기.
- **시세 구독 키는 세션별**(08-10): KST 10~16시(주간거래 창)엔 `R+BAQ/BAY/BAA+티커`, 그 밖엔 `D+NAS/NYS/AMS+티커`로 체결가(HDFSCNT0)를 구독하고 경계에서 회전한다(`rotateSessionKeys`). **주간거래 미지원 종목은 R키가 "mci send failed"로 거절**되므로(08-28 실사고 — 접속키 재발급으로 오진하기 쉬움; 접속키는 앱 시작마다 새로 받는다) 리스트 행에 `feedRejected`로 "주간거래 미지원 · 시세 없음 · RBAQxxx 거절"을 보이고, 실패 진단 문구에도 trKey를 적는다. 틱이 없으니 그 종목은 봉·판정·진입이 생기지 않는다(별도 제외 로직 없음). 16:00 KST 뒤 D키로 회전하면 다시 받는다.
- **안전장치**: 매수 전 프리플라이트, FAULT 인터록(사용자 Stop으로만 해제), 미체결은 무한 대기(자동 취소는 `abandon` 경로만, 부분체결 미확정이면 fail-closed).

## 4. FAULT 범위 (08-08)
**진입 경로**(프리플라이트·인계 실패)만 전역 동결. **관리 중 그리드의 fault는 그 그리드만 격리**(`gridFaulted`) — 한 종목 오류로 나머지 종목 관리와 폴 타이머가 멈추지 않게.

## 5. 모드 스위치 (상수 한 줄 롤백)
진입 후 관리 모드의 **판정은 `positionManager.resolvePositionMode` 한 곳**이다(2026-08-19 구조 개선) — 우선순위 **추세 > 변곡점 조합 > OCO 그리드**, 각각 "스위치 상수 AND 설정 주입(`PositionManagementConfig`의 trend/inflection/grid)". 세 경로는 모두 포지션 관리자 인터페이스의 어댑터(`RulePositionManager`×2 · `OcoGridPositionManager`)라 오토파일럿은 어느 모드인지 모른다. 롤백 = 아래 스위치 한 줄(또는 managerProvider의 주입 한 줄).

| 스위치 | 값 | 켜짐 | 꺼짐 |
|---|---|---|---|
| `TREND_MODE` | true | 추세 신호 + 추세 청산 규칙(+서킷 데코레이터) + 매매 | 변곡점(사다리) 신호 + 조건부 그리드 |
| `INFLECTION_GRID` | true | (추세 꺼짐일 때) 변곡점 조건부 그리드 + 매매 | OCO 매도그리드(core/grid, ADR 0002) |
| `GRID_EXIT` | true | (둘 다 꺼짐일 때) OCO 매도그리드 | 관리자 없음 — RunCycle의 옛 SELL 신호 청산 |
| `CIRCUIT_MODE` | false | 서킷 상태에서 ma5 청산 무시, 정지 중 지정가 매도 | 관측만(이벤트 기록) |
| `LADDER_ENTRY` | true | 변곡점 모드의 진입 감지기 = 사다리 | SG 감지기 |

feedSlot(신호 생성)과 autopilot(포지션 규칙)이 **같은 상수 하나**를 읽어 층 간 불일치 조합을 막는다.
