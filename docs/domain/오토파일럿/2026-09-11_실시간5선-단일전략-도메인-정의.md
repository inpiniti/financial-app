# 실시간5선 단일전략 도메인 정의

> 작성일: 2026-09-11
> 목적: 단일 규칙으로 책임 경계를 고정해 실패 지점을 즉시 식별한다.

## 1. 목적

- 운영 전략은 `realtimeMa5` 하나로 고정한다.
- 규칙은 3개만 고정한다.
  - 신호가격 기준: 체결가 단일 기준
  - 설정 반영 시점: 전 항목 즉시 반영
  - 추가진입 조건: 평단 대비 -3%일 때만 실행
- 다중 전략 선택지로 생기던 "왜 안 샀는지/왜 또 샀는지" 추적 난도를 줄인다.

## 2. 도메인 정의 (7개)

| 도메인 | 책임(Owner) | 입력 | 출력 | 불변식 |
|---|---|---|---|---|
| 실시간5선 | `core/realtime-ma5` | 확정 분봉 종가 배열, 현재 틱 | `ma5`, `slope`, `breakout` | 돌파식은 `prevTick < currentMa5 < currentTick` |
| 돌파감지 | `features/scalper/feedSlot` | 틱/분봉 업데이트, 실시간5선 상태 | `BUY` 신호 컨텍스트 | 신호 발행은 감지 책임만 수행(수량/주문 판단 금지) |
| 진입 | `features/scalper/autopilot` | `BUY` 신호, 설정 스냅샷 | 신규 진입 주문 시작 | 포지션 없을 때만 진입 경로 사용 |
| 추가진입 | `features/scalper/positionManager` | `BUY` 신호, 현재가, 평단/보유수량 | 추가진입 주문 시작 | 평단 대비 -3%일 때만 실행, 조건 아니면 매수 금지 |
| 매수 | `core/execution` + `positionManager` | 주문 지시(side/qty/price) | 체결/취소/장애 결과 | 주문은 실행 계층에서만 추격/정정 |
| 체결 | `positionManager.poll` + `autopilot.settle` | 브로커 체결 결과 | 평단/수량 갱신, 거래기록, 관리 해제 | 매수 체결 시 평단 x 1.03 매도 주문 재등록/정정, 매도 체결 시 관리 중 티커를 즉시 해제 |
| 설정 | `lib/appSettings` + `managerProvider` | 저장값/기본값 | 런타임 설정 스냅샷 | 저장 직후 즉시 반영, 레거시 전략값 유입 금지 |

## 3. 인터페이스 경계

- 신호 계층 -> 포지션 계층
  - `Signal='BUY'`, `price`, `entryEvent`, `at`
- 포지션 계층 -> 실행 계층
  - `{ side: 'buy'|'sell', qty, price, shouldAbort }`
- 실행 계층 -> 포지션 계층
  - `{ kind: 'done'|'cancelled'|'fault', result? }`
- 설정 계층 -> 조율 계층
  - `ManagerSettings` 단일 스냅샷(`trading`, `entryLadder`)

## 4. 데이터 흐름

1. 틱 수신
2. 실시간5선 계산
3. 돌파감지(`BUY`)
4. 오토파일럿이 포지션 유무로 경로 분기
5. 신규진입 또는 추가진입 주문 시작
6. 체결 폴링으로 평단/수량 갱신
7. 평단 x 1.03 매도 주문 선등록/정정
8. 매도 체결 시 active ticker 해제(unpin + 관리맵 제거)

## 5. 장애 시나리오

- 시세 지연: WS 공백 시 기존 보호 로직으로 폴백(REST 가격 조회 경로)
- 미체결: 실행 계층이 추격/취소/장애를 상태로 반환
- 가용자본 부족: 추가진입 수량 계산에서 0으로 캡핑되어 발주 생략
- 중복 신호: 동일 평단에서 추가진입 이벤트는 1회만 처리하고, 체결로 평단이 바뀔 때만 다음 추가진입을 재허용

## 6. 로그 규약 (최소 키)

- 신호: `ticker`, `signal`, `price`, `at`, `entryEvent`
- 주문 시작: `ticker`, `side`, `qty`, `limitPrice`, `at`
- 주문 결과: `ticker`, `side`, `status(done|cancelled|fault)`, `filledQty`, `fillPrice`, `at`
- 포지션 갱신: `ticker`, `prevAvg`, `nextAvg`, `prevQty`, `nextQty`, `at`
- 설정 반영: `startAmountUsd`, `entryQty`, `minTickRate`, `watchCount`, `maxConcurrentGrids`, `at`

## 7. 검증 체크

- 단위: 실시간5선 돌파식, 추가진입 수량/자본 캡
- 통합: `feedSlot -> autopilot -> positionManager`에서 진입/추가진입/체결 순서
- 운영: 같은 평단에서 추가진입 1회만 발생하는지, 저장 직후 설정이 다음 사이클부터 반영되는지
