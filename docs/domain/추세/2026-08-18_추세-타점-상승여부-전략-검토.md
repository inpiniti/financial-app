> 배경: 변곡점(SG 기울기 부호 전환, `docs/domain/변곡점/`)으로 타점을 잡는 시도가 크게 이득을 내지 못하고 있어, **분봉 이동평균 4선만으로 타점을 잡는 전략**을 실제 급등주 1분봉 차트 3장으로 손 시뮬레이션한 기록. 결론은 **이평선 단독으로 간다** — 변곡점과의 조합은 하지 않는다(§7).

## 1. 검토한 전략

```
진입: 분봉5선·20선·60선·120선의 기울기가 모두 + (직전 봉 대비 상승)
청산: 분봉5선의 기울기가 − 로 꺾이는 즉시
```

⚠ **정배열(5>20>60>120 레벨 순서)이 아니다.** 각 선의 **방향(기울기 부호)만** 본다.

## 3. 왜 조건이 급등 초입에 켜지는가 — 이동평균 "방향"의 성질

처음엔 "120선은 2시간 평균이라 늦게 반응 → 고점 근처에서 진입"이라 판단했으나 **WFF 재검토에서 철회**했다.

- SMA가 길수록 늦는 것은 **레벨**(값)이 가격을 따라가는 속도다.
- **방향 전환**은 다르다. 직전 구간이 오래 평평했다면 120봉 평균이 그 값에 붙어 있으므로, 첫 급등봉 하나에도 평균은 **즉시 상승 전환**한다(기울기가 완만할 뿐).
- 따라서 "오래 횡보하다 튀는" 급등주(WFF·XOS)에서는 4선 상승이 **급등 초입에 동시에 켜진다.** 이 앱의 목적(급등 편승)에 맞는 이유.
- 이미 흔들리며 오르내리던 종목(WETO 1차 파동)은 60·120선 방향이 늦게 잡혀 진입이 늦다.

## 4. 약점 — 너무 쉽게 켜지는 쪽

1. **급등봉 하나짜리**: 평평하다 봉 하나 튀면 4선이 다 +. 다음 봉이 되돌리면 5선이 바로 꺾여 소폭 손실 청산. 이번 3장엔 없지만 급등주 스캔에 걸리는 종목 다수가 이 유형 → **손실 횟수의 주범** 예상.
2. **휩쏘**: 급등 도중 조정(WFF 6→5, WETO 17 횡보)에서 5선이 잠깐 꺾여 나가고 다시 4선 +면 재진입 — 조정 저점에서 팔고 반등 후 다시 사는 손실.
3. **120선 부호는 사실상 항상 +**: 한 번 급등하면 두 시간 동안 120선은 계속 오른다(WFF는 폭락 중에도 120선이 5.3까지 상승). 즉 **하락 국면의 반등에서 5·20·60이 잠깐 +면 진입**된다. 실질 필터는 5·20·60뿐, 120선 기울기는 "고점 후 급락"을 못 거른다.

## 5. 보완안

| # | 보완 | 막는 약점 | 대가 | 판단 |
|---|---|---|---|---|
| A | **위치 조건 1개**: 현재가 > 분봉60선 | 4-3 (하락 중 반등 진입) | 정배열이 아니라 위치 하나만 — 진입 지연 거의 없음 | **채택 후보** |
| B | **진입 2봉 연속 +, 청산 1봉 꺾임** (비대칭) | 4-1, 4-2 일부 | 진입 1분 지연. 청산은 민감하게 유지(청산 위험 최소화 원칙) | **채택 후보** |
| C | 진입 시 120선 이격 상한(현재가/분봉120선 − 1 ≤ N%) | 끝물 추격 | 오래 횡보 후 급등하는 종목은 초입에도 이격이 커서 **오히려 진입을 막음** | 보류 |
| D | 최소 기울기 크기 문턱(%/봉) | 4-1 잔진동 | 캘리브레이션 필요, 진입 지연 | 보류 |

현재 선호: **A + B**. 잠정 규칙:

```
진입:  분봉5·20·60·120선 기울기 모두 +  가 2봉 연속  AND  현재가 > 분봉60선
청산:  분봉5선 기울기 −  (1봉, 즉시)
판정 불가: 4선 중 null(봉 부족·데이터 유실)이면 신호 없음 — **fail-closed**. 추세는 게이트가 아니라 트리거이므로 기존 게이트의 fail-open(null이면 통과)과 반대다(구현 시 정정)
```

## 6. 데이터 — 1분봉을 어떻게 만들 것인가 (설계 시 결정)

`kis/minuteChart.ts`는 REST 스냅샷(최근 120봉)이다. 실시간 판정에는 두 방법이 있다:

1. **REST 매 분 폴링** — 구현 단순, 그러나 종목 수 × 분당 1회 호출·지연 수 초·배터리 부담(상승 감지 v3 문서의 1급 제약).
2. **WS 체결가로 1분봉 로컬 합성** — 체결가 → 1분 버킷 종가 → `computeTrend`. 호출 0, 지연 0. 워밍업(120봉=2시간)은 감시 시작 시 REST 1회로 채우고 이후 WS로 이어 붙인다.

**2안이 자연스럽다.** 워밍업 REST + WS 이어붙이기의 봉 경계 정합(같은 분이 두 번 들어가지 않게)이 구현의 핵심 주의점.

## 7. 변곡점과 조합하지 않는 이유 (검토만 함)

변곡점(초 단위)은 "지금 꺾였나", 추세(분 단위)는 "어느 국면인가"를 보므로 보완 관계로 보이지만, 조합은 하지 않는다:

- 추세 필터가 켜진 국면(급등 초입, 4선 +)에서는 변곡점 BUY도 거의 계속 나온다 → **조합 결과 ≈ 이평선 단독.** 정밀도가 더해지는 건 청산 급락 예외 정도인데, 5선 꺾임만으로 3/3 급락을 피했다.
- 청크(1~3초)와 봉(1분) 주기가 다른 두 상태기계를 붙이면 테스트가 곱으로 늘고, 결과가 나빴을 때 원인 분리가 안 된다. 사다리→변곡점 조합→롤백을 반복한 이력상 **변수 하나짜리 규칙을 먼저 검증**한다.
- 이평선 단독의 약점(4-1·4-2)은 §5 A·B로 이평선 안에서 고친다.
- 변곡점 코드는 삭제하지 않고 기존 관례대로 **한 줄 스위치**로 남긴다. 이평선 단독이 실제로 안 벌리면 그때 "변곡점을 청산 보조로만" 붙이는 걸 재검토.
