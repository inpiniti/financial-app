> 작성일 2026-08-14 · 분류: **도메인 문서** · 상태: **구현됨** (`features/scalper/slopeRate.ts`, 같은 날)

> 관련 문서: `docs/domain/변곡점/2026-08-14_변곡점-개요와-구현.md`, 표시 plan: `2026-08-14_기울기-초-표시-plan.md`

## 1. 기울기/초란

**최근 윈도우 동안 가격이 초당 몇 % 움직였는지**를 나타내는 순간 지표. 물리적으로 존재하는 값이 아니라 이 앱이 정의하는 **가격변동율 지표**다.

- `-0.4 기울기/초` = 1초에 0.4%씩 빠지고 있다.
- `3 기울기/초` = 1초에 3%씩 오르고 있다.
- `0 기울기/초` = 횡보.

틱/초와 짝을 이루는 개념이다:

| | 틱/초 | 기울기/초 |
|---|---|---|
| 답하는 질문 | **얼마나 활발한가** (체결 빈도) | **어느 방향으로 얼마나 빠르게 가는가** (방향+속도) |
| 단위 | 건/초 | %/초 (부호 있음) |
| 성격 | 항상 ≥ 0 | 음수=하락, 양수=상승 |
| 구현 | `TickRateMeter` (10초 윈도우 순간값) | `SlopeMeter` (`features/scalper/slopeRate.ts`) |

두 지표는 직교한다 — 틱/초가 높아도 횡보(기울기/초 ≈ 0)일 수 있고, 틱이 드물어도 급락(기울기/초 큰 음수)일 수 있다. 둘을 함께 보면 "활발하게 오르는 종목"(틱/초 높음 + 기울기/초 양수)을 구분할 수 있다.

## 2. ⚠ 용어 구분 — "기울기" 단독 사용 금지

이 앱에는 이미 "기울기"라는 말이 있다. 변곡점 감지기(SG)의 **1차 미분**으로, 단위가 **%/청크**(청크=3초 리샘플)다. 이번에 정의하는 지표와 이름이 겹치므로:

- **"기울기/초"** — 항상 단위를 붙여 부른다. 이 문서의 지표. 원시 틱 기반, %/초, 사용자에게 보여주는 값.
- **"기울기"(단독)** — SG 감지기 내부의 평활 미분(%/청크). 변곡점 판정 전용, 밖으로 노출하지 않는다.

두 값은 수치도 다르다(3초 청크 기준 %/청크 ≈ %/초 × 3). 문서·코드 주석·UI 어디서든 혼용하지 말 것.

## 3. 정의 (정본)

```
윈도우 W(기본 10초, 틱/초와 동일) 안의 원시 틱 중
  p_first = 가장 오래된 틱 가격, t_first = 그 시각
  p_last  = 가장 최근 틱 가격,  t_last  = 그 시각

기울기/초 = ((p_last − p_first) / p_first × 100) ÷ ((t_last − t_first) / 1000)
```

- **분모는 윈도우 크기가 아니라 실제 경과시간**(t_last − t_first)이다. 틱이 3초치만 있어도 "그 3초 동안 초당 몇 %였나"를 정직하게 답한다. (틱/초가 고정 W로 나누는 것과 다른 점 — 틱/초는 "빈도"라 빈 시간도 0건으로 의미가 있지만, 기울기/초에서 틱 없는 시간은 정보가 없다.)
- **최소 스팬 가드**: t_last − t_first < `minSpanMs`(기본 1,000ms)면 **판정 불가(null)**. 한두 틱 사이의 순간 점프를 초당 환산하면 값이 폭주한다(0.1초에 0.3% 움직임 → 3%/초로 과장).
- **판정 불가(null) ≠ 0**: 틱이 끊겨 윈도우 안에 유효 스팬이 없으면 null(모름)이다. 0은 "가격이 안 움직였다"는 적극적 판정이므로 절대 혼용하지 않는다. 틱/초는 끊기면 0으로 수렴하지만 기울기/초는 null로 간다 — 이 비대칭이 의도다.
- **양끝점 방식의 한계 수용**: 윈도우 안에서 V자로 출렁여도 양끝이 같으면 0이다. 이 지표는 "순간 추세 속도"지 변동성 지표가 아니다. 출렁임은 틱/초와 변곡점 감지기 몫.

## 4. 구현 — `SlopeMeter` (2026-08-14 구현 완료)

`TickRateMeter`와 같은 계약의 순수 클래스 (`features/scalper/slopeRate.ts`):

- 순수 TS, 외부 의존 0. 시각은 전부 인자로 받는다(clock 주입 없음 — 호출부가 `clock.now()`를 넘긴다).
- 내부는 `(tsMs, price)` 오름차순 큐 + head 인덱스 프루닝(틱 폭주 시 O(1)) — `TickRateMeter`의 구조를 그대로 따른다.
- `record(atMs, price)` / `rate(nowMs): number | null` / `series(nowMs): (number|null)[]` / `reset()`.
- 시계열(표시 plan): 원시 이력을 `windowMs + historyMs(기본 4초)`만큼 보존해, `series()`가 "4초전~현재" 5칸을 타이머 없이 조회 시점에 되계산한다(배터리 제약 — `TickRateMeter`도 동일 개조).
- `rate()` 호출 시점 프루닝으로 값이 자연 갱신된다(별도 타이머 없음).
- 배선은 `FeedSlot.pushTick()` — 틱/초 미터 옆에 나란히 상시 기록하고, `FeedSlotView`에 `slopeRate: number | null`로 노출한다. 판정(detector)과 무관한 표시·선정용 지표이므로 attach/detach와 무관하게 항상 돈다.
- 반드시 과거 틱 재생 단위 테스트를 붙인다(급등·급락·횡보·틱 끊김·스팬 미달 null·역행 틱).

## 5. 파라미터

| 항목 | 기본값 | 근거 |
|---|---|---|
| 윈도우 W | **15초** (`feedSlot.FEED_RATE_WINDOW_MS`, 속도와 공유) | 표기 단위 "/15초"와 시야 일치 — 표기값이 환산이 아니라 실제 "지난 15초" 관찰값이 되게. 미터 클래스 기본값(10초)은 순수 로직·테스트 보존용으로 유지, 배선에서 덮어쓴다 |
| 최소 스팬 | 1초 (`minSpanMs`) | 초당 환산 폭주 방지, 이보다 짧으면 null |
| 표기 단위 | **%/15초** (정본 %/초 × 15, 라벨 "기울기/15초") | %/초는 소수 1자리에서 거의 다 0.0으로 뭉개짐 → 5초 → 15초로 확정(2026-08-14 관찰 피드백, 분당 ×60은 너무 길다). 속도도 같은 규칙(틱/15초, 정수) |
| 표기 | 소수 1자리, 부호 필수 (`+0.3`, `-0.4`, `0.0`) | 부호가 정보의 절반 |
| null 표기 | `—` (0으로 표기 금지) | §3 — 모름과 횡보의 구분 |

## 6. 활용

1. **UI 표시** ✅ (2026-08-14) — 트레이딩 리스트(AutoPilotScreen)의 행에 속도·기울기/초 각각 "4초전~현재" 5칸 시계열로 표시. 상세: `2026-08-14_기울기-초-표시-plan.md`.
2. **감시 종목 선정 보조** (후보) — 현재 감시 3종 선정은 틱/초 기준. "활발 + 상승 중"(틱/초 상위 ∧ 기울기/초 > 0) 조합 필터 후보.
3. **급락 방어 참고 신호** (후보) — 큰 음수 기울기/초를 그리드 매수 지연 등의 참고 입력으로. 단, 매매 판정에 넣을 땐 변곡점 감지기의 fail-open 원칙(입력 null이면 통과)을 따를 것.

2·3은 미결정. 진입 빈도보다 청산 위험 최소화 원칙에 따라, 매매 로직 투입은 표시·선정 용도로 충분히 관찰한 뒤 판단한다.
