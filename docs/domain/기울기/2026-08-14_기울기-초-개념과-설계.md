# 기울기 (Slope) — 개념·정의·구현 지침

> 작성일 2026-08-14 · 분류: **도메인 문서** · 상태: **구현됨 v2** (`features/scalper/slopeRate.ts`, 같은 날)
> 짝 개념: 틱/초 (`features/scalper/tickRate.ts`, `TickRateMeter`)
> 관련 문서: `docs/domain/변곡점/2026-08-14_변곡점-개요와-구현.md`, 표시 plan: `2026-08-14_기울기-초-표시-plan.md`

## 1. 기울기란

**직전 봉(10초) 평균가 대비 현재 봉 평균가가 몇 % 움직였는지**를 나타내는 지표. 물리적으로 존재하는 값이 아니라 이 앱이 정의하는 **가격변동율 지표**다. UI 라벨은 "기울기/10초".

- `-0.4` = 직전 10초 평균보다 이번 10초 평균이 0.4% 낮다 (하락 중).
- `+3.0` = 직전 10초 평균보다 3% 높다 (급등 중).
- `0.0` = 두 봉 평균이 같다 (횡보).

틱/초와 짝을 이루는 개념이다:

| | 속도 (틱/초) | 기울기 |
|---|---|---|
| 답하는 질문 | **얼마나 활발한가** (체결 빈도) | **어느 방향으로 얼마나 빠르게 가는가** (방향+속도) |
| 단위 | 건/초 (표기는 틱/10초) | 직전 봉 대비 % (부호 있음) |
| 성격 | 항상 ≥ 0 | 음수=하락, 양수=상승 |
| 구현 | `TickRateMeter` | `SlopeMeter` (`features/scalper/slopeRate.ts`) |

두 지표는 직교한다 — 속도가 높아도 횡보(기울기 ≈ 0)일 수 있고, 틱이 드물어도 급락(기울기 큰 음수)일 수 있다. 둘을 함께 보면 "활발하게 오르는 종목"(속도 높음 + 기울기 양수)을 구분할 수 있다.

## 2. ⚠ 용어 구분 — "기울기" 단독 사용 금지 (코드·SG 문맥)

이 앱에는 이미 "기울기"라는 말이 있다. 변곡점 감지기(SG)의 **1차 미분**으로, 단위가 **%/청크**(청크=3초 리샘플)다. 이번에 정의하는 지표와 이름이 겹치므로:

- **"기울기/10초"** — 항상 단위를 붙여 부른다. 이 문서의 지표. 원시 틱 기반 봉 평균 비교, 사용자에게 보여주는 값. 코드 식별자는 `slopeRate`.
- **"기울기"(단독)** — SG 감지기 내부의 평활 미분(%/청크). 변곡점 판정 전용, 밖으로 노출하지 않는다. 코드 식별자는 `slope`.

## 3. 정의 (정본, v2 — 봉 평균 비교)

```
봉 크기 W = 10초 (틱/초와 동일, 시계열 칸 간격과도 동일)
  현재 봉 = (t−W, t]     의 틱 평균가 avg_cur
  직전 봉 = (t−2W, t−W]  의 틱 평균가 avg_prev

기울기 = (avg_cur − avg_prev) ÷ avg_prev × 100
```

- **평균끼리 비교한다** — 봉 안에서 틱이 출렁여도 평균에서 상쇄된다. 관찰용 지표에 필요한 건 봉 단위의 추세이지 순간 틱이 아니다.
- **판정 불가(null) ≠ 0**: 두 봉 중 하나라도 틱이 없으면 null(모름)이다. 0은 "두 봉 평균이 같다"는 적극적 판정이므로 절대 혼용하지 않는다. 속도는 끊기면 0으로 수렴하지만 기울기는 null로 간다 — 이 비대칭이 의도다.
- **v1 (폐기, 같은 날)**: 처음엔 윈도우 양끝 틱으로 `%변화 ÷ 실경과초`(%/초)를 쓰고 최소 스팬 1초 가드를 뒀다. 양끝점은 봉 끝 틱 하나에 값이 휘둘려 평균 비교로 교체 — 초당 환산도 소수 1자리에서 0.0으로 뭉개져 표기 단위 유랑(초→분안→5초→15초)의 원인이었다. 봉 평균 대비 %는 값 자체가 사람 눈금이라 환산이 없다.

## 4. 구현 — `SlopeMeter` (2026-08-14 v2)

`TickRateMeter`와 같은 계약의 순수 클래스 (`features/scalper/slopeRate.ts`):

- 순수 TS, 외부 의존 0. 시각은 전부 인자로 받는다(clock 주입 없음 — 호출부가 `clock.now()`를 넘긴다).
- 내부는 `(tsMs, price)` 오름차순 큐 + head 인덱스 프루닝(틱 폭주 시 O(1)) — `TickRateMeter`의 구조를 그대로 따른다. 보존 = `2W + historyMs`(가장 먼 칸의 직전 봉까지).
- `record(atMs, price)` / `rate(nowMs): number | null` / `series(nowMs, points=5, stepMs=W)` / `reset()`.
- 시계열: 타이머 없이 조회 시점 되계산(배터리 제약). 간격 기본값 = 봉 크기라 칸이 겹치지 않는다.
- 배선은 `FeedSlot.pushTick()` — 속도 미터 옆에 나란히 상시 기록하고, `FeedSlotView`에 `slopeRate`·`slopeRateSeries`로 노출한다. 판정(detector)과 무관한 표시·선정용 지표이므로 attach/detach와 무관하게 항상 돈다.
- 반드시 과거 틱 재생 단위 테스트를 붙인다(상승·하락·봉 내 출렁임 상쇄·봉 비면 null·역행 틱·시계열 재현성).

## 5. 파라미터

| 항목 | 기본값 | 근거 |
|---|---|---|
| 봉 크기 W | **10초** (`feedSlot.FEED_RATE_WINDOW_MS`, 속도와 공유) | 5초는 짧다는 관찰(2026-08-14). 시계열 간격과 동일 → 5칸이 겹침 없는 독립 봉 |
| 시계열 | 10초 간격 × 5칸 = 최근 50초, 겹침 0 (`FEED_SERIES_STEP_MS`/`POINTS`) | 처음의 1초 간격(15초 윈도우)은 이웃 칸이 14초를 공유해 5칸이 죄다 비슷했다. 윈도우=간격이어야 각 칸이 서로 다른 구간을 본다. 이력 보존 = (칸수−1)×간격 = 40초 |
| 표기 | 값 그대로(환산 없음), 소수 1자리, 부호 필수 (`+0.3`, `-0.4`, `0.0`) | v2 값 자체가 "직전 봉 대비 %"라 사람 눈금. 부호가 정보의 절반 |
| 속도 표기 | 틱/10초 (틱/초 × 10, 정수) | 봉과 같은 시야 — 각 칸 = 그 10초 봉의 실제 틱 수 |
| null 표기 | `—` (0으로 표기 금지) | §3 — 모름과 횡보의 구분 |

## 6. 활용

1. **UI 표시** ✅ (2026-08-14) — 트레이딩 리스트(AutoPilotScreen)의 행에 속도·기울기 각각 10초 봉 5칸(최근 50초) 시계열로 표시. 상세: `2026-08-14_기울기-초-표시-plan.md`.
2. **감시 종목 선정 보조** (후보) — 현재 감시 3종 선정은 틱/초 기준. "활발 + 상승 중"(속도 상위 ∧ 기울기 > 0) 조합 필터 후보.
3. **급락 방어 참고 신호** (후보) — 큰 음수 기울기를 그리드 매수 지연 등의 참고 입력으로. 단, 매매 판정에 넣을 땐 변곡점 감지기의 fail-open 원칙(입력 null이면 통과)을 따를 것.

2·3은 미결정. 진입 빈도보다 청산 위험 최소화 원칙에 따라, 매매 로직 투입은 표시·선정 용도로 충분히 관찰한 뒤 판단한다.
