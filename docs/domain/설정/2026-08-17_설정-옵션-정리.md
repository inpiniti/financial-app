# 설정 (Settings) — 옵션별 의미와 반영 경로

> 작성일 2026-08-17 · 갱신 2026-08-18(수량 옵션) · 2026-08-31(가격 하한 — 데스크탑에서 이식) · 분류: **도메인 문서** (변곡점+그리드 조합 반영판)
> 코드: `lib/appSettings.ts`(정의·저장), `app/settings.tsx`(설정 화면), `features/scalper/ui/managerProvider.tsx`(엔진 반영), `lib/kisSettings.ts`(KIS 키 — 별도)

## 1. 구조 — 저장은 하나, 반영은 매니저가

- **저장소**: 매매 파라미터는 전부 `lib/appSettings`(AsyncStorage, `app:settings` 키) 하나에 저장된다. KIS 앱키·계좌는 민감정보라 `lib/kisSettings`(secure-store)로 분리돼 있고 이 문서 범위 밖이다.
- **반영 경로(2026-08-19 단일화)**: 설정 화면은 저장만 한다. `managerProvider.managerSettingsFrom(appSettings)`가 단위 변환(%→소수, 초→ms)을 모아 **스냅샷 하나**로 만들고, `AutoPilotManager.applySettings(스냅샷)` → `AutoPilot.applySettings` 한 번에 내려간다. 시점은 셋 — ① 부팅(`buildManager`), ② 트레이딩 화면 포커스마다(`refreshLiveSettings`), ③ "자동 트레이딩 시작하기" 직전. 매니저가 모듈 스코프 싱글턴이라 이 경로가 없으면 앱을 껐다 켜기 전까지 옛값으로 돈다(과거 실사고). 항목별 setter(setGridConfig 등)·오토파일럿 쪽 설정 영속(옛 v3 `config`)·역동기화(syncTradingConfig)는 없앴다 — **정본은 appSettings 하나**, 오토파일럿 영속(v4)에는 일시정지·일별 누계 같은 상태만 남는다(옛 v3의 config는 부팅 폴백으로만 읽고 정본이 덮어쓴다).
- **적용 시점 게이트**: 진입금액·수량·최소 속도·동시 그리드 수(스냅샷의 `config`)는 **정지(IDLE) 상태에서만** 반영된다(`applySettings`가 거절 사유를 돌려준다). 그리드 폭·매수취소·사다리 감지는 매매 중에도 즉시 반영된다. 매매 중 저장된 진입 설정은 정지 후 다음 포커스·시작 직전에 반영된다.

## 2. 화면에 있는 옵션 (조합 모드에서 실제로 쓰이는 것)

### 2-1. 트레이딩 설정

| 옵션 | 키 | 기본 | 의미 |
|---|---|---|---|
| 진입금액 (USD) | `startAmountUsd` | 1 | 종목 하나에 처음 들어가는 금액. 진입 수량 = floor(금액 ÷ 현재가). **이 수량이 곧 물타기 고정 수량이 된다**(조합의 "최초 진입 수량"). 0이면 미설정 — 시작이 거부된다. 리스트 필터에도 쓰인다(이 금액보다 비싼 종목은 1주도 못 사니 리스트에서 제외). 상한 $100,000(오타 방어) |
| 수량 (주) | `entryQty` | 0(미설정) | **2026-08-18 추가.** 지정(≥1 정수)하면 진입 수량을 금액 계산 대신 **이 수량으로 고정**한다 — $0.001짜리도 $100짜리도 똑같이 이 수량만 산다. 물타기 고정 수량도 이 값(=최초 진입 수량). 리스트의 "진입금액 이하" 가격 필터는 **유지**된다 — 수량 모드에서 진입금액은 "이 가격 이하 종목만"이라는 상한 역할(사용자 확정: 테스트 중이라 $100짜리는 위험, "$10 이하 중에서 1주씩"이 의도). 빈 칸/0이면 옛 그대로 floor(진입금액 ÷ 현재가). 진입금액은 항상 필수(> 0). 반영 경로·IDLE 게이트는 진입금액과 동일(`pilot.setConfig`). 판정 단일 출처 `autopilot.fixedEntryQtyOf` |
| 가격 상한 (USD) | `maxPriceUsd` | 200 | **2026-08-20 추가**(풀데이 시뮬 — 진입금액 겸용 상한이 MRNA류 유동성 급등주를 배제). **수량 모드(entryQty ≥ 1)일 때만** "이 가격 이하 종목만 감시"의 상한으로 쓴다. 0/빈 칸이면 옛 동작(진입금액이 상한). 금액 모드에서는 무시(진입금액이 상한 — 1주도 못 사는 종목 배제). 상한 $100,000. 소비처 `autopilotManager`의 watchlist `maxPriceUsd` 게터 |
| 가격 하한 (USD) | `minPriceUsd` | 0(없음) | **2026-08-31 추가**(데스크탑 2026-08-29 개선 이식). 이보다 싼 종목은 감시하지 않는다 — 초저가 동전주 편중 방어. **금액·수량 모드 모두** 적용, 걸러진 자리는 차순위가 채운다. 0/빈 칸이면 필터 없음. 판정은 상한과 같은 관대 판정(현재가 파싱 실패 시 통과, `watchlist.isAbovePriceFloor`). 소비처 `autopilotManager`의 watchlist `minPriceUsd` 게터 |
| 동시 그리드 수 | `maxConcurrentGrids` | 1 | 한 번에 관리(보유+진입 중)할 종목 개수. 상한 6(`MAX_GRIDS_LIMIT` — WS 구독 예산·현금 분할 한계). 첫 진입 노출 = 진입금액 × 이 값 |
| 최소 속도 (틱/초) | `minTickRate` | 1 | 이보다 조용한 종목은 감시·진입하지 않는다. 신호 시점과 발주 직전 두 번 검사한다. 0 설정 불가(> 0 강제). ⚠ 유동성 하한으로만 쓸 것 — 10~20처럼 올리면 수직 급등의 클라이맥스에서만 신호가 통과해 "꼭대기 선택기"가 된다(2026-08-20 분석, 권장 1~3). 추세 진입은 이와 별개로 **감시(틱속도 상위 3종) 요건 + 챱 차단(밴드폭 1.5%) + 추격 게이트(+1%)**를 거친다 |

## 3. 화면에 없는 고정값 (설정이 아니라 설계 결정)

변곡점+그리드 조합(2026-08-15 도메인 문서)의 파라미터는 **의도적으로 설정에서 뺐다** — 테스트 중인 설계의 핵심 수치를 화면에서 흔들 수 있게 두지 않는다. 설정 화면의 "변곡점 그리드 (고정값)" 패널이 읽기 전용으로 보여준다.

| 항목 | 값 | 단일 출처 |
|---|---|---|
| 매도 수익 문턱 | 평단 +2% | `autopilot.INFLECTION_THRESHOLDS.sellProfitPct` |
| 물타기 낙폭 문턱 | 평단 −3% | `autopilot.INFLECTION_THRESHOLDS.buyDropPct` |
| 변곡점 청크 | 1초 | `feedSlot.INFLECTION_CHUNK_SECONDS` |
| SG 버퍼 | 21 | `feedSlot.INFLECTION_BUFFER_SIZE` |
| 물타기 수량 | 최초 진입 수량 고정(배수 아님) — 설정 `entryQty`를 지정했으면 그 수량 | `core/conditional`(entryQty) |
| 매매 재정정 스로틀 | 1초 | `core/execution`(minReorderIntervalMs 기본값) |

값을 바꾸려면 코드를 바꾸고 도메인 문서를 갱신한다 — 설정 항목으로 승격하려면 그때 논의.

## 4. 저장은 되지만 화면에서 내린 옵션 (롤백 전용)

조합 모드에서 미사용이라 2026-08-17에 설정 화면에서 내렸다. **저장 키는 살아 있고 저장 시 기존 값을 그대로 되쓴다** — 롤백 스위치(`feedSlot.INFLECTION_ENTRY`·`autopilot.INFLECTION_GRID`를 false)로 옛 경로(사다리 진입 + OCO 그리드)에 돌아가면 이 값들이 다시 쓰인다.

| 키 | 기본 | 옛 의미(롤백 시) |
|---|---|---|
| `gridBuyWidthPct` | 5 | OCO 그리드 매수폭 — 평단 −이 %에 물타기 지정가 |
| `gridSellWidthPct` | 2 | OCO 그리드 매도폭 — 평단 +이 %에 익절 지정가 |
| `gridBuyMultiplier` | 1 | OCO 물타기 수량 = 보유수량 × 배율(1이면 2배 증량) |
| `entryLadderIntervalPct` | 3 | 사다리 진입 간격 — 고점에서 이 %씩 내려올 때마다 홀 1칸 |
| `entryLadderCount` | 4 | 사다리 홀 횟수 — 이 횟수째에 진입 |
| `orderQty` | 1 | 옛 수동 카드 주문 수량(2026-08-08 수동 카드 제거 후 스키마 호환용) |
| `environment` | live 강제 | KIS 모의투자는 시세 WS·순위 미지원이라 'live'로 강제(로드 시 덮어씀) |

⚠ 원칙(메모리 "설정 제거 전 실제값 확인"): 화면에서 내리는 것과 **키를 삭제해 고정값으로 굳히는 것**은 다르다. 키 삭제는 사용자의 실사용 값 확인 없이는 하지 않는다.

## 5. 이미 제거된 옛 설정 (2026-08-08)

청크 초·버퍼 크기·매수/매도 모멘텀 문턱·BUY 게이트(거래량 스파이크·체결강도)·수수료율. 코드 기본값이 옛 설정 기본값과 동일해 동작 무변경으로 제거됐고, 저장소에 남은 옛 키는 로드 시 버려진다. (조합 모드의 청크 1초·버퍼 21은 이것과 별개로 §3의 고정값이 강제한다.)

## 6. 재구현·수정 시 지켜야 할 것

1. **저장 스키마는 명시 키 복사** — `loadAppSettings`가 키를 하나씩 골라 담는다(제거된 옛 키를 확실히 버리기 위해). 키 추가 시 load·save·기본값 세 곳을 함께 고친다.
2. **새 설정은 두 곳만** — 설정 화면(`app/settings.tsx` + `lib/appSettings.ts` 키·기본값·load)과 소비처(`managerSettingsFrom` 변환 + 그 값을 쓰는 모듈)다. 스냅샷 하나가 부팅·포커스·시작 직전 세 시점에 내려가므로 시점별 반영 코드를 따로 쓰지 않는다. 저장만 하면 재부팅 전까지 안 먹는다는 옛 함정은 이 경로로 막혀 있다.
3. **화면에서 내린 값은 저장 시 보존** — `app/settings.tsx`가 로드값을 ref에 들고 있다가 그대로 되쓴다. 새 입력란을 내릴 때 이 패턴을 따르지 않으면 저장 한 번에 기존 값이 기본값으로 덮인다.
4. **고정값은 단일 출처에서 읽는다** — 설정 화면 안내문이 §3의 상수를 import해 표시한다. 문구에 숫자를 하드코딩하면 코드와 어긋난다.
