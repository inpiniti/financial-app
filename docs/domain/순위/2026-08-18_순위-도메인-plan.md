# 순위 (Ranking) — 트레이딩 리스트 원천 선택 (plan)

> 작성일 2026-08-18 · 분류: **도메인 문서** (같은 날 구현 완료)
> 선행: `docs/domain/설정/2026-08-17_설정-옵션-정리.md`(설정 반영 경로), `features/scalper/watchlist.ts` 헤더(리스트 규칙 이력)
> 코드: `core/ranking/index.ts`(카탈로그·선택·계획, 순수 TS) · `features/scalper/rankingSnapshot.ts`(계획 → 스냅샷 조립) · `features/scalper/watchlist.ts`(스냅샷 → 리스트) · `features/scalper/ui/managerProvider.tsx`(토스·한투 조회 배선, 설정 반영) · `features/scalper/ui/RankingSelectionPanel.tsx` + `app/settings.tsx`(설정 화면 "순위" 패널) · `lib/tossRanking.ts`(기간·다건 조회) · `features/inquiry/Ranking.tsx`(홈 순위 화면 토글)

## 1. 왜

트레이딩 리스트(감시 후보 최대 30종목)는 2026-08-14부터 **토스 거래대금·거래량 실시간 순위, 관리종목 제외, 각 15개**로 코드에 고정돼 있었다. 어느 순위에서 몇 개를 뽑을지는 전략의 일부라 사용자가 조절할 수 있어야 하고(요청 2026-08-18), 홈 순위 화면에서도 토스 순위의 기간(실시간/1일)과 위험종목 포함 여부를 껐다 켤 수 있어야 한다.

## 2. 용어 (정본)

| 용어 | 정의 |
|---|---|
| **원천(Source)** | 순위 하나. 토스는 `종류(거래대금·거래량) × 기간(실시간·1일) × 위험(포함·미포함)` 조합이 곧 원천 하나(8개). 한투는 종류 하나가 원천 하나(7개)이고 기간창은 원천의 옵션. id 예: `toss:amount:realtime:norisk`, `kis:tradeVolume`. |
| **위험포함 / 위험미포함** | 토스 순위의 관리종목(투자위험·경고 지정 계열) 필터 여부. 미포함 = `KRX_MANAGEMENT_STOCK` 필터를 실어 제외. 시총·$1 필터는 넣지 않는다(2026-08-14 결정 유지). |
| **선택(Selection)** | 원천별 `{enabled, count, window?}`. `lib/appSettings.rankingSelection`에 저장. |
| **계획(Plan)** | 선택에서 켜져 있고 count>0인 원천만 **카탈로그 순서**로 나열한 것. 순서 = 우선권(앞 원천이 겹치는 티커를 가져가고 뒤 원천은 차순위로 충원). |
| **총 상한** | 켜진 원천 count 합 ≤ **30** (`RANKING_TOTAL_MAX` = `WATCHLIST_MAX_SIZE`). 근거: KIS WS 구독 예산 41건(체결가 30 + 호가 + 상세화면). |

## 3. 규칙

1. **카탈로그 순서가 우선권** — 토스 8개(거래대금 → 거래량, 실시간 → 1일, 위험미포함 → 위험포함) 다음 한투 7개(거래량 → 거래증가율 → 거래회전율 → 거래량급증 → 가격급등 → 매수체결강도 → 상승율). 사용자가 순서를 바꾸는 UI는 두지 않았다(필요해지면 선택에 order를 더한다).
2. **기본 선택 = 옛 고정 구성** — 토스 거래대금 실시간 위험미포함 15 + 토스 거래량 실시간 위험미포함 15. 설정을 건드리지 않으면 동작이 이전과 같다.
3. **저장 검증** — 켜진 count 합이 0이면 거부(리스트가 통째로 빔), 30 초과면 거부. 계획 단계는 최후 방어선으로 뒤 원천부터 잘라 30을 지킨다.
4. **한투 기간창** — 일 단위 종류(거래량·거래증가율·거래회전율·상승율)는 `NDAY` 0~9(기본 당일), 분 단위 종류(거래량급증·가격급등·매수체결강도)는 `MINX`/분 단위 `NDAY` 0~9(기본 5분전 — 폴링 3분보다 살짝 넓게). 방향(GUBN)은 급등·상승율 고정 — 리스트가 어차피 +등락만 채용한다.
5. **한투 조회 규칙은 홈 순위 화면과 동일** — NAS·NYS 직렬 조회 후 지표로 병합(`kis/ranking.mergeRankingRows`), 아멕스 제외.
6. **실패 정책** — 토스 묶음 실패는 throw(워치리스트가 직전 리스트 유지). 한투는 원천 하나 실패 시 그 원천만 비우고 계속, 단 한투만 있는 계획에서 전부 실패하면 throw.
7. **반영 경로** — `managerProvider.refreshLiveSettings`가 계획 키(`rankingPlanKey`)를 비교해 바뀌었을 때만 갈아끼우고, **폴링 중이면 즉시 재조회**(다음 3분 주기를 기다리지 않음). 정지 상태면 재조회하지 않는다(start가 즉시 1회 돈다).
8. **토스 기간 값** — 실호출로 확인(2026-08-18): `realtime`·`1d`만 결과가 다르고 그 외 값은 realtime으로 폴백된다. 그래서 기간 옵션은 둘뿐.

## 4. 홈 순위 화면

토스 순위 종류를 고르면 셀렉트 두 개가 추가된다 — 기간(실시간/1일)·위험종목(위험포함/위험미포함). 기본은 실시간·위험포함(토스 앱 화면과 동일). 종류 라벨은 "토스거래량순위/토스거래대금순위"로 바꿨다(더 이상 실시간 고정이 아니라서).

## 5. 열린 문제

- 원천 순서 사용자 정렬 — 지금은 카탈로그 고정. 요청 시 선택에 order 추가.
- 한투 순위 폴링은 KIS REST 유량을 쓴다(원천당 거래소 2콜, 3분마다). 원천을 여럿 켜면 콜이 늘어난다 — 문제되면 폴링 주기를 원천별로 분리.
