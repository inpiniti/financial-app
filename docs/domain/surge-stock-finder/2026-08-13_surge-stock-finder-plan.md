## 0. 범위 (논의로 확정)

**진입·눌림목·자동매매 연동은 전부 범위 밖.** 이 기획은 딱 하나만 한다:

> 급등 신호와 급락 신호를 감지해서 그 순간의 체결가·호가를 **DB에 기록**한다. 쓸만한 신호인지는 나중에 기록을 보고 판단한다.

가짜 신호가 섞이는 것을 허용한다 — 오탐 필터링보다 **빠른 발화 + 충실한 기록**이 우선이다. 기록이 곧 오탐율 측정 도구다.

## 1. 기록 스키마 (핵심 산출물)

1행 = 1에피소드(급등 → 후속 급락). Supabase 테이블 `surge_events` 신설(기존 `approved_users`와 같은 프로젝트, 마이그레이션 추가).

| 컬럼 | 의미 | 기록 시점 |
|---|---|---|
| `ticker` | 종목코드 (+시장구분) | 급등 확정 시 |
| `surge_at` | 급등 시간 | 〃 |
| `surge_price` | 급등 시점 체결가 | 〃 |
| `surge_ask1`, `surge_ask2` | 급등 시점 매도1·2호가 (PASK1/PASK2) | 〃 |
| `plunge_at` | 급락 시간 | 급락 확정 시 |
| `plunge_price` | 급락 시점 체결가 | 〃 |
| `plunge_bid1`, `plunge_bid2` | 급락 시점 매수1·2호가 (PBID1/PBID2) | 〃 |
| `price_change_pct` | 체결가 변동율 = (급락체결가 − 급등체결가) / 급등체결가 | 〃 |
| `l1_change_pct` | 1호가 변동율 = (급락시 매수1호가 − 급등시 매도1호가) / 급등시 매도1호가 | 〃 |
| `l2_change_pct` | 2호가 변동율 = 위와 동일하되 2호가 기준 | 〃 |

- 변동율 정의: **급등 시점 매도호가에 사서 급락 시점 매수호가에 팔았을 때**의 ±% — 스프레드 비용이 포함된 현실적 왕복 수익률.
- 페어링 규칙: 급락 신호는 같은 종목의 **열린 에피소드**(급등 기록됨, 급락 미기록)를 닫는다. 열린 에피소드가 없는 단독 급락도 행으로 남긴다(급등 컬럼 null). 급등 후 급락이 안 오면 타임아웃(초안 30분)으로 미완결 마감.
- 2호가 가용성 확인 완료: HDFSASP0 페이로드에 PBID2=17, PASK2=18 존재. 원문 중복 표기로 인덱스가 불확실한 건 3호가 그룹부터이므로 1·2호가는 안전 (`docs/koreainvestment/실시간호가.md:69-70, 93-94`). 현재 파서는 1호가만 소비 중 → 2호가 읽기 추가 필요 (`kis/realtimePrice.ts:130-180`).

## 2. 감지기 설계 — 2단계 (조기경보 → 확정)

후행성 논의 결론: **판정창은 짧게, 기준선은 길게.** 후행성을 만드는 건 판정창이고, 기준선(비교 대상)은 길어도 지연을 만들지 않는다. 기준선이 너무 짧으면(예: 직전 5초) 평소에도 빠른 종목과 방금 빨라진 종목을 구분 못 한다.

### 급등 (SURGE)

| 단계 | 조건 (초안) | 지연 | 역할 |
|---|---|---|---|
| 1단계 조기경보 | 틱 레벨: 연속 업틱 + 직전 1~2초 틱수가 롤링 기준선(60초~5분) 대비 X배 | ~1초 | **호가 WS 동적 구독 트리거** (기록 준비) |
| 2단계 확정 | 1초 청크 평균가 3~5개 연속 상승(정배열) AND 틱속도 배수 유지 | 3~5초 | DB 기록 발화 — 이 시점의 체결가·매도1/2호가 스냅샷 |

### 급락 (PLUNGE)

같은 감지기의 부호 반전 — **역정배열**(1초 청크 3~5개 연속 하락 + 틱속도 폭증). 확정 시 체결가·매수1/2호가 스냅샷으로 에피소드를 닫는다.

- 청크는 기존 1초 고정(`managerProvider.tsx:150`) 그대로. 감지기는 `core/surge/` 순수 TS 모듈로 신설, 기존 감지기와 **병렬 부착**(LadderDetector 교체·간섭 없음, 사다리 앵커 리셋 금지).
- STRN·EVOL은 v1 판정 조건에 넣지 않고 **기록만** 해두는 것 고려(추후 필터 후보 분석용) — 스키마 확장 여지로 남김.

## 3. 호가 스냅샷 문제와 해법

급등이 터지는 종목은 보통 호가 구독이 없다(호가는 감시 top3 ∪ 진입중 ∪ 보유만, `autopilotManager.ts:492-518`). 신호 순간의 호가를 기록하려면:

**1단계 조기경보 = 호가 구독 트리거.** 경보가 뜨면 즉시 해당 종목 호가 WS를 붙인다 → 3~5초 뒤 2단계 확정 시점엔 호가 수신 중. 에피소드가 닫히거나(급락 기록) 타임아웃까지 유지 후 해제.

구독 예산 (KIS 한도 41건):

| 용도 | 건수 |
|---|---|
| 체결가 — 리스트 전 종목 (**20 → 30 확대**) | 30 |
| 호가 — 기존 (감시 top3 ∪ 보유, 그리드 1개 기준) | ~4–5 |
| 호가 — 에피소드 동적 구독 (상한 명시, LRU 해제) | ≤ 3 |
| 합계 | ≤ 38 (+상세화면 몫 여유) |

- 리스트 30 확대는 "리스트 밖에서 튀는 종목은 못 본다"는 구조적 사각을 줄이는 효과도 겸한다. 완전 해소는 불가(전 종목 스캔 서버는 기각) — 리스트 밖 종목은 다음 순위 폴링에서야 편입된다.
- `maxConcurrentGrids`를 올려 쓰면 기존 호가 몫이 불어나므로 에피소드 호가 상한과 합산 검사를 코드에 명시할 것.
- 조기경보 남발로 호가 슬롯이 마르면 오래된 경보부터 해제(LRU). 호가 미수신 상태에서 확정이 먼저 오면 호가 컬럼 null로 기록(버리지 않는다).

## 4. 파라미터 초안 (코드 기본값, 설정 화면 노출 없음)

| 파라미터 | 초안값 | 의미 |
|---|---|---|
| `surgeTickRateMultiple` | 3배 | 조기경보 틱속도 배수 (vs 롤링 기준선) |
| `surgeBaselineSec` | 300 | 틱속도 롤링 기준선 길이 |
| `surgeConfirmChunks` | 4 | 정배열 확정에 필요한 연속 상승 1초 청크 수 |
| `plungeConfirmChunks` | 4 | 역정배열 (급락) 동일 |
| `episodeTimeoutMin` | 30 | 급등 후 급락 미발생 시 미완결 마감 |
| `episodeQuoteSlots` | 3 | 에피소드 호가 동적 구독 상한 (구현 시 5→3 — 리스트 30 확대 후 41건 예산 재계산) |
| `signalCooldownSec` | 60 | 동일 종목 재발화 쿨다운 (중복 행 방지) |

값들은 전부 기록 데이터를 보고 조정한다 — v1의 목적 자체가 이 값들의 적정치를 찾는 것.

## 리스크·미결

- **HDFSCNT0은 지연체결가**(미국 무료 시세) — 신호 시각 자체가 소스 지연을 물고 있다. 기록엔 문제없지만, 데이터 해석 시(특히 "몇 초 만에 잡았나" 평가) 감안할 것. 호가는 나스닥 마켓센터 0분지연 무료.
- 미국 주간거래 세션(KST 10~16시)은 유동성이 얇아 틱속도 기준선이 왜곡될 수 있음 — 세션 전환 시 기준선 리셋 검토 (`daySession.ts`).
- Supabase 기록은 네트워크 실패 시 유실 가능 — v1은 재시도 큐 없이 단순 insert로 시작하되, 유실이 눈에 띄면 로컬 버퍼 추가.
- 토스 비공식 순위 API 폴링 주기 단축은 여전히 보류(차단 리스크) — 리스트 30 확대만 반영.
- **감지 가동 조건 — (a)안 확정(2026-08-13 사용자 결정)**: "자동 트레이딩 시작하기"(`autopilot.start()`)와 함께 켜지고 정지와 함께 꺼진다. 자동매매가 도는 동안의 데이터가 실전 조건과 같아 분석 가치가 높다는 판단. "매매 없이 기록만 모으는" 감시 전용 모드는 필요성이 확인되면 별도 기획.
- 에피소드 운영 규칙(재시작 고아 행 정리, 재급등 무시, 단독 급락 호가 null 허용, 기록 실패 시 감지 지속)은 DB 문서 §2에 확정해 두었다.
