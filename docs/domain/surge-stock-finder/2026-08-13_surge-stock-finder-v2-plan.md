## 1. v1이 실패한 이유 (수집 데이터 기준)

v1 정의(1초 청크 4개 연속 상승 + 틱속도 폭주)로 하루 수집한 결과 — closed 69건:

- 1호가 왕복 변동율 평균 **−1.94%** (승 10/50), 체결가 기준도 평균 −0.27%
- 세트 수명 중앙값 **20초**, 15초 미만 사망 28건(평균 −2.66%)
- 진입 스프레드 >0.3% 세트는 평균 −3.29% — 구조적 전멸

진단 두 가지:

1. **폭 조건 부재**: v1 확정 조건 어디에도 "얼마나 올랐는지"가 없다. 페니주에서 $0.0001씩 4번 오르는 것(합계 +0.1%)도 통과 → 감지 대상이 급등이 아니라 **4초짜리 미세 발작**이었다. (초안의 "60초 ≥3%" 폭 조건을 후행성 논의 때 속도와 맞바꾸며 버린 결과 — 진짜 급등은 4초 안에 확인될 수 없다는 물리적 트레이드오프를 무시했다.)
2. **감지와 진입 신호의 혼동**: 급등은 초 단위 이벤트가 아니라 **분 단위 상태**(in-play)다. 상태 판정을 초 단위 트리거처럼 설계하니 확정 지점이 국소 고점이 됐고, 확정 즉시 되돌림에 맞았다.

## 2. v2 설계 원칙

```
[1층 스캐너]  종목이 "급등 상태"로 들어왔는가 — 분 단위, 폭·구조·참여로 확실하게  ← 이 문서의 범위
[2층 트리거]  급등 상태 종목에서 언제 들어가는가 — 초 단위                        ← v2 범위 밖(기존 사다리가 후보)
```

- 속도 경쟁은 2층에서만 한다. 1층이 30초 늦는 것은 결점이 아니다 — 진짜 급등은 분 단위로 지속된다.
- 모든 문턱은 고정 %가 아니라 **그 종목의 변동성(σ) 단위** — 페니주와 정상주에 같은 잣대가 적용되게. (v1도 틱속도에는 이 원리를 썼다 — 기준선 3배. 가격에 안 쓴 게 문제였다.)
- v2도 **기록 전용**이다(매매 연동 없음). 세트 = 급등 지점(진입시점 후보) + 이탈 지점(이탈시점) — v1과 동일하게 세트만 기록.

## 3. 급등 지점 판별 — 3조건 AND의 최초 동시 성립 틱

| 조건 | 판별식 (초안) | 재료 |
|---|---|---|
| **폭** | 최근 60초 수익률 ≥ **4σ** (σ = 최근 20~30분의 60초-수익률 롤링 표준편차) | 1초 청크 버퍼 연장(롱 버퍼) |
| **구조** | 현재가가 **최근 5분 신고가** 갱신 중 | 5분 고가 링(초당 1값) |
| **참여** | 틱속도 ≥ 기준선 3배(v1 A경로 유지) AND 체결강도(STRN) ≥ 100 | TickRateMeter·기존 링 / STRN은 수신 중 |

- 성립 순간의 시각·체결가를 급등 지점으로 기록. **앵커(60초 수익률의 시작가)도 함께 기록** — "어디서 출발한 급등을 얼마나 온 시점에 인지했나"가 MFE 분석의 기준선이다.
- σ 워밍업: 롤링 창(20분) 미달 시 무발화. v1의 속도 정배열(B 경로)은 **조기경보 전용으로 강등** — 확정(급등 판정)에는 쓰지 않는다(폭 조건이 없는 경로라 v1 실패의 재발 통로).
- 상태 유지: 급등 확정 후 에피소드가 닫힐 때까지 같은 종목 재확정 없음(v1 재급등 무시 규칙 유지).

### 조기경보(호가 예열)의 v2 역할

확정 전에 호가 WS를 붙여야 하는 요구는 v1과 동일. v2 경보 = **폭 2σ 도달 + 참여 성립**(신고가 불요) — 확정의 완화판. 발화 시 호가 동적 구독(상한 3, LRU — v1 골격 그대로). v1 B경로(속도 정배열)도 경보 트리거로는 유지(워밍업 전 커버).

## 4. 이탈 지점 판별 — 3경로 OR, 먼저 닿는 것

| 경로 | 판별식 (초안) | 잡는 상황 | 기록 사유 |
|---|---|---|---|
| ① 돌파 실패 | 가격이 **돌파했던 5분 신고가 선 아래로 복귀** | 가짜 돌파 — 뚫었던 선을 도로 내주면 그 자리에서 사망. 구조 기준이라 가장 빠르고 명확 | `breakout_fail` |
| ② 소프트 | 참여 식음(틱속도 기준선 복귀) + 트레일링 고점 대비 하락 ≥ **1.5σ** | 힘 빠진 페이드 (v1 "둔화"의 σ 버전) | `soft` |
| ③ 하드 | 트레일링 고점 대비 하락 ≥ **3σ**, 참여 무관 | 투매 (v1 "급락"의 σ 버전) | `hard` |

- **스프레드 하한**: 이탈 문턱 = max(σ 문턱, 최근 스프레드 × 2). 페니주에서 σ < 스프레드면 호가 왕복만으로 이탈이 찍힌다 — 그건 하락이 아니라 호가 소음.
- v1 데이터의 "확정 즉시 사망" 다수는 사실 돌파 실패였다 — ①이 이를 **실패라고 즉시, 명시적으로** 기록한다. 이탈 사유 분포가 곧 진단이 된다: `breakout_fail` 과다 → 진입 조건 강화 / `soft` 과다 → 지속력 부족 / `hard` 과다 → 변동성 장세.
- 만료(expired)는 틱이 끊긴 극단 케이스만 잔류(v1 유지).

```
앵커(출발가) ──[+4σ & 5분 신고가 & 참여]──▶ 급등 지점 기록 ──┬─ ① 돌파선 상실
                                            │ 트레일링 고점 추적 ├─ ② 식음 + 고점−1.5σ
                                            ▼                  └─ ③ 고점−3σ
                                       호가 예열 유지 ────────────▶ 이탈 지점 기록 + 세트 종결
```

## 5. 기록 확장 — 마이그레이션 0005

세트당 반사실 분석(MFE)이 가능하도록 컬럼 추가:

```sql
-- 0005_surge_events_v2.sql (초안)
alter table surge_events
  add column if not exists anchor_price numeric,   -- 급등 출발가(60초 수익률 시작점)
  add column if not exists peak_price   numeric,   -- 이탈 시점 트레일링 고점 (MFE = peak/surge_price)
  add column if not exists surge_sigma  numeric,   -- 급등 시점 σ(60초 수익률 표준편차, 소수) — 문턱 튜닝 근거
  add column if not exists exit_reason  text
    check (exit_reason in ('breakout_fail', 'soft', 'hard') or exit_reason is null);
```

- 기존 컬럼·RLS·생성 컬럼(변동율 3종) 그대로 — add column만이라 v1 데이터와 공존.
- 분석 예: `peak_price`가 일관되게 `surge_price` 근처(MFE≈0)면 급등이 확정 시점에 이미 끝난다는 뜻 → 추격류 전략 전면 폐기 근거. MFE가 +2σ 이상인데 성적이 −면 진입/이탈 타이밍 문제 → 튜닝 여지.
