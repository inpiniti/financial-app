# 변곡점 (Inflection Point) — 개념·역사·구현

> 작성일 2026-08-14 · 분류: **도메인 문서** (이 앱의 출발점이 된 핵심 개념의 정리)

> 코드: `core/detector/index.ts`(SG 감지기), `core/ladder/index.ts`(사다리 감지기), `features/scalper/feedSlot.ts`(배선·스위치)

## 1. 변곡점이란 — 이 앱에서의 정의

이 앱은 처음부터 **"변곡점 단타 앱"**으로 설계됐다(2026-07-29 PRD). 여기서 변곡점은 수학의 2차 미분 부호 전환이 아니라, **평활된 가격 곡선의 기울기(1차 미분) 부호가 바뀌는 지점**을 뜻한다:

- **상승 변곡점 (BUY)**: 기울기 `-` → `+` 전환 = 바닥. 진입 신호.
- **고점 변곡점 (SELL)**: 기울기 `+` → `-` 전환 = 천장. 청산 신호.

핵심 철학(PRD §2, 사용자 확정 2026-07-29):

- **고정 손절·익절·시간 손절 없음.** 진입도 청산도 오로지 변곡점 신호로만. 하락 방어는 고점 변곡점 청산이 담당한다.
- 승률 100%가 아니라 **손익비 관점의 손실 최소화·계좌 보호**가 목적.
- 틱 단위 매매 지양 — 노이즈를 제거한 **1~3분 단위의 큰 변곡점 파동**만 추적한다(수수료·슬리피지).

- 판정 주기는 **리샘플 청크 마감** — SG든 사다리든 입력 주기가 같다.

## 3. 1세대 구현 — SG 미분 감지기 (`TrendDetector`, `core/detector/index.ts`)

`ml-savitzky-golay`로 버퍼의 1차 미분(기울기)·2차 미분(가속도)을 매 청크 계산하고, 부호 전환에 확인 단계를 덧댄 상태기계.

### 3-1. 매수 상태기계 (2026-07-31 모멘텀 확인 단계)

부호 전환만으로 사면 잔파동에도 사므로, 전환 감지 후 "모멘텀 확인 대기"를 거친다:

1. `prevSlope < 0 && slope >= 0` 전환 감지 → 대기 진입(이 청크엔 BUY 없음).
2. 이후 매 청크 **상대 기울기(slope ÷ 마지막 가격, %/청크) ≥ 문턱**(`minBuyMomentum`, 기본 0.01%/청크)이면 BUY. 상대값이라 $2든 $300이든 같은 %기울기면 같은 판정.
3. `confirmWindowChunks`(기본 5) 소진 또는 기울기 재음전 → **대기 폐기**(전환 감지로 복귀).
4. 문턱 0이면 끔 — 전환 즉시 BUY(하위호환).

여기에 **BUY 게이트**(2026-08-03)가 AND로 붙는다: 거래량 스파이크 배수(`minVolumeSpikeRatio`)·체결강도(`minStrength`), 입력 null이면 통과(**fail-open** — 데이터 유실이 매매를 전면 중단시키지 않게).

### 3-2. 매도 상태기계 (2026-07-31 — 매수와 비대칭)

실사례가 계기: 0.439 매수 → 0.437 얕은 눌림에서 기울기가 0을 잠깐 하향 통과했다는 이유로 즉시 청산돼 이후 0.99까지의 추세를 놓쳤다. 그래서 "전환 즉시 매도"를 약한 필터로 개정:

1. `+ → -` 전환 감지 → "매도 확인 대기" 진입.
2. 하락 상대 기울기 크기 ≥ 매도 문턱(`minSellMomentum`, 기본 0.005%/청크) → SELL.
3. 대기 중 기울기가 +로 회복 → 매도 폐기, 홀딩 (핵심 구제 경로 — 얕은 눌림 홀딩).
4. **대기 한도(`sellConfirmWindowChunks`, 기본 2청크=6초) 만료 시 무조건 SELL** — ⚠ 매수(만료 시 폐기)와 반대. 매도는 지연 상한이 6초일 뿐 반드시 실행돼 방어선을 보존한다.
5. **급락 예외**: 상대 가속도(accel ÷ 가격) ≤ `crashAccelThreshold`(기본 -2%/청크²)면 대기 무시 즉시 SELL. 임계 근거 — 평범한 둥근 정점의 상대 가속도는 최악 ≈ -0.008/청크², 진짜 폭락은 -0.013 이하로 깊어진다(합성 시나리오 캘리브레이션). 만료 6초 방어선이 있어 임계를 보수적으로 잡아도 노출은 최대 6초.

매수·매도 대기 상태는 완전 독립(reset 포함). 순수 TS 클래스라 과거 틱 재생 단위 테스트 가능(`core/detector/index.test.ts`).

## 4. 왜 교체됐나 — SG 변곡점의 한계 (2026-08-07)

SG 기울기 부호 전환의 구조적 결함:

- 찔끔 내려갔다(기울기 −) 찔끔 올라가도(기울기 +) 부호는 전환된다. 모멘텀 문턱은 "전환 직후 기울기"만 본다.
- **얼마나 내려왔는지(누적 낙폭)는 아무도 안 본다.** 사실상 횡보인 잔파동에서도 "바닥"을 선언한다.

→ 해법: 매도실행기(그리드)와 같은 **사다리 논리**로 바닥을 재정의. "간격 g%만큼 실제로 떨어질 때마다 가상 매수(홀) 1회"를 기록하고, 홀이 N번 쌓여야(누적 낙폭 최소 N×g%) 진짜 하락으로 인정한다. 잔파동은 구조적으로 걸러진다.

## 5. 2세대 구현 — 가상 그리드 사다리 (`LadderDetector`, `core/ladder/index.ts`) ★ 현행

주문 없는 가상 포지션의 상태기계. 입력은 청크 마감가 1개(기존과 같은 주기):

```
앵커 A = 감시 시작 시점 가격 (가상 평단, 트레일링 고점)
가상 매수선 = 직전 레벨 × (1−g)    ← 닿으면 홀 카운트 +1, 레벨 갱신
가상 매도선 = 직전 레벨 × (1+g)    ← 닿으면 "가상 익절" = 사다리 전체 리셋
```

1. 첫 청크 → 앵커만 세운다(신호 없음).
2. 카운트 0에서 가격이 레벨보다 높으면 → **트레일링 고점 갱신**(상승장에서 낙폭 기준이 낡지 않게 — 눌림목을 고점 기준 낙폭으로 잡는다).
3. 가격 ≤ 레벨×(1−g) → 홀 카운트 +1. **급락 1청크가 여러 레벨을 관통하면 관통 수만큼 카운트**(3레벨 급락 = 홀 3회).
4. 카운트 진행 중 가격 ≥ 레벨×(1+g) 반등 → 가상 익절 = 전체 리셋(신호 없음 — 잔파동 해소).
5. **카운트 ≥ N(기본 3)** → BUY 게이트(거래량/체결강도, fail-open — SG와 동일 계약) 통과 시 **BUY 발화 + 리셋**. 게이트 미통과면 `buyGateBlocked`로 카운트 유지(그 사이 반등하면 4의 리셋 우선).

### 5-1. 핵심 설계 결정 (plan L1~L6)

| # | 결정 | 내용 |
|---|---|---|
| L1 | 순수 가격 사다리 | 배율(m)은 감지에 미적용 — 배율은 실주문 수량 개념. 적용하면 레벨 간격이 배율 설정에 끌려다녀 튜닝이 꼬인다 |
| L2 | N번째 홀 즉시 BUY | 떨어지는 칼 리스크는 BUY 게이트 AND + 체결 후 매도그리드 물타기가 방어 |
| L3 | 설정 2개 | `entryLadderIntervalPct`(g, 기본 1%)·`entryLadderCount`(N, 기본 3) → 기본 누적 낙폭 약 3%에서 진입. ⚠ g는 매도그리드 폭과 **별개** — 감지는 분 단위 잔파동, 매도그리드는 포지션 관리로 시간 스케일이 다르다 |
| L4 | SG 감지기 보존 | 삭제 안 함. `feedSlot.ts`의 **`LADDER_ENTRY = true`** 상수 한 줄이 롤백 스위치 |
| L5 | BUY 전용 | 청산은 매도그리드(`core/grid`) 몫이라 SELL 변곡점 불필요. 사다리 옵션 미주입 하네스는 SG detector 그대로(회귀 안전) |
| L6 | 리셋 시점 | BUY 발화 후·가상 익절 후·감시 해제/재부착 시 완전 리셋. attach = 새 감지기 = 새 앵커 |

## 6. 현재 배선과 역할 분담 (2026-08-14 기준)

```
feedSlot.attachDetector()
  ├─ LADDER_ENTRY=true && ladderOptions 주입 → LadderDetector  ← 현행 (진입 감지)
  └─ 그 외(스위치 off·옵션 미주입 하네스)     → TrendDetector   ← 롤백/폴백 (SG)
체결 후 → 매도그리드(core/grid)가 청산·물타기 인계 (GRID_EXIT 경로)
```

- **진입** = 사다리 변곡점(누적 낙폭 기반 바닥), **청산** = 매도그리드(평단±폭 OCO). SG 감지기의 SELL 상태기계(§3-2)는 그리드 미주입 폴백 경로에서만 살아 있다.
- 2026-08-14 이후 관련 방어: 그리드 매수 다리 5초 지연 + min(평단, 현재가) 앵커(급락 방어), 비대칭 그리드 폭(매수폭/매도폭 분리).
- UI: InstanceCard·AutoPilotScreen이 사다리 뷰(현재 홀 n/N·다음 매수선)를 표기. SG 시절의 모멘텀 배지는 사다리 뷰로 교체됨.

## 8. 재구현·수정 시 지켜야 할 것

1. **순수 TS·플랫폼 무관** — 감지기는 외부 의존 최소(`ml-savitzky-golay`만 허용, 사다리는 0)의 순수 클래스로 유지한다. 돈이 걸린 로직이라 **과거 틱 재생 단위 테스트**가 가능해야 한다.
2. **신호 계약 고정** — 감지기 교체는 `'BUY'` 신호 계약만 지키면 autopilot 무변경으로 배선 교체가 가능하다(2026-08-07 교체가 그렇게 됐다). 새 감지기를 시도할 땐 같은 패턴(한 줄 스위치 + 기존 감지기 보존)을 쓴다.
3. **게이트는 fail-open** — 거래량/체결강도 입력 null(판정 불가)은 통과. 데이터 유실이 매매를 전면 중단시키면 안 된다.
4. **매도 비대칭 불변** — SG 폴백 경로를 만질 때, 매수 대기는 만료 시 폐기·매도 대기는 만료 시 무조건 실행이라는 비대칭을 깨지 말 것(방어선).
5. **잔파동 회귀 테스트** — "찔끔 하락+찔끔 반등 무신호"가 사다리 도입의 존재 이유다. 감지 로직 수정 시 이 회귀 테스트(±0.5g 반복 무신호)를 반드시 유지한다.
6. **진입 빈도보다 청산 위험 최소화** — 파라미터 조정은 보수적으로: 횟수보다 간격(g)·홀 수(N)를 키우는 방향이 우선이다.
