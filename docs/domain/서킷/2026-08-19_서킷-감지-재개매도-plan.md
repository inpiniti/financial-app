## 0. 단계 — 관측 먼저

서킷 종목은 하루 1종목꼴이라 **정지 중 WS 동작을 모른 채 규칙부터 짜면 안 된다.** 1단계는 이벤트만 남기고, 2단계에서 규칙을 켠다. 두 단계는 한 번에 구현하되 2단계는 스위치(`CIRCUIT_MODE`, `features/scalper/circuitMode.ts`, TREND_MODE와 같은 관례)로 기본 꺼짐.

## 1. `core/circuit` — 순수 로직

- `HaltDetector`: `pushTick(price, tsMs)` / `poll(nowMs)` → `HALT_SUSPECT`(무체결 ≥ 45초 ∧ 직전 3분 틱 ≥ 30) / `RESUME`(재개 첫 틱, 갭 % 포함) 이벤트. 세션 필터(main만)는 호출부(daySession)가 건다.
- `HaltSequence`: 정지 직전가 수열 `p[]`와 방향 `d[]`, `consecutiveDown`, `lastHaltPrice`, 재개 창 길이 `windowSec[]`(재개 첫 틱 시각~마지막 틱 시각). `onHalt(price, lastTickMs)` / `onResume(price, tsMs)`. `inCircuit` = 어떤 k에서 `windowSec[k] < 60` 뒤 정지 k+1이 감지됐고 아직 300초 무정지 재개가 없음.
- `CircuitExitRule`(PositionRule 계약 — `TrendExitRule`을 감싸는 데코레이터): 서킷 상태면 `decide('SELL') → null`(ma5 무시), `onPrice`는 손절선 위임, 새 메서드 `onHalt(price) → ConditionalDecision | null`(하킷 2연속 or 손절선 → `{side:'sell', qty:전량, limit: p×0.88}`). 5분 무정지면 서킷 상태 해제.
- 테스트: AIXC 08-18 정지 수열(창 1~3초 가정)을 픽스처로 — ①은 정확히 15번째 정지(2.45)에서 발화, 그 전 하킷 1회(1.69·2.59)에선 발화 안 함, 상킷 연속 홀드, 해제 뒤 ma5 SELL 다시 통과. 고립 정지 픽스처(정지 1회 → 재개 뒤 정상 틱 5분) — 상태 진입 없음·ma5 SELL 그대로 통과.

## 2. 배선

- `FeedSlot`: 틱 시각 링(최근 3분)과 마지막 틱 시각을 노출 → 매니저/오토파일럿 1초 폴 루프(기존 리프라이스 틱)에서 `HaltDetector.poll`. 슬롯 스냅샷에 `halt: {state, sinceMs, count}` 추가(행 텍스트에 "정지 n회 · 하킷 2연속" 표시).
- `autopilot`: 보유+`HALT_SUSPECT` → `CircuitExitRule.onHalt`. 결정 있으면 **지정가 발주 경로** 필요 — 현재 `startConditionalExec`은 현재가 추격 시장성 정정이므로, "지정가 고정 + 미체결 시 재개 틱부터 추격으로 전환"을 Execution 옵션으로 추가(`initialLimit`, `chaseAfterFirstTick`). 취소선 없음(shouldAbort=false 그대로).
- 정지 중 발주가 거절되면(§미결 1) 결정을 보류(`pendingHaltSell`)했다가 `RESUME` 첫 틱에 즉시 같은 지정가로 발주.
- `ExitReason`에 `'CIRCUIT' | 'MANUAL'` 추가, `tradeResults` 매핑, 이벤트 문구("정지 중 매도 접수 · 재개 단일가에 소화해요").

## 3. 외부 청산 기록(정본 §6)

- 보유 종목 잔고 재확인: 정지 감지 시 + 2분 주기 `fetchPosition`(기존 정산 경로 `next.qty <= 0` 분기 재사용). 수량 0 → 주문체결내역 조회로 마지막 매도 체결가·시각 → `MANUAL` 정산. 조회 실패 시 마지막 현재가 + 이벤트 "체결가 미확인".
- 2분 폴은 보유 종목 수만큼 REST 호출 — 보유는 보통 1~3종목이라 한투 초당 한도 안.

## 4. 순서

1. `core/circuit` + 테스트(AIXC 픽스처).  2. FeedSlot 틱 시각·스냅샷 + 이벤트(관측 단계, `CIRCUIT_MODE=false`에서도 이벤트는 남김).  3. ExitReason 확장 + 외부 청산 기록(서킷 무관하게 바로 켬).  4. Execution 지정가 옵션 + autopilot 배선(스위치 뒤).  5. 다음 서킷 종목 실사용 이벤트로 §미결 확인 → 스위치 켬.
- 커밋은 1~4 완료 후 한 번(플랜 단독 커밋 금지). 분석 일지(`docs/분석/README.md`)에 "08-18 AIXC 서킷 → 서킷 도메인" 항목 추가.

## 4-1. 구현하며 정한 것(문서 §3 보강)

- **활발함 문턱 완화**: 직전 정지 감지 뒤 15분(`relaxAfterHaltMs`)은 "재개 뒤 체결 1건 이상 + 45초 무체결"만으로 정지 판정 — 서킷 연속 구간에선 3분 창에 30건이 안 쌓여 두 번째 정지부터 못 봤다(테스트에서 발견).
- **1초 폴 관측**: 틱마다가 아니라 리프라이스 틱(1초)에서 슬롯의 (`price`, `lastTradeAt`)를 넘긴다 — 같은 `lastTradeAt`은 중복 기록 안 함. 체결 수는 "초당 최대 1건"으로 세지므로 30건 = 3분 중 30초 이상 체결이 있었다는 뜻(실측 틱 수보다 보수적).
- **정지 중 지정가 유지**: Execution `chaseGate` — 재개 뒤 첫 체결(`slot.lastTradeAt > 정지 직전 체결 시각`)이 관측되기 전엔 정정하지 않는다(1초 폴이 정지 중 낡은 현재가로 지정가를 끌어올리는 사고 방지). 취소선 판정은 게이트와 무관(추세는 취소선 없음).
- **MANUAL 2회 연속**(2분 간격) — 문서 §6. 체결가는 현재가 기록(APTR0058).
- **UI 미반영**: 슬롯 행의 정지/서킷 상태 텍스트는 이번에 넣지 않았다(관측 단계는 이벤트로 충분). 스위치 켤 때 같이.
- 정규장 게이트 `isUsRegularSession`(ET 09:30~16:00, Intl 서머타임 자동) — 서킷 감지에만 쓴다.

## 5. 미결 (첫 실사용 이벤트로 확인)

1. **한투가 정지 중 지정가 주문을 접수하는가.** 거절이면 `RESUME` 즉시 발주로 대체(재개 경매는 놓치고 첫 틱 이후 체결 — 08-18 11:20봉은 시가 2.41→저가 2.20이라 1분 안에 팔렸을 것).
2. **정지 중 WS로 무엇이 오나.** 체결가 틱이 아예 끊기는지, 호가만 바뀐 틱(PBID/PASK 변화, 체결가 동일)이 오는지 → 후자면 "무체결"을 체결가·누적거래량 변화 없음으로 판정해야 함.
3. 45초·틱 30개 문턱이 저유동 보유 종목에서 오탐하지 않는지(정규장 활발 종목만 대상이지만 점심시간 소강 확인). **재개 창 60초(체감 5초)** — 실측 `windowSec`을 이벤트로 남겨 AIXC형(수 초)과 고립형(수 분)이 실제로 갈리는지 확인. 창은 재개 경매 체결 시각~마지막 체결 시각이라 경매 한 번이면 0초.
4. 12% 지정가 여유가 충분한지 — 08-18 하킷 재개 갭은 −2%(2.45→2.41)·−1%(2.12→2.10)였고 재개 봉 저가는 −10%(2.45→2.20). 재개 경매가가 −12% 아래면 미체결→추격.
5. 서킷 상태 해제 5분이 적절한지(AIXC 11:59→12:10 사이 11분 무정지 뒤 한 번 더 정지 있었음 — 해제 뒤 재진입 시 다시 상태 진입하면 되므로 큰 문제는 아님).
