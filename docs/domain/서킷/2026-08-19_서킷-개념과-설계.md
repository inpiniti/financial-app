## 1. 왜 — 추세 규칙이 시간축에서 작동을 못 하는 종목

AIXC 08-18 정규장: 0.83 → 09:33 1.19 첫 정지 → 상킷 연속으로 10:55 3.14 고점 → 하킷 연속으로 11:59 1.36 → 12시 이후 정지 없이 1.3~1.8 횡보, 종가 1.29. **정지 24회**(5분 정지가 대부분, 10분 정지 5회), 정지 사이 거래 가능 시간은 1~2분뿐 — 한 시간에 거래 기회 6번꼴.

이런 종목에서 추세 규칙은 세 가지가 깨진다.

1. **봉이 안 닫힌다.** 우리 봉은 틱 주도(다음 봉 첫 틱이 직전 봉을 닫음)라 정지 중엔 봉이 멈추고, 재개 순간 갭 봉 하나가 닫힌다. `close < ma5` 판정이 갭 뒤에 나온다.
2. **매도 주문은 정지 중엔 체결이 안 되고, 재개는 단일가 경매다.** 지정가는 "그 가격에 팔린다"가 아니라 "경매가 ≥ 내 지정가면 경매가로 팔린다 / 아니면 미체결"이다. 재개 뒤 1~2분 안에 다시 정지되면 미체결 주문은 다음 정지 구간에 갇힌다.
3. **정지 중 호가창은 뒤집혀 있다.** 체결 없이 쌓인 주문이라 매수 5불 / 매도 1.2불 같은 crossed 상태로 보이고, 재개 직전 대량 취소된다. 잔량은 신호가 아니라 노이즈다 — **호가를 보고 "적당한 가격"을 고르는 방식은 안 통한다.**

08-18 사용자는 화면을 지켜보다가 한투 앱을 따로 켜서 2.45 하킷 뒤 재개(시가 2.41)에서 2.2에 팔았다. 그 매도는 앱에 기록되지 않았다(외부 체결). 이 도메인은 **그 판단과 그 손동작을 코드로 옮기고, 외부 체결도 기록에 남기는 것**이 목적이다.

## 2. 사실 — LULD 정지의 모양 (08-18 실측)

- 정지 길이 5분(봉 4개 무체결)이 기본, 재개 경매 불균형이면 5분 연장 → 10분(봉 9개). 첫 정지(09:35)와 정점 부근(10:35·10:46·11:01·11:11)이 10분.
- 재개 봉은 정지 직전가 대비 갭으로 열린다. 상킷 뒤 재개는 위로(1.19→1.43, 1.51→1.54, 2.65→2.79), 하킷 뒤 재개는 아래로(2.45→2.41→저가 2.20, 2.12→2.10→1.85).
- 정지 직전가 수열(정지 순서대로): 1.19, 1.51, 1.77, 1.93, **1.69↓**, 1.78, 2.20, 2.40, 2.65, 2.95, **2.59↓**, 2.67, 3.14, **2.99↓, 2.45↓**, 2.12↓, 1.85↓, 1.81↓, 1.82, 1.73↓, 1.53↓, 1.50(12:10)…
  - 상승 국면에도 하킷이 한 번씩 끼어든다(1.69, 2.59). **하킷 1회는 꺾임 신호가 아니다.** 2연속(2.99↓, 2.45↓)부터 내리막이 이어졌다.

## 3. 규칙 (정본 — 사용자 확정 2026-08-19)

```
대상:  보유 중인 종목(추세 모드). 정지 감지는 보유 종목에서만 의미 있다(진입 판단은 별도, §5).
정지 감지 (HALT):
   정규장(ET 09:30~16:00) 중, 직전 3분 체결이 활발했던 종목(체결 ≥ 30건)에서 무체결 ≥ 45초 → 정지 의심.
   단, 직전 정지 감지 뒤 15분 안에는 활발함 문턱을 풀어 "재개 뒤 체결 1건 이상 + 무체결 45초"로 본다
   (서킷 연속 구간은 재개 창이 몇 초라 3분에 30건이 안 쌓인다 — 첫 정지만 문턱을 넘으면 된다). 체결 = 체결량(EVOL) > 0 인 틱.
   재개 첫 틱이 정지 직전가 대비 |갭| ≥ 3% 이면 정지 확정(사후). 의심 단계에서 이미 주문을 준비한다(§4).
   ※ 정지 중 우리 WS로 무엇이 오는지(호가 틱 유무)는 첫 실사용 이벤트로 확인 — plan §미결.
정지 수열:  p_k = k번째 정지 직전 체결가. 방향 d_k = sign(p_k − p_{k−1}) (k=1은 진입 후 직전 봉 종가 대비).
거래 창:  w_k = k번째 재개 첫 틱 ~ 그 뒤 마지막 틱까지의 초. (다음 정지가 감지되면 확정)
고립된 정지(정지 → 재개 → 정상 거래 계속, w ≥ 60초): **아무것도 안 함.** 기존 추세 로직 그대로.
   08-18 서킷 종목 대부분이 이 모양이었고 정상 로직이 잘 돌았다(사용자 관찰). 정지 하나에 하락 지정가로 파는 건 과잉이다.
서킷 상태 진입: 재개 뒤 거래 창이 **60초 미만인 채로 다시 정지**(w_k < 60초 ∧ 정지 k+1 감지) — "재개 몇 초 만에 재정지" 패턴(AIXC).
   (사용자 체감은 5초였지만 분봉으론 검증 불가 — 60초 미만은 확실하므로 60초로 두고 실측 windowSec으로 조인다.)
   이때부터 슬롯을 "서킷 상태"로 표시하고 **ma5 청산(close < ma5)은 무시**한다
   — 봉이 시간축에서 안 맞고(§1-1), 첫 하킷에서 털리면 3.14까지 못 간다(§2). 손절선(−7%, 틱 판정)은 그대로 산다.
   정지 수열 p_k는 상태 진입 전(첫 정지)부터 쌓는다 — 상태 진입 시점에 이미 2연속 하킷이면 즉시 조건 ①.
청산 조건 (둘 중 하나):
   ① 하킷 2연속: d_k < 0 ∧ d_{k−1} < 0
   ② 손절선: p_k ≤ 평단×(1−0.07)   (정지 직전 틱에서 TrendExitRule.onPrice가 이미 울렸으면 그쪽이 먼저)
   상킷(d_k > 0)은 몇 번이든 홀드. 하킷 1회 뒤 상킷이면 연속 카운트 리셋.
청산 방법 — "재개 단일가에 무조건 소화":
   조건 충족 시 정지 중에 지정가 매도(전량) 접수: 지정가 = p_k × (1 − 0.12).
   경매가 ≥ 지정가면 경매가로 체결(지정가보다 좋게 팔린다), 미체결이면 재개 첫 틱부터 기존 매매(추격 정정, shouldAbort=false)로 1호가(PBID) 추격.
   한투가 정지 중 주문을 거절하면 → 재개 감지(첫 틱) 즉시 같은 지정가로 발주(plan §미결 1).
서킷 상태 해제: 재개 후 5분 동안 정지 없음(w ≥ 300초) → 상태 해제, ma5 청산 복귀. (AIXC 12:00 이후 구간이 이 모양.)
기록:  청산 사유 exitReason = 'CIRCUIT'(하킷 2연속) / 'STOP_LOSS'(손절). 정지 수열은 이벤트로 남긴다.
```

08-18에 대입: ①은 11:11 정지(2.45↓, 직전 2.99↓)에서 충족 → 정지 중 지정가 2.45×0.88=2.16 접수 → 11:20 재개 경매(시가 2.41, 저가 2.20)에서 체결. 사용자 실매도(2.2)와 같은 자리, 진입 ~1.0 기준 +1.2. 비교: 첫 정지 매도 +0.4, 첫 하킷 매도 +0.7, 안 팔면 +0.3.

## 4. 왜 호가 도메인은 안 만드나

- 정지 중 호가는 crossed·낚시가 섞여 판단 근거가 못 된다(§1-3). "잔량 많은 데 걸기"는 재개 경매에선 의미가 없다 — 체결은 경매가 하나로 난다.
- 필요한 1호가(PBID/PASK/VBID/VASK)는 이미 체결가 틱 페이로드로 온다(2026-08-14 결정, `createRealtimeFeed.onTick → quoteHandler`). 10호가 WS(HDFSASP0)를 다시 구독하면 MAX SUBSCRIBE OVER 문제로 돌아간다. **호가 구독은 다시 열지 않는다.**
- 재개 후 미체결 추격은 기존 매매(1호가 추격 정정)로 충분하다.

## 5. 범위 밖(이번엔 안 함) — 기록만

- **진입 차단**: 서킷 이력 종목의 당일 진입 금지. 진입은 막을 수 있어도 보유 중 서킷은 못 피하므로 우선순위 낮음(분석 §4). 정지 수열이 이벤트로 쌓이면 그때 판단.
- **상킷 익절**: 상킷 N회 뒤 일부 익절 같은 변형은 표본 1건으로 정하지 않는다.
- 08-18 AIXC 분봉에선 재개 창이 1~2봉으로 보이지만 봉이 경계를 걸친 탓이고, 실제는 재개 경매 체결 뒤 몇 초 만에 재정지였을 것(예: 10:24 봉이 2.65 단일가에 38,804주 = 경매 한 번). **창 길이 60초(체감 5초)는 틱 시각으로 실측해 검증**(plan §미결 3).
- 하루 표본 1종목(AIXC). GNPX(같은 날 −37% 갭)는 첫 하킷이 곧 진입가 밑이라 손절선이 먼저 잡는 케이스 — 서킷 종목 2~3건 더 모아 §3 상수(45초·60초·3%·12%·5분)를 재검토.

## 6. 외부(수동) 청산 기록 — 서킷과 별개지만 같이 고친다

08-18 매도는 한투 앱에서 했고 앱은 몰랐다. 실시간체결내역통보(H0GSCNI0)는 현재 배선돼 있지 않다. 이번엔 **잔고 재확인**으로 푼다: 보유 종목은 (a) 정지 감지 시 (b) 그 외 2분마다 `fetchPosition` — 수량 0이면 주문체결내역(`docs/koreainvestment/주문체결내역.md`)에서 그날 그 종목의 마지막 매도 체결가·시각을 읽어 exitReason = 'MANUAL'로 정산·기록(`trade_results`). 체결내역을 못 읽으면 마지막 현재가로 기록하고 이벤트에 "체결가 미확인" 표시.
