# 모델 청산에 "익절 전 재확인 + 래칫"을 넣는다 (보류는 검증됨, 래칫 변형은 사용자 지시로 선적용)

> **2026-09-02 사후 검증 통과** — 반영 직후 사용자 지시로 래칫 그대로를 4폴드 백테스트했다(financial-analyze
> `docs/analysis/2026-09-02_래칫-사후-검증.md`): 합계 +70.6(기준 +39.2의 1.8배) · PF 1.24~1.36 · 최악 −3.35%
> 동일 · 4폴드 전부 기준 상회. 보류 검증본(+83.8)보다 ~16% 적지만 "+3% 반납 없음"·짧은 보유(20~23분)를 얻는다.
> H=q95는 전 폴드에서 q90에 밀림 — 현행(q90=상위 10%) 유지. 아래 본문의 "미검증" 서술은 반영 시점 기준이다.

±3% 대칭 청산(ADR 0008)은 익절 +3%에서 무조건 팔아 큰 상승을 매번 잘랐다. 사용자 제안 "익절 전에 모델을
다시 물어 오를 가능성이 높으면 유지"를 워크포워드 4폴드로 검증한 결과(financial-analyze
`docs/analysis/2026-09-01_익절-전-모델-재확인-청산.md`) **모든 문턱에서 기준 우위** — 최적 H=상위 10%에서
합계 2.1배(+83.8 vs +39.2)·PF 1.22~1.44·최악 −3.35% 동일·손익분기 슬리피지 2~4배 완화.

**Decision**: 익절선 터치 순간 최신 봉 확률 ≥ 보류 문턱(H, model.json `hold_threshold` = 학습 분포 상위 10%,
export_model.py가 동봉)이면 팔지 않는다. 이때 검증된 "확률 꺾이면 매도" 대신 **밴드를 터치 레벨 기준
±3%로 올려 다는 래칫**(앵커 ×1.03)을 쓴다 — 사용자가 "+3% 벌었다가 −3%로 반납"을 막으려고 직접 고른
변형이고, **래칫 자체의 백테스트는 사용자 지시로 생략**했다("백테스트는 고만하고 반영해줘"). 손절은 항상
현재 밴드 하단(첫 계단부터 본전 근처 잠금), 시간 청산 120분·장 마감은 그대로. 확률이 없거나 3분 넘게
낡았으면(입양·스캐너 실패·구 모델 파일) 보류 없이 그대로 익절한다(fail-closed — 검증된 기본으로 후퇴).

**Considered**: ① 검증된 원형(보류 + 확률 꺾임에 매도, 하단은 진입 −3% 고정) — 수익은 확인됐지만 +3%→−3%
반납 경로가 남는다(사용자가 이 지점을 명시적으로 거부). ② 래칫 백테스트 후 적용 — 사용자가 중단 지시.
래칫은 보류 변형 대비 "하단을 위로만 움직이는" 수정이라 최악 손실을 키우는 방향이 아니라고 판단하고
적용했다(단, 조기 하단 청산으로 수익 합계가 보류 변형과 다를 수 있음은 실거래로 관측).

**Consequences**: 승률은 내려가고(백테스트 보류 변형 기준 58%→27~39%) 보유가 길어진다(12분→25~38분,
슬롯 회전 저하). 래칫 계단·보류 여부는 이벤트 문구(밴드 하단/상단·래칫 N계단)와 게이지(밴드가 올라간다)로
관측한다. 롤백 스위치 `MODEL_TP_HOLD=false`(exitRule) 한 줄 — ADR 0008의 ±3% 단일 밴드로 복귀.
