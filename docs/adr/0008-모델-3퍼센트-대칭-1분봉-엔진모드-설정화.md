# 모델을 ±3% 대칭·1분봉으로 재학습해 교체하고, 엔진 모드(±3% 단타 ↔ 모델)를 설정으로 강등한다

앱 청산이 ±3% 대칭(ADR 0007)이 된 뒤에도 모델은 "+5%가 −2%보다 먼저"(5분봉)를 예측하고 있었다 — 모델이
예측하는 사건과 앱이 실행하는 규칙이 다른 기하다. 사용자가 "3% vs −3% 동등, 1봉 기준"을 지시해 라벨을
**+3%/−3%/120분 first-touch, 1분봉 Feature**로 재학습했고, 워크포워드 4폴드 전부 흑자(승률 58.0~58.4% ·
PF 1.136~1.164 · 합계 +39.2 — 구 5분·+5/−2 모델 +21.9의 1.8배, 검증 정본: financial-analyze
`docs/analysis/2026-09-01_1분봉-대칭-3퍼센트-워크포워드.md`)를 확인하고 `core/model/model.json`을 교체했다.
동시에 모델 청산도 같은 기하(익절 +3% · 손절 −3% · 최장 120분, `MODEL_EXIT_SYMMETRIC`)로 바꿨다 —
**라벨과 청산은 한 몸**이라는 원칙이 이 ADR의 핵심이다.

이 결정은 문서로 확정했던 두 판단을 뒤집는다: ① "Feature 시간축 5분봉 채택"(2026-08-21 — 1분봉 열화는
+5/−2 라벨에서의 관측이었고 대칭 라벨에서는 재현되지 않았다) ② "트레일 −5% 청산 채택"(2026-08-24 — 그
연구는 +5/−2 모델 전제였다). 되돌리려면 `MODEL_EXIT_SYMMETRIC=false` + 구 model.json(2026-08-31 이전
커밋) + `MODEL_BAR_MINUTES=5`를 **세트로** 되돌려야 한다 — 하나만 돌리면 학습-실행이 다시 어긋난다.

**엔진 모드 설정화**: 무엇으로 매매할지(`engineMode: 'martingale' | 'model'`, 기본 martingale)를 컴파일
상수에서 설정(appSettings)으로 강등했다. 조건부 주입(managerProvider) 방식이라 엔진 코어의 "상수 AND 주입"
이중 게이트는 그대로다. **반영은 앱 완전 재시작 시**로 한정했다 — 슬롯 봉 주기·ModelScanner·워밍업이 매니저
생성 시점에 굳고, 보유·미체결 상태에서 청산 규칙이 갈리는 실계좌 사고를 원천 차단하기 위해서다(런타임
매니저 재생성안은 상태 전이 위험 대비 이득이 작아 기각).

**Consequences**: 신모델은 거래가 3배(1분봉)·건당 우위가 얇아(평균 +0.19~0.22%/거래) **손익분기 슬리피지
≈0.2%p/왕복**(구모델 0.33%p)로 체결 품질에 더 민감하다 — 모델 모드 실운용 전 관측 포인트는 익절/손절
체결 슬리피지(exitSnapshot.line 대비)다. 스캐너는 1분마다 종목당 봉 조회(seed 시 최대 1,452봉을 토스
from 커서 페이징)를 돌므로 조회량이 5배가 된다. Final Test 봉인 구간은 재사용하지 않았다 — 판정은
워크포워드로 종결.
